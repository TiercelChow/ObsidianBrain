LLM Wiki：书籍知识工作流

将 Markdown 书籍整理为可浏览、可核对的主题知识，围绕同一本书连续提问、开展研究，并交付研究报告与 PPTX。原书只读，知识与运行记录保存在本机，不依赖 Obsidian。

00 / OVERVIEW

总览 — 从书籍资料到可维护的知识

LLM Wiki 不止于检索原文片段：先跨章节整理概念、方法、论断与关系，经审核形成主题知识，再以这些知识支持问答和研究。每本书在共享的本地 SQLite 中逻辑隔离，默认不混入其他书籍的内容。

四类使用场景

主题知识整理同步 Markdown 来源，智能编译跨章主题，审核后形成正式知识。 知识浏览与维护阅读完整正文，核对引用与论断，处理来源变化和待审核内容。 连续问答围绕书籍追问、比较和解释，在回答中原位查看本轮引用。 专题研究与演示确认受众与用途，获得阶段化研究报告或可下载 PPTX。

五个页面的职责

页面主要操作得到什么
书籍知识库同步来源、启动编译、查看进度与审核入口每本书的来源、编译和健康状态
Wiki 工作台检索主题，阅读正文、论断、引用与历史可持续维护的正式知识
知识问答选择书籍和会话，连续提问并核对来源流式回答、会话历史与本轮证据
研究任务确认简报，启动研究，查看阶段与交付完整报告、已保存章节或 PPTX 文件
Wiki 配置管理供应商、密钥、规则、Skill、用量与备份可查看、可调整的执行配置

首次使用路径

  1. 配置并验证模型：在 Wiki 配置中添加供应商与 API Key，选择模型和真实容量。DeepSeek Harness 是执行器，不要求使用 DeepSeek 的模型 API。
  2. 同步、编译并审核：从阅境轩登记 Markdown 文件夹，为这本书建立知识库。来源同步后启动智能编译，在审核通过后查看主题知识。
  3. 问答或研究：短问题从问答开始；需要多主题分析或演示材料时，确认材料偏好、创建研究任务，再手动启动。原文、当前知识与历史引用分别保留。
ⓘ来源同步不等于知识编译：同步建立可检索的章节索引，不等于已经完成语义编译。章节索引可作兜底，正式主题知识仍需模型编译和审核。添加书籍不会自动启动全书模型调用；PDF 只用于阅境轩阅读，不进入 Book Wiki。

系统分工 — 业务数据与原生 Agent 执行

应用负责来源、知识存储、工具范围、审核和运行生命周期；DeepSeek Harness 负责授权范围内的多轮决策、工具调用、Skill 读取与生成，不重复实现其原生 Agent Loop。

知识管线 — 编译、应用与审核回流

Markdown 原书（只读）
  → 书籍知识库：扫描、结构抽取、版本、编译报告
  → 语义编译：完整正文 + 原子论断 + 关系与引用
  → proposal：结构化候选 → 审核 → 单事务写正式知识
  → Wiki 工作台：浏览、体检、来源复核、历史与关系
  → 知识问答 / 研究任务：按需取证 → 可追溯答案 / 完整报告 / PPTX
  ↺ 显式保存或研究结论回写：仍是候选，回到审核
层拥有的职责不做什么
前端展示真实阶段、正文、引用、已保存成果与操作入口不凭动画或时间推断任务成功
Rust / Axum生命周期、资源分配、工具范围、校验、审核、事务及恢复不重复实现 Harness 内部推理与压缩循环
SQLite生成知识、来源版本、会话、运行、研究成果、配置与 Skill不与可编辑 Markdown Wiki 双写
DeepSeek Harness原生多轮决策、受控工具调用、按需 Skill、ACP 流式生成不直接操作数据库或改写原书
💡为什么划清这条分工线？模型适合判断下一步读什么、如何综合；业务程序适合保证版本、事务、权限和恢复。将二者分开，换供应商不需要迁移知识，模型失败也不会破坏已经保存的成果。

四个主要页面共享数据管线，Wiki 配置作为控制面。编译报告可以直达对应审核；问答引用先开预览，再由用户选择工作台或阅境轩定位；研究失败仍可查看原阶段成果与完整报告。

01 / SOURCES

来源与更新 — 结构完整，历史可回看

来源同步不调用模型。它把 Markdown 文件夹变成带版本、带结构、带位置的证据库，并指出原书变化影响了哪些已有知识。

怎么做的 — 每书隔离与 Markdown AST

  1. 每书一库：书架 reader_books 与 knowledge_bases 一对一；Book Wiki 只接收 Markdown 文件夹，PDF 保留为阅境轩阅读能力。
  2. 结构化抽取：使用 Markdown AST 识别真实标题和结构，支持 Setext 标题，代码或公式中的伪标题不会参与章节划分。协议 markdown-v3-structured 保留原文及换行形式。
  3. 定位与邻接：source_span_structures 保存标题路径、相邻片段和位置；缺少旧定位数据时返回未知，不补造行号。
  4. 保护原子结构：表格、代码块、显示公式及行内边界不能被机械切断。不可拆分的大结构先做容量预检，放不下则明确失败，而不是裁掉尾部。
  5. 搜索与阅读分开：搜索返回命中附近的短预览；正文按 Unicode 字符分页，并记录本次实际返回范围。只有正文读取才进入引用账本。

怎么检索 — SQLite 原生词法底座

knowledge_entries_fts：标题 / 别名 / 摘要 / 正文 / 标签 / cjk_terms
source_spans_fts：来源标题 / 章节标题 / 原文 / cjk_terms

连续中文：“知识管理” → “知识 识管 管理”（写入与查询使用同一规范化）
排序：bm25 + 标题、别名等字段权重；语义知识条目优先，章节来源兜底
正文 / FTS 同事务更新；列表 LIMIT/OFFSET 分页，不用 LIKE 全表扫描补位
💡为什么仍保留 FTS？它是轻量、可重建的本地召回底座，但不是完整语义检索，也不能保证所有同义表达都命中。当前用模型浏览编译目录和 Harness 多轮补查补充词法检索；向量检索尚未实现，不把 BM25 包装成语义理解。

增量编译除变化文档外，还会重读受影响主题的当前贡献来源与必要依赖根主题；不只看变化章节，也不重读无关书籍或旧版本。无实质新增不能清除过期影响，“需复核”也不等于“已证伪”。

02 / COMPILE

完整知识编译 — 不止摘要，也不止章节拆分

智能编译跨来源组织主题，产出导航摘要、完整正文、原子论断与证据。章节镜像是兜底，不是 LLM Wiki 的最终知识形态。

怎么做的 — 三层知识，而非摘要拼正文

层保存什么用途
导航摘要 summary标题、别名与短概述目录发现与快速浏览，不代替完整知识
完整正文 content_md机制、步骤、完整公式、变量、前提、版本、例外与反例阅读、问答与跨章综合
原子论断 claims有条件的知识陈述及各自来源核验、冲突检查、增量保留与审计

模型收到什么 — 完整合同与本批材料

{compile.md：主题选择、条件保留、new / update / disputed 与序列化规则}
<output_schema>{semantic-output.schema.json：与服务端同一份 Schema}</output_schema>
<compile_skills>{实际启用的 ingest Skill；无自定义时用 book-ingest}</compile_skills>
<source_spans>{本批完整结构片段、真实 span_id、标题与位置}</source_spans>
<existing_wiki>{从全书轻量身份目录选出的相关标题 / 别名 / slug}</existing_wiki>
<current_compile_candidates>{相关前批候选身份}</current_compile_candidates>
<book_configuration>{有效书籍配置}</book_configuration>

没有固定“前若干条实体”截断；全目录能放入本批预算时全部发送，否则按相关词与 token 预算选择完整身份行。
原文、规则、配置不能静默删尾；无法容纳则报告容量问题。
后续归并另接收有效基线的完整正文与全部有效原子，不把过期正文当新证据。

生成什么 — 当前编译合同

协议 semantic-contract-v5-knowledge-body 要求一个完整 JSON 对象。以下是数据形状示例，引用 ID 仅作说明，真实运行必须来自本批来源：

{
  "entries": [{
    "_classification": "new",
    "entry_type": "method",
    "slug": "capacity-planning",
    "title": "容量规划",
    "summary": "按峰值与适用条件安排容量，并验证异常负载。",
    "content_md": "## 机制\n在明确测量口径下规划容量。\n\n## 步骤与边界\n先测峰值，再保留余量，最后核对异常情形；不能把平均负载当作峰值。",
    "aliases": ["容量评估"],
    "confidence": 0.8,
    "citations": ["span-example"],
    "claims": [{
      "claim_text": "在峰值口径一致时，容量评估需同时考虑负载与余量。",
      "predicate": "需要",
      "object_text": "相同口径的峰值与余量",
      "confidence": 0.8,
      "citations": ["span-example"]
    }],
    "relations": []
  }]
}

Schema 的存储安全边界包括每批最多 12 个主题、摘要最多 1,000 字符、正文最多 30,000 字符、每主题最多 8 条原子论断；这些是安全信封，不是统一篇幅目标。关系使用 to_slug / relation_type / evidence，只能连接本批候选或已提供的真实主题；引用必须属于本批，论断引用必须包含于条目引用。

完整响应 → 单对象解析 → JSON Schema → 引用 / 身份 / 关系校验
  失败 → repair_context（精确字段路径 + 有界失败摘录）→ 完整重写一次
  再失败 → 明确停止，不写成功检查点
  通过 → 保留完整正文与原子 → 主题归并 → 版本复验 → 变更集

合法空结果：{"entries": [], "no_material_reason": "本批仅为导航，无新增知识"}
空正文 / 无理由空数组 / 合法无实质结果，是三种不同情况。

怎么归并 — 旧知识不被增量覆盖丢失

  1. 身份对齐：从全书轻量目录按标题、别名与 slug 词匹配选相关身份。这是规则提示，不是完备语义去重；模型与人工审核仍需判断是否同一对象。
  2. 无损原子合并：同一论断合并来源；不同谓词、对象条件与版本分别保留。每条原子只连接它自己的依据，不把全部条目引用复制给每条论断。
  3. 有效基线归并：完整有效旧正文进入归并 Prompt。过期正文不混入当前事实，混合过期主题只保留仍有有效依据的旧原子。
  4. 冲突与并发：冲突保留双方并进入高风险候选；创建候选及批准时检查基线 revision，防迟到结果覆盖人工更新。已有争议不因润色自动解除。
💡为什么去掉机械截断？删掉尾段可能同时删掉公式条件、异常步骤和反例，剩下的短句看似完整却改变了结论。当前宁可明确报容量问题，也不让有损产物获得成功检查点。

增量、指纹与报告

knowledge_compile_checkpoints 记录已成功分析的来源版本与 compile_fingerprint。指纹覆盖协议与规则、有效 Skill / 配置、Runtime / 模型及能力配置；改变后在用户下次触发编译时重新分析，不静默启动全书模型调用。驳回候选会释放对应检查点，允许重编。

后台编译请求入队即返回，离开页面不中断执行。报告记录计划位置、来源版本、逐片段状态、主题归并与真实审核关联；失败或取消保留已完成批次，未开始片段不会被标成完成。分页可查看历史报告，旧运行没有记录时明确未知。

03 / REVIEW

审核与复核 — 分析完成不等于正式可用

候选、正式知识和来源有效性是不同状态。批准不仅检查模型格式，还重新确认版本、引用与整组变更能否一致生效。

怎么做的 — 单事务与人工保护

  1. 候选先落库：knowledge_change_sets 保存变更理由、before / after、期望版本、分类、引用审计与影响范围；正式知识尚未被改变。
  2. 批准再复验：引用仍属于当前来源版本，对象仍属于授权书籍，revision 与基线一致；任一失败整组不应用。
  3. 原子提交：实体、历史版本、论断、关系、引用、FTS 和审核状态在同一个事务写入，大变更前先备份。
  4. 保护人工内容：人工编辑、合并、拆分及阅境轩摘录同样形成候选。模型不能通过省略或改写 human_protected 解除已有保护。

怎么处理过期知识 — 两条明确的人机闭环

需求入口与处理不会发生什么
更新仍需要的知识retry_knowledge_source_review 显式重读当前贡献来源 → 新候选 → 审核后解除对应影响不删除检查点；不无限自动重试；无实质结果不清除 stale
保留但退出当前问答propose_knowledge_entry_archive 创建服务端授权的高风险归档候选 → 人工批准不删除正文、原子、关系或历史证据；不把归档当事实核验
💡为什么过期影响不能随编译结束一起清掉？“模型看过来源”不代表已经更新了受影响结论。只有真实的当前依据候选被审核，才证明这项知识完成了业务更新；无结果、失败和历史归档都不能冒充它。
04 / WORKSPACE

Wiki 工作台 — 把知识、依据与状态放在一起

完整知识可以阅读，原子论断可以检查，来源变化可以定位。工作台是同一数据库模型的读侧，不是另一套 Markdown 文件管理器。

怎么展示 — 内容为主，辅助信息按需展开

  • 正文与论断：查看完整 Markdown、公式、表格、代码与 Mermaid，复用阅境轩安全渲染管线；原子论断保留独立依据及 supported / disputed / stale 等状态。
  • 来源与维护：显示需复核原因、当前与历史来源、依赖影响，提供重试复核或历史归档候选入口。
  • 分页与图谱：实体、报告来源和报告主题后端分页；桌面图谱按需加载有限快照，手机以轻量洞察为主，关闭后释放数据。
  • 报告与审核深链：准确打开当前报告关联的变更集，而不是跳到任意最近候选；历史审核已应用不代表来源至今仍有效。
  • 两端一致：电脑弹窗、手机底部抽屉复用系统组件；正文独立滚动、操作固定、长路径换行。隐藏或关闭界面停止相关轮询，迟到响应不重开窗口、不抢焦点。
💡为什么体检不调用模型？lint_book_knowledge_base 检查缺引用、失效来源、重复标题和结构状态等确定性问题。代码能确认的性质不必再引入模型不确定性；语言事实是否成立仍需要证据核验。
05 / ADAPTIVE QA

自适应问答 — 先理解，再取证，按缺口补查

优先利用编译后的知识，必要时回到原文。规划目录、正式证据和会话记忆分开管理；Harness 在同书授权范围内多轮补查，不把最初召回当成最终答案边界。

怎么规划 — 没有统一 top-k

  1. 理解追问：小型同书历史与结构化意图记忆辅助消解指代，生成独立问题。当前原话优先，用户可以改变或清空旧目标与约束。
  2. 发现编译知识：标题、别名和短概述按 token 分页进入独立只读规划 Run；建立目标、子问题、证据类型、深度和预期输出需求。候选必须属于真实目录页。
  3. 分配资源：候选、初始正文、上下文、输出、工具与期限分开计算，随问题和模型能力变化；多页候选交错合并，尚无跨全部页面的全局语义重排。
  4. 原生补查：Agent 使用 knowledge_list_compiled_catalog、knowledge_get_entry 等工具继续查编译知识；遇到精确公式、数值、条件或争议再用 book_read_source_span 核对原文。

怎么记住上下文 — 记意图，不把旧回答变事实

会话与完整消息持久化在 SQLite。意图记忆只保留用户目标、明确约束、未解决问题和有效实体 ID，不把旧模型结论总结成新证据。普通历史回答、整份目录、未选摘要和规划 JSON 不进入最终回答 Prompt；改写上一条答案时，旧答案也只是待编辑文本。

记忆保存受最新已完成交换与 revision 保护，迟到旧 Run、部分输出或并发冲突不会覆盖新记忆。每轮引用编号独立，上一轮的 [S1] 不能直接带进新一轮。

怎么引用 — 实际已读证据账本

<evidence>
[S1] 已整理知识条目：对象 ID / revision / 路径与位置
     {本轮实际可见正文；含争议时保留提示}
[S2] 原始来源片段：span_id / source_version_id / 实际行区间
     {本轮工具实际返回文本}
</evidence>

来源卡片与引用预览读取原 Run 的冻结证据。
旧运行没有快照时明确未知；当前版本入口必须标为“非本轮证据”。

怎么输出 — 原生流式与明确终态

run_started / phase      → 准备、连接、分析、工具等公开阶段
tool_started / finished  → 真实工具调用反馈
text_delta               → Run 级实时事件桥接经 ACP / SSE 追加正文
text_replace             → 新尝试、工具回合或最终提交校正，不重复追加全文
usage                    → 上下文占用 / 容量；不是完整计费 token
completed                → 正常完成、引用校验、单事务保存交换与来源
error / cancelled        → 保留已收到的部分内容，明确原因

正文使用安全 Markdown 渲染，最终校正完整结果；检索来源在输出结束后展示，首 token 前用公开阶段提示过程，不展示或存储隐藏思维链。断开前台问答流会取消该 Run，后台编译与研究则不依赖页面存活。

Harness 默认 ACP 在已提交消息后可能只给整段正文。应用的临时插件订阅公开的 agent/assistant-stream，按模型尝试身份转发真实增量，再用提交事件校正；不靠前端延迟播放冒充模型流式。插件与受限 MCP 工具用 Run 级 insert 配置加载，不修改全局 Harness 或扩大工具权限。

输出不足、轮次上限与研究衔接

情况系统处理下一步
max_tokens · 输出截断在有效容量允许时最多两次自动扩大输出预留，建立关联回答 Run，保留已有规划而不重复目录规划；重新取证并生成完整回答，用 text_replace 替换草稿，不把残缺片段拼成成功答案仍不足或已达硬限时，调整模型输出能力、推理策略或问题范围；也可转为分阶段研究
max_turn_requests · 请求轮次耗尽轮次上限不能通过增加输出 token 修复，不进入输出扩容重试拆分目标、转为研究任务，或调整运行配置后显式重试
qa_output_scope_limit · 范围预检不通过规划估计的完整回答明显超出可见正文容量时，在启动回答 Run 前停止；估计不是实际用量，已发生的规划调用仍可能产生费用缩小本轮范围，或将复杂目标交给持久研究流程

“深入研究此问题”保留当前书籍与补全指代后的独立问题，预填可编辑的研究简报；需要用户确认后才创建研究任务，不自动启动付费研究，也不把旧答案当作新证据。取消、凭据拒绝和硬容量不足不会触发相同预算的循环请求。

未完成记录 — 保留输出，不改写对话历史

失败、取消或未写入会话的回答可从未完成记录继续查看。未完成正文以草稿呈现，不冒充成功回答，不启用可能不完整的引用跳转。可恢复的输出截断提供“继续完成完整答案”入口，建立关联新 Run 重新生成；达到硬限时先调整配置或范围，不直接拼接旧草稿。

完整回答已经生成、但会话写入未完成时，可以补存到会话历史，不再调用模型。服务端确认同书、同会话及对话顺序仍匹配后，以幂等事务保存原回答和冻结来源；如果后续对话已改变顺序，则拒绝插入，避免悄悄改写历史。

💡为什么目录不跟着答案走？目录是候选索引，不是证据。把未选材料和旧模型结论不断拼接，会消耗上下文并混淆依据。保留意图、舍弃无关候选、重读真实证据，才能兼顾追问连贯性与引用可靠性。
06 / BUDGETS & COVERAGE

预算与证据缺口 — 自适应，不是无限扩张

候选发现、实际阅读、上下文与回答长度不是一个数。问题越广、证据越复杂，起始资源可越多；继续扩展必须有缺口、有进展，并遵守模型与安全硬上限。

Agent 可以用哪些反馈工具

原生工具作用约束
knowledge_get_run_budget查看本轮初始预算、消耗、硬上限与证据要求只读业务预算；估算负载不是账单
knowledge_report_evidence_coverage逐子问题报告 missing / partial / conflict / 有依据，连接实际 S 引用未报告不能推定完成；自报不是事实证明
knowledge_request_budget_extension根据具体缺口扩大软预算最多三次；后续需新增实际已读证据，不扩大权限或截止时间

模型能力、应用护栏与实时占用

供应商配置声明上下文与最大输出，问题或阶段需求决定实际预留。问答与研究在未声明上下文时使用 1,048,576 token 的应用规划默认值，输出另有 262,144 token 的应用护栏；两者都不是模型能力承诺，也不表示每次请求会读满或输出到上限。

填写供应商真实能力后按该能力计算；显式声明更大的上下文不会被固定裁成 1M。同一模型路由的 ACP 容量上报可替代未知默认值，若低于配置则进一步收紧。输入、输出、推理余量、工具返回和合同修复分别预留；智能编译还使用独立的批次安全边界，不能把问答默认值理解为所有运行的统一预算。

检查器展示规划目标、目录总量与实际浏览量、预算扩展理由、已读证据、覆盖自报及停止原因。实时占用跟随 Harness 原生压缩更新，但数据取证的累计负载不因压缩归零。到硬上限、连续补查无新依据或缺少来源时停止，不无限重试。

等待与失败 — 按实际运行阶段判断

边界当前策略恢复原则
startup_timeout准备工作区、启动与连接阶段默认 120 秒；尚未提交问题时可作有限重试不把未连接和模型长回答混为一谈
idle_timeout已提交问题后，默认连续 600 秒没有 ACP 进展才判定停滞；真实进度消息刷新计时保留已收到的正文，不自动重放可能已付费的请求
整体期限问答与研究按预算计算，应用最大期限为 2,400 秒；编译单批另按 90–600 秒管理是运行保护，不是供应商响应速度承诺

重试只针对可恢复的限定错误，不以相同预算无限重放。凭据无效、拒绝授权、取消和已知硬限需要先解决原因；后台研究的队列退避与前台问答的恢复操作分别管理。

💡为什么不直接放开到最大上下文？容量大不等于需要读满。简单问题应低成本响应，复杂问题应按子问题取证；无关内容越多，越容易污染依据。自适应的目标是足够而且相关，不是单纯增加 token。
07 / DURABLE RESEARCH

可恢复研究 — 阶段成果不会随失败消失

研究不再是一次长回答。目标、主题、证据矩阵、综合、报告与交付分别保存；各阶段借助 Harness 原生多轮能力完成，应用负责耐久状态和恢复。

创建前 — 确认材料与用户简报

  1. 材料准备情况：先显示知识库状态、来源同步、编译与待审核情况。暂停或归档的库不能启动研究；未同步、只有章节索引或待审核时提示实际可用材料，而不是假定语义知识已经就绪。加载失败可重试。
  2. 可选预分析：根据用户诉求建议受众、用途、深度、语气和交付偏好。预分析不读取书籍内容，也不启动研究；这是独立的模型调用，可能产生供应商费用，不属于资料调查或研究成果。
  3. 用户简报：预分析结果只是建议，用户确认重点选择；可以跳过预分析或在失败后手动确认。报告与 PPT 的受众、用途、主题和叙事形式按需设置，而不是让系统自行替用户决定。
  4. 保存并启动：确认简报后创建任务，由用户手动启动研究。简报保存在数据库，未启动的草稿可修改；已执行的输入与成果保留当次版本，不因之后的配置调整而悄悄变化。

研究与演示分别使用已确认的偏好。决策、参考类报告优先呈现结论与行动依据，教学、机制类内容按理解顺序展开；PPT 依据受众形成叙事，不强制把每个研究问题变成一页。这些规则改善组织方式，但不保证模型每次都能产出无需编辑的成品。

怎么规划与取证 — 每个主题有自己的资源

任务持久化不可变目标、约束、验收条件、术语、子问题与所需证据。主题深度、expected_output_tokens 和真实模型能力决定阶段输入、输出、工具与期限；复用预算查看、覆盖报告和缺口扩展工具，不把整个研究固定为相同工具次数。

初始 FTS 可以没有命中，Harness 仍可按目录 → 编译正文 → 原文逐步查证。明确输出截断时可在能力范围内扩大预留；达到硬容量或缺乏进展时停止相同自动请求，已有章节与完整报告保留。

review / refresh — 真正冻结旧版基线

  1. 选真实对象：规划使用 target_entry_ids，同一事务冻结这些条目的完整正文、具体主张、原始来源与版本。
  2. 分页看基线：knowledge_get_research_baseline 限当前 task / question / Run。章节只读本主题，综合指定同一任务的 question_id；用 source_basis_index 回读保留的旧原文，即使旧片段已被当前版本替换。历史材料不获得本轮 S 编号，不能冒充当前证据。
  3. 对照当前证据：核验连接真实基线条目 / 主张 ID，再读当前知识与原文。review 检查支持、反对及条件；refresh 区分变化、未变与未知。
  4. 缺基线不伪造：找不到基线时只能输出 partial/missing，不能声称已核验或发现版本变化。

跨主题综合 — 保留差异，而非强行统一

synthesis 使用已保存主题的发现、限制和准确版本。容量不足时提供覆盖全部主题身份的结构投影，而不是截取开头；Agent 可通过 knowledge_get_research_manifest 分页读取完整发现矩阵，通过 knowledge_get_research_section 回读完整章节。旧章节引用编号被中性化，新增事实仍需重读当前证据获得本轮编号。

投影保留全部主题 ID 与 revision，但不等于模型已经阅读全部正文。未读完整矩阵不能宣称全部主题一致、合格或没有冲突；无法取得所需材料时应标为 insufficient 并说明缺口。工具读取记录证明实际提供的范围，不等于独立证明模型的每条结论。

section_checks 必须对应全部真实主题与当前 revision，检查目标覆盖、术语、比较维度、版本 / 条件、反例、同源重复和冲突。不同条件下成立的结论不强行合并，原章节不被综合摘要替换。综合自报不等于独立事实证明，综合阶段新增读取的来源同样进入失效链。

完整报告 — 正文与引用一起组装

应用确定性合并完整章节及综合对照，不截掉报告尾部。同一对象同一版本的引用统一编号，合并实际已读范围并保留来源 Run。组装不是新的模型取证，也不产生虚构的 token 用量。引用与结构校验之后，任务最终完成事务再查来源版本，避免交付途中变化被误认证为当前成果。

PPTX — 从整份报告策划，而不是从开头截取

容量足够时使用完整报告；不足时依据报告结构投影，保留所有主题的完整发现与限制、尾段及可容纳的完整公式 / 表格 / 代码片段。检查器记录材料模式和选材范围，不是前若干字符截取。必要材料仍超硬限则失败并保留报告。

{
  "schema_version": "1.0",
  "title": "研究结论",
  "audience": "目标读者",
  "core_message": "一个明确且有依据的中心结论",
  "theme": "editorial",
  "slides": [{
    "layout": "statement",
    "title": "关键结论",
    "takeaway": "保留条件，不虚构报告没有的事实",
    "body": ["来自已保存报告的论证"],
    "citations": ["S1"]
  }]
}

上面是规格形状节选，不是可直接提交的完整演示。实际合同还检查页数、密度、版式多样性、专用载荷与证据编号；通过后由 Rust 生成器输出可编辑 OOXML，文件保存到受管成果目录，数据库保存哈希、大小、引用与质量报告。PPTX 目前只提供下载，不提供应用内预览。

队列、租约与迟到写保护

  • 数据库队列：knowledge_tasks 入队即返回，页面离开仍运行。任务支持取消、有限退避重试和服务重启恢复。
  • 租约：45 秒活跃租约、15 秒心跳，覆盖研究、PPT 策划与渲染；每库最多一个运行中的写任务。
  • 执行栅栏：递增 research_execution_epoch、阶段领取 UUID 与活跃租约共同保护阶段、成果、候选及 MCP 写入，旧 worker 不能写入新尝试或延长已死租约。
  • 成果身份：run_id 表示当前阶段尝试，content_run_id 标识已保存正文的原始 Run。恢复中预览仍读原证据，状态轮询不会把报告替换成排队摘要。
  • 交互窗口：“阶段与已保存成果”展示目标、基线、证据矩阵、历史版本与检查器；关闭 / 隐藏停止相关轮询，不改变后台任务，也不自动申请焦点。

恢复与草稿 — 只重做需要重做的阶段

规划、主题、综合和演示策划遇到 max_tokens 时，各阶段最多两次自动扩容；格式合同另有一次有界修复，不与输出扩容混为同一计数。新尝试只重做对应阶段，已保存的其他章节与报告仍可查看。达到有效输出硬限后，不再用相同预算付费重放；调整能力或范围后再显式恢复。

research_turn_limit 与 presentation_turn_limit 表示请求轮次耗尽，不靠扩大 token 修复。缩小目标另建任务时仍需用户确认，不隐式继承旧任务的阶段成果或外部网络授权。容量预检失败可记录阶段失败，但不会伪造一个模型 Run 或用量。

查看未保存输出提供失败或取消尝试的原始草稿，不再发起模型调用。未保存输出不进入阶段正文或最终报告；已通过合同的正文由 content_run_id 保留原运行身份，与最近一次失败尝试分开。原始草稿不是可发布的研究成果，也不冒充已核验的引用。

💡为什么保存阶段，而不是只保存最终回答？长研究包含多个可以复用的成果。最后一步 PPT 失败不应让前面所有章节重做；综合失败也不应重生成已完成章节。阶段保存同时提供明确的恢复边界与来源变化影响范围。
08 / CONFIG & SKILLS

配置与 Skill — 看得到，也能知道是否生效

模型供应商、配置文档和方法 Skill 是控制面；硬合同、证据边界与工具权限仍由应用约束。检查器保存本次有效输入，页面之后的修改不会偷换历史运行。

模型配置 — 执行器与供应商解耦

配置作用
多个供应商 / 模型支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 兼容协议；Harness 不是只能调用 DeepSeek API
context_window声明模型上下文能力；未声明保持未知，不把应用护栏当模型规格
max_output_tokens限制最大输出，结合问题 / 阶段需要分配，不和输入预算混为一个数
reasoning_policy声明推理策略与能力，和输出、重试预算分别处理
凭据页面可配置系统凭据库密钥，或使用环境变量名；数据库保存引用，不保存明文 Key，临时配置与审计不含密钥

固定版本 DeepSeek Harness 通过 ACP stdio 运行，每个 Run 独立临时工作区，结束、取消或超时回收。供应商能力字段进入实际请求和运行诊断；配置验证可显式发起真实探测，但静态介绍页不会连接本地服务。

配置文档与 Skill 有什么关系

  • 配置文档：purpose / schema / instructions / AGENTS 描述目标、组织和通用约束，全局及书籍级内容在数据库管理，形成本次不可变有效配置。
  • Skill：定义问答、编译、研究或演示的方法，绑定范围 qa / research / both / ingest / all；启用不代表获得更多权限。
  • 硬规则：应用 Prompt / Schema 定义当前来源、输出合同与安全边界；配置与 Skill 不能覆盖这些约束。

两种实际生效方式

应用方式场景真实含义
harness_native_available问答与研究当前用途的 Skill 物化到隔离目录，Harness 原生 Skill 工具按需读取；可用不代表模型必然读过，正文不重复塞入答案 Prompt
prompt_injected智能编译与演示策划等固定合同运行有效指令直接进入该 Run 的 Prompt，结合模型容量预检；不能静默截掉必需规则尾部

当前安全级别仅支持受控 UTF-8 指令与参考文本，不执行导入脚本，也不开放任意 Shell / 文件系统。原生问答与研究目前物化指令正文，不自动开放 ZIP 附加资源。开发期 Skill 只保留当前版；运行检查快照仍保存当次有效内容，不依赖今后的当前版。

运行检查器 — 本次实际使用了什么

agent_run_inspections 保存最终 Prompt、哈希、配置与 Skill 快照、应用方式和工具白名单；agent_runs / agent_run_events 保存运行及公开事件；agent_run_evidence 记录实际读取的正文与版本。检查器还展示预算、覆盖自报、扩展与停止原因，以及研究阶段和 PPT 选材范围。旧运行没有记录时明确未知，不补造历史。

用量统计 — 占用、估算与账单分开

ACP 报告的上下文占用 / 容量可以随 Harness 压缩变化，也可能报告带币种的累计费用；这些不等于完整计费 token。当前本地 token 估算覆盖应用可见的初始 Prompt 与最终输出，不包含 Harness 内部推理、工具重放和压缩，应标为 estimated 并说明范围。

只有真正收到供应商账单明细才可标 measured；旧运行缺数据是 unavailable。统计可按时间和调用方筛选，目录规划归入问答，各研究阶段归入研究任务；推理与缓存明细不重复计入输入加输出总量。

💡为什么不把“已启用”写成“模型已使用”？按需 Skill 的选择权在 Harness。应用能证明本次提供了什么、实际返回了什么证据，不能凭绑定状态证明模型读了指令，更不能凭一次评测分数保证所有真实问题都正确。
09 / SECURITY & STORAGE

安全与数据边界 — 更多取证，不是更多权限

资源可以按问题扩展，书籍范围、网络授权和写入权限不能因此扩大。正式知识始终由 Rust 的校验、审核与事务保护。

受控工具桥与最小权限

问答与研究通过本机 MCP 工具网关访问知识。agent_run_capabilities 保存短时令牌哈希，绑定 Run、知识库范围、工具白名单与有效期；每次调用检查运行仍有效。工具 Schema 拒绝额外字段，跨书、过期、已撤销或越权请求被拒绝。

运行工具原则
问答同书目录、知识正文、来源、关系与预算工具；不能直接写正式实体
研究以上能力加任务绑定的基线 / 章节读取与进度报告；研究成果由应用生成知识候选，回写仍走审核
编译 / 归并 / 演示策划等纯变换完整材料按合同提供；无用 MCP 工具不装载，零工具 Run 不签发能力令牌

工具网关中的 knowledge_propose_changes 是提案接口，不是批准接口；当前问答与分阶段研究白名单不授予它，研究结论由应用走候选通道。Harness 权限升级请求自动应答 Cancelled，不打开系统凭据提示或通用 Shell；正常的原生 Agent Loop、Skill、流式与压缩仍保留。

外部研究 — 逐任务授权的窄门

外部研究默认关闭。用户在专题研究任务中显式开启、指定授权域名与请求额度后，才提供 book_fetch_external。只接受标准 HTTPS / 443 文本，检查公网 DNS、禁止重定向，限制正文大小和超时；尝试前原子扣额度，失败也计数。外部证据单独标识，不能伪装为书内来源或绕过审核。

💡为什么预算扩展不带来网络能力？“证据不够”不是访问任意网站或其他书籍的授权。应用只能在既有授权范围内允许更多阅读；超出范围的资料需求应明确交给用户决定。

数据权威、备份与导出

数据权威位置
原始 Markdown用户本地原书，只读来源
来源版本、结构、知识、引用、对话、任务、审计、配置与 SkillSQLite；正文是数据库 Markdown 字段，不是可编辑磁盘 Wiki
Agent 工作区按 Run 物化的临时文件，不是知识主存储
PPTX 等二进制成果受管 artifacts 文件 + 数据库哈希、引用、状态与校验元数据
Markdown Wiki / JSONL 导出单向快照，位于原书之外，不自动反向同步

知识库不是仅凭原书就能恢复的缓存。SQLite Online Backup 创建包含 WAL 最新写入的一致快照，迁移、删库和大变更前自动备份。恢复前检查完整性、外键与迁移版本，并生成操作前安全快照；运行期间不执行恢复，失败可回退。FTS 可重建，但知识、历史和引用需要备份。

ⓘ完整备份：SQLite 快照不包含 PPTX 等磁盘成果文件。需要保留演示交付物时，还应备份系统数据目录中的 artifacts/；原书目录也应单独备份。只恢复数据库可以恢复成果元数据，不能重新获得已经丢失的 PPTX 文件。

真实隔离验收 — 已观察到什么

2026-10-03 真实隔离验收使用独立实例、八篇虚构资料及一个真实供应商模型，核对编译、六轮问答、研究、恢复与两份 PPT。它补充了 Mock 与自动回归，但不是所有供应商、所有书籍的质量保证，也不是严格受控的质量前后对比。

已验证的流程观察结果仍需改进或验证
语义编译与审核多来源主题、关键公式与条件保留，候选审核和版本发布可用；不合格归并被合同拦截别名归并、语义去重与关系组织仍不足，偶发编译合同失败仍存在
流式与连续问答六轮真实分片重放与最终正文一致，追问指代及冻结来源可核对首字等待仍较长，个别引用格式需要修正；不承诺端到端时延已全部解决
研究恢复与来源变化服务重启保留已完成章节；旧基线可回读，仅受影响阶段重做，无依赖成果不重复调用模型报告重复、个别绝对化表述和未经证实的自审说法仍需人工编辑
PPTX 下载与离线检查两份 9 页、11 页演示实际下载并逐页查看，关键条件可见，未发现遮挡或截断窄列折行、关系连线仍需打磨；未完成 Microsoft PowerPoint 兼容认证

明确未实现或未验证的能力

  • 向量 / Embedding 语义检索：未实现。当前是 FTS5 / BM25、中文二元组、标题别名、模型目录选择与原生补查的组合。
  • 跨全部目录页的全局语义候选重排：未实现。当前候选按页选择、交错合并；不能保证最优全局召回。
  • 独立逐句蕴含或事实核验：未实现。程序验证结构、权限、实际读取范围、引用与当前版本，不等于逐句事实核验；Agent 的覆盖 / 综合判断是公开自报。
  • 更丰富的会话对象记忆：未实现。现有意图记忆包含目标与约束，不等于完整跟踪每个方案、比较标准和中间决策。
  • 普遍的真实模型质量保证：不存在。已有真实样本验证，但大规模真书、其他供应商全矩阵与全面召回评估尚未完成；不能将结构通过、模型自报一致或引用覆盖率等同于每句话正确。
ⓘ使用边界：安全与容量上限依然存在，应在配置中填写模型真实能力。Book Wiki 不支持 PDF / OCR；PPTX 作为下载交付物。检查器能解释公开流程与材料范围，不展示模型隐藏思维链。
