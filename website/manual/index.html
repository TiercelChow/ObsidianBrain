从这里开始 — 核心功能与使用路径

ObsidianBrain 是在自己的电脑上运行的阅读、记录、任务与书籍 AI 工作台。官网只提供介绍与手册，不能直接打开你的数据。不需要 Obsidian；阅读、小记和个人任务也不需要先配置 AI。

文档阅读阅境轩：本地书架、Markdown / PDF 阅读与位置恢复。 图文记录时光机：小记、图片与标签，支持检索、编辑和删除。 个人任务任务中枢：短期待办、多级子任务、进展记录与日历。 书籍知识工作流书籍 Wiki：主题编译、引用问答、研究报告与 PPTX。

首次使用：安装与功能验证

  1. 1
    安装并启动

    选择 macOS Apple Silicon、Intel 或 Windows x86_64 的步骤，启动后打开 http://localhost:9876。首页会显示你的任务、最近阅读、小记、Wiki 状态和系统信息；初次使用没有数据是正常的。

  2. 2
    先读一本书

    进入阅境轩，在书架点「＋」，登记本地文件夹或 PDF 的绝对路径。点封面阅读，再回书架打开它，确认能继续上次位置。

  3. 3
    留下小记，或创建待办

    时光机点「＋」写一条文字或图片记录；任务中枢点列表中的「＋」安排标题、日期和重要程度。这两步都不产生模型费用。

  4. 4
    需要 AI 时再开启 Wiki

    先配置并验证模型，再为一本 Markdown 文件夹建立知识库、同步、编译并审核。然后提问，或生成报告 / PPTX。

按钮与手机导航怎么认

  • 常用图标：「＋」用于新增；铅笔用于编辑；垃圾桶进入删除确认；放大镜用于搜索；「…」打开更多功能。电脑悬停可查看按钮名称，手机在操作抽屉中查看行名称。保存、取消、付费运行和破坏性确认仍保留文字。
  • 手机五个主入口：底部 Dock 按「首页 → 阅境轩 → 时光机 → 任务中枢 → Wiki」排列。Wiki 各页面由上方子 Dock 切换；任务子 Dock 提供任务 / 日历、搜索、筛选。阅读或任务详情使用页内返回 / 书架入口离开。
  • 首页快捷进入：点击某项任务进入详情，点最近阅读继续阅读，点小记定位原记录，点 Wiki 动态进入运行或审核。不是只有统计数字。
  • 电脑端代码仓：在「日常 → 代码仓」点「＋」，登记 Git 仓库名称和路径。眼睛图标查看分支、最近提交和语言统计，打开图标在 VSCode 打开仓库；手机端不展示。
ⓘ「个人长期任务」是你手动推进的计划；「Wiki 研究任务」是 Agent 执行的研究。它们不是同一个列表，小记也不会自动变成 Wiki 知识。当前没有个人任务提醒、重复规则或外部日历同步。

安装与启动

下面介绍在目标电脑上从源码构建的安装方式；若使用发布包，请以对应 GitHub Release 的安装说明为准。前端会嵌入最终的单个可执行文件，构建完成后基础功能不再需要 Node.js 或 Rust；若启用默认的 DeepSeek Harness 书籍智能功能，则需保留可用的 npm / npx。

系统处理器当前方式最终文件
macOSApple Silicon（arm64）在 Apple Silicon Mac 上原生构建obsidian-brain
macOSIntel（x86_64）在 Intel Mac 上原生构建obsidian-brain
Windows 10 / 11x86_64使用 MSVC 工具链原生构建obsidian-brain.exe
ⓘ 架构说明：macOS 会按当前终端的架构编译。在 Apple Silicon 上先运行 uname -m，结果应为 arm64；若显示 x86_64，说明终端可能正在 Rosetta 下运行。Windows ARM64 当前没有经过构建和运行验证，暂不列为支持平台。

macOS：Apple Silicon 与 Intel

两种 Mac 使用相同流程。先准备 Git、Node.js、Rust stable 和 Xcode Command Line Tools；Apple Silicon 会生成 arm64 文件，Intel Mac 会生成 x86_64 文件。建议使用能运行本项目测试命令的 Node.js 22.18 或更新版本，不依赖旧版 Rust 的兼容性承诺。

  1. 1
    安装构建环境

    运行 xcode-select --install 安装 Apple 命令行工具，再从 Node.js 官网和 Rust 官网安装 Node.js 与 Rust。

  2. 2
    下载并构建

    在终端依次执行下面的命令，先用 npm ci 安装锁定的前端依赖。make install 会构建前后端，再安装到当前用户的 ~/.local/bin/，不需要 sudo；只构建而不安装可以运行 make build。

git clone https://github.com/TiercelChow/ObsidianBrain.git
cd ObsidianBrain/frontend
npm ci
cd ..
make install
  1. 3
    加入 PATH

    若终端提示找不到命令，把 export PATH="$HOME/.local/bin:$PATH" 加入 ~/.zshrc，然后重新打开终端。

  2. 4
    验证并启动

    运行 obsidian-brain version 检查安装，再运行 obsidian-brain start。

Windows 10 / 11：x86_64

Windows 使用下面的 PowerShell 源码流程。请先安装 Git、Node.js 22.18 或更新版本、Rust stable，以及 Visual Studio Build Tools 的「使用 C++ 的桌面开发」工作负载（包含 MSVC、Windows SDK 和 CMake 工具）。

  1. 1
    准备工具链

    安装 Node.js、Rustup 和 Visual Studio Build Tools。Rustup 使用默认的 x86_64-pc-windows-msvc 工具链。

  2. 2
    构建嵌入式前端

    先把 Vue 前端生成到后端要求的 frontend/dist_new/，再编译 release 可执行文件。

git clone https://github.com/TiercelChow/ObsidianBrain.git
Set-Location ObsidianBrain
Set-Location frontend
npm ci
npx vue-tsc -b
npx vite build --outDir dist_new --emptyOutDir
Set-Location ..\backend
cargo build --release
  1. 3
    安装可执行文件

    构建结果位于 backend\target\release\obsidian-brain.exe。将它复制到固定目录，例如 %LOCALAPPDATA%\ObsidianBrain\bin\，并在 Windows「环境变量」中把该目录加入当前用户的 Path。

  2. 4
    验证并启动

    重新打开 PowerShell，运行 obsidian-brain.exe version，再运行 obsidian-brain.exe start。

首次打开

obsidian-brain start
# 浏览器访问 http://localhost:9876
  • 停止服务：obsidian-brain stop
  • 查看状态：obsidian-brain status
  • 前台排错：obsidian-brain start --foreground
  • 数据目录：默认位于用户主目录下的 .obsidian-brain/；任务数据库也在其中。
  • 独立运行：不再需要 Obsidian 或 Local REST API 插件。小记和任务保存在本地 SQLite，时光机原图保存在数据库同级 timeline/images/；默认位于 ~/.obsidian-brain/。

手机怎么打开

手机界面是访问电脑上的同一服务，不是独立手机安装包。电脑启动服务、允许受信任局域网访问后，手机连接同一网络，在浏览器打开 http://电脑的局域网IP:9876。手机选择的文件路径仍属于电脑，电脑关闭或服务停止后就不能访问。

🔒局域网访问：绑定 0.0.0.0 会让其他设备也能访问；仅本机使用时设为 127.0.0.1。只在你信任的网络和设备间使用，不要将端口暴露到公网。
01 / READ

阅境轩 — 阅读本地 Markdown 与 PDF

阅境轩把电脑上的 Markdown 文件夹和 PDF 整理成书架，并在阅读视图中提供文件、正文与目录。它读取的是本地文件路径，不要求内容位于 Obsidian Vault 内。

📚

书架管理

登记文件夹或单个 PDF，补充书名、描述和类别；支持按书名、描述、类别搜索及类别筛选。

📄

Markdown 阅读

支持 CommonMark/GFM、H1–H6 目录、表格、任务列表、脚注、代码高亮、行内与块级 KaTeX 公式、含公式的 Mermaid 图、Obsidian 链接/图片嵌入/高亮/Callout，以及本地链接跳转。

🔎

PDF 阅读

PDF 默认适合正文宽度，支持放大、缩小、恢复适宽、页码定位和文档目录；页面按阅读位置渐进渲染。

↩️

按文件恢复进度

文件夹内每篇 Markdown 分别记录滚动位置，每个 PDF 分别记录页码；再次打开书籍时回到最后阅读的文件。

添加一本书

  1. 1
    进入书架

    打开「阅境轩」，选择「书架」，点击搜索栏旁的「＋」。手机书架每行展示三本书。

  2. 2
    选择本地内容

    输入绝对路径，或点路径输入框旁的文件夹图标，用应用内路径选择器选择一个 Markdown 文件夹或 PDF。手机也选择运行服务那台电脑上的路径。

  3. 3
    补充书架信息

    书名留空时会使用文件名；描述和类别可选，用于后续搜索与筛选。

  4. 4
    开始阅读

    保存后点击封面。若已有阅读记录，会自动打开上次的文件并恢复其位置。

阅读视图怎么用

⌘ 换一本书：回到书架再点另一张封面，不在阅读页直接更换目录。书籍卡片的「…」可以编辑信息或移出书架；移出书架不删除原始 Markdown / PDF。
02 / CAPTURE

时光机 — 记录与回看碎片想法

时光机适合快速留下尚未整理成正式笔记的内容。小记按日期倒序分组，正文支持 Markdown，也可以附带图片和标签。

✏️

轻量记录

输入 Markdown 正文，标签使用中文或英文逗号分隔；正文有内容或已选择图片时即可发布。

🖼️

最多 9 张图片

可以从文件选择图片，也可以直接把剪贴板中的图片粘贴到编辑框；发布前可移除预览图。

🗓️

按时间回看

支持今天、最近 7 天、最近 30 天、本月、上月和自定义日期范围；电脑端时间轴会跟随正文滚动。

🔍

关键词搜索

输入后约 300 毫秒自动查询小记正文与标签，可与日期范围组合。搜索结果中的关键词会被高亮。

写一条小记

  1. 1
    打开编辑器

    点击「＋」写下正文。手机「＋」和搜索栏在一行，最右侧「…」打开时间筛选；电脑也使用加号新建。

  2. 2
    添加上下文

    按需输入标签，并通过「图片」按钮选择图片，或者直接粘贴截图。

  3. 3
    发布

    点击编辑器底部的「发布小记」（编辑已有内容时是「保存修改」）。可以只记录文字或只添加图片，最新内容会加入时间线；在回看历史或筛选状态下，发布后通过「查看最新」进入。每张图片不超过 20 MB，支持 PNG、JPEG、GIF、WebP。

  4. 4
    继续回看

    每次加载 20 条；到列表底部后点击「加载更多」继续读取。

编辑、删除与图片存储

  • 查看图片：点击缩略图进入大图查看器；支持上一张、下一张、放大、缩小和重置。
  • 编辑小记：电脑端使用卡片右上角编辑图标，手机端点击「更多」打开底部操作抽屉；可以修改正文、标签、增删图片，记录时间保持不变。其他设备已修改同一条小记时，系统提示版本冲突，不会覆盖新内容。
  • 删除小记：确认后从 SQLite 删除记录，同时清理没有其他小记引用的系统内原图与缩略图。共享图片保留；磁盘权限等导致的清理失败会显示待清理数量，并在下次启动和每 5 分钟重试。
  • 独立存储：SQLite 是小记唯一事实来源，默认原图位于 timeline/images/。自定义数据库文件名会使用独立的 timeline-<哈希>/，以「图片存储」显示的实际目录为准；不再从 Obsidian 月份文件同步或回写。
  • 有界缓存：可重建缩略图位于 timeline/cache/，默认上限 256 MB（按 1024 计），超过后按 LRU 淘汰最久未使用的缓存。时光机「图片存储」可调整 0–4096 MB 上限或清空缓存，设为 0 不缓存，原图不受影响。
  • 迁移旧图片：在「图片存储」选择含 Timeline/ 的旧目录，点击「复制旧图片」手动搬运一次即可；启动时不会自动扫描或搬运旧目录。只复制已被小记引用的旧图片，不改动旧库 Markdown 或原图，缺图仍保留小记并支持手动重试。
  • 暂存清理：取消编辑会释放本次新增、尚未发布的图片；异常中断遗留的未引用暂存图片，24 小时后自动回收。
ℹ️ 备份注意：SQLite 一致快照不包含原图。完整备份需要保留数据库及同级 timeline/images/，缓存无需备份；备份时暂停写入并使用一致快照。恢复数据库不能找回已经物理删除的照片，确认旧图片迁移完成前请保留旧库。
03 / ACT

任务中枢 — 管理待办与长期目标

任务中枢把工作分成两种尺度：短期待办用于快速记录近期事项；长期任务用于持续推进目标，并支持多级子任务和进展历史。

SHORT

短期待办

记录标题、描述、开始与结束日期、重要程度。状态只有待处理、已完成和已取消，适合一件可以直接完成的事。

LONG

长期任务

除基础信息外，可拆出多级子任务，为根任务或任一子任务记录进展，并持续查看整体完成度。层级受系统安全限制，不是无限深度。

新建与查找任务

  1. 1
    点击「＋」新建

    选择短期待办或长期任务，填写标题、描述、开始日期、结束日期和重要程度。

  2. 2
    使用统一编辑入口

    打开详情后，右上角编辑按钮可以修改信息、日期、重要程度和状态；根任务也从这里进入归档。

  3. 3
    快速聚焦

    顶部可搜索标题或描述，并按任务类型、状态筛选；列表内还可快速查看全部、逾期、今日和受阻。

任务视图

列表按照紧迫程度分组，组内优先显示更重要的任务。点击任务后，电脑端列表会压缩成一条竖向导航，把空间留给详情；手机端进入独立详情，顶部左箭头返回任务列表，右上铅笔修改信息。手机底部固定「＋」添加子任务、铅笔记录进展；长期任务用「任务拆解 / 进展记录」切换内容。

任务信息标题、状态、日期和描述
任务拆解多级子任务树
进展进展与状态记录
  • 拆解：长期任务详情左侧只显示子任务，不重复显示已经在页首出现的根任务。
  • 查看子任务：点击子任务会打开详情弹窗，可查看描述、日期、子任务和该节点自己的进展。
  • 调整层级：可把子任务拖到新的父任务，也可以在编辑弹窗中选择父任务；系统会阻止循环层级。
  • 记录进展：根任务和子任务都可以追加说明，并可选择同时写入一个明确完成度。
  • 完成度：完成节点显示 100%；否则优先使用最新明确完成度，没有明确值时由未取消的子节点平均计算。
  • 关闭任务：把状态改为已完成或已取消时，可以填写关闭说明；关闭根任务时可选择同时关闭未完成子任务。
  • 归档：归档只隐藏根任务，不删除详情、进展和历史；默认任务列表和日历不显示已归档项目。

日历视图

切换到「日历」后，可以按月查看任务日期范围。月历格只展示顶层任务；选中日期后，右侧或下方明细也先显示顶层任务，点击展开按钮才显示当天有效的子任务。

操作结果
切换月份 / 回到今天电脑端提供上月、今天、下月；手机端保留前后月份切换
选择日期查看这一天处于开始与结束日期范围内的顶层任务
双击日期电脑端直接新建任务，并把开始、结束日期预设为当天
点击当日日程的「＋」创建任务，日期预设为所选日
展开任务在当日明细中逐层显示有效子任务；切换日期后自动收起
🔒 数据说明：任务数据只保存在本地 SQLite 的 task_documents、task_nodes、task_progress 和 task_audit_events 表中，不会写入 Obsidian 的 Tasks/ 文件夹。任务数据不能从 Vault 重建，请定期在应用的数据保护区创建并下载 SQLite 一致快照。
↻ 任务更新使用版本检查避免并发覆盖。如果页面提示版本冲突，请刷新任务详情后再提交修改。

书籍 Wiki — 从来源到可审核的知识

为阅境轩书架中的每个 Markdown 文件夹建立一个独立知识库。同步先建立章节来源索引；智能编译再尝试跨章节归并概念、论断与关系。原始 Markdown 文件保持只读，结构化实体、引用、版本、审核记录和运行状态保存在本机 SQLite。单个 PDF 目前不能建立 Wiki。

开始前：配置 Agent Runtime 与模型

智能编译、知识问答和研究任务需要可用的 Agent Runtime。当前只支持通过 ACP 接入 DeepSeek Harness；这里的 “DeepSeek” 指运行时，不要求使用 DeepSeek 的模型 API。你可以配置兼容协议的其他模型供应商。

  1. 1
    添加模型供应商

    进入「Wiki 配置 → 模型供应商」，点「＋」。填写名称、协议、Base URL 与模型 ID，和供应商提供的信息保持一致。可以保存多个供应商，后续用铅笔修改。

  2. 2
    配置 API Key

    选择「系统凭据库」时，在页面密码输入框填写密钥并保存；数据库只记录配置元数据，不保存明文密钥。选择环境变量模式时，填写变量名，例如 CUSTOM_LLM_API_KEY，再在启动后端的进程环境设置其值。不要把密钥放进 Skill、书籍文档或截图。

  3. 3
    声明模型能力

    按供应商说明填写上下文窗口、最大输出与推理策略；不清楚时不要猜一个很大的值。声明只用于请求规划，不能让模型超出实际能力。启用并保存供应商。

  4. 4
    绑定执行器

    电脑需要有可执行的 npx。进入「Agent Runtime」，检查 ACP 启动命令，例如 npx -y @deepseek-ai/dsh@0.1.5-rc.1 --profile acp，选择刚保存的第三方模型供应商、启用并保存 Runtime。首次启动可能下载依赖；不选择供应商则使用 Harness 默认 Profile。

  5. 5
    验证已保存配置

    点击「验证已保存配置」，检查执行器能否实际启动并完成模型请求。只有显示「连接已验证」才继续编译或问答；修改供应商或 Runtime 后重新保存、验证。这个步骤会调用模型，可能产生费用。

ⓘ如果系统提示「未找到可执行文件」，先检查服务进程能否找到 npx 或你填写的 ACP 程序；如果模型请求失败，检查 API Key 所在环境变量是否对后端进程可见，以及 Base URL、模型 ID、协议是否匹配供应商。更改环境变量后需要重新启动服务。

从书架建立知识库

  1. 1
    添加 Markdown 书籍

    先在「阅境轩 → 书架」添加一个 Markdown 文件夹。书籍知识库按书架中的每本文件夹书籍隔离；PDF 可以继续阅读，但暂不进入 Wiki 工作流。

  2. 2
    建立知识库

    进入「知识 → 书籍知识库」，找到对应书籍，点击「建立知识库」。这一步创建知识库及默认配置文档，不会自动完成来源同步。

  3. 3
    同步

    点击同步图标（手机在「…」操作抽屉选择「同步来源」），读取 Markdown，建立章节来源与检索索引。同步不调用模型，只产生章节证据，不等于已经生成主题 Wiki；原书修改后也需要重新同步。

  4. 4
    智能编译

    来源同步完成后，点击「智能编译」。页面会显示运行阶段、来源与批次进度；离开页面不会取消后台任务，需要时可主动停止。编译生成主题知识候选，而不是立即改写正式 Wiki。

  5. 5
    审核并发布

    运行结束后点击「查看并审核」，逐项核对新增、更新或争议候选的正文、引用、影响范围和前后差异。确认无误再点「批准并应用」；不合适的候选可驳回并注明原因。

↻什么时候再编译：书籍来源变更后先同步，再做增量编译；模型、配置或生效 Skill 的指纹变化，可能让系统重新分析更多甚至全部来源。同步后的章节证据仍可作为兜底，智能编译没有产生有效候选时也不会伪造待审核内容。

在 Wiki 工作台查看与维护

进入「知识 → Wiki 工作台」，选择一本书后按标题、摘要或正文搜索实体。打开实体可以查看 Markdown 正文、论断、关系、原文引用和版本历史；引用包含来源路径、行号与摘录。关系洞察帮助浏览知识之间的连接，「知识体检」用于检查缺少来源或重复主题，不调用模型，也不会自动修改数据。

  • 审核队列：「审核」入口集中展示待决候选；批准时服务端再次校验来源和引用，再原子写入正式知识。
  • 人工调整：编辑、合并或拆分实体会形成高风险候选，需要回到审核队列确认，不能绕过审核直接覆盖正式版。
  • 同步来源：工作台也提供同步入口；来源变更后应重新同步并按需重新编译。
  • 暂停与归档：在「书籍知识库 → 管理」调整书籍状态。暂停或归档后知识库只读；删除生成知识会移除该书的 Wiki 产物，但不会删除书架条目或原书。

知识问答：带着来源追问

进入「知识问答」，选择一本书后提问。Agent 按问题决定是否检索，优先选择已编译的主题知识；证据不足时继续读取相关实体或原文。工具目录与检索候选用于定位，不直接当成已读证据。回答以流式 Markdown 显示，引用标记对应本轮实际读取的材料；回答结束后页面在下方展示来源卡片。

  1. 1
    问一个具体问题

    例如「这本书如何解释缓存命中率？有哪些影响因素？」。问题可以包含比较对象、期望深度和适用条件；没有这些内容的书不能凭空给出依据。

  2. 2
    在同一会话继续追问

    例如「刚才第二个因素有哪些反例？」。最近会话帮助理解指代，不代替本轮证据；长对话不保证保留全部旧内容，必要时重新说明关键限制。

  3. 3
    打开来源预览

    点击回答中的 [S1] 或末尾来源卡片，弹窗核对本轮引用的正文与位置，不直接跳走。再点「打开当前版本」才进入工作台；当前版本可能与引用时的快照不同。

  4. 4
    决定怎么处理答案

    回答下方眼睛查看本轮运行，保存图标生成 Wiki 待审核候选，研究图标把问题带到研究任务创建界面。手机通过会话设置查看历史，点「＋」新建会话；中文输入法确认候选不会直接发送。

  • 证据不足：先确认已同步、书籍选择正确，或换一个更贴近原文的关键词；不要把没有引用的回答当作已核实结论。
  • 保存回答：「保存到 Wiki」只创建待审核候选，不会立即把模型回答写入正式知识库。
  • 边界：一次问答限定在所选书籍；不同书籍的来源不会混入同一个回答。

研究任务：报告和可下载 PPTX

适合需要比较多个概念、分阶段整理证据、形成完整成果的问题。研究报告与 PPTX 都以所选书籍为主要依据；它与任务中枢里的个人待办不同。

  1. 1
    说明任务

    在「研究任务」点「＋」，选择书籍、任务类型和交付物。专题研究用于深入分析，知识刷新用于重新核验已有知识，事实审核用于检查具体主张。

  2. 2
    把交付要求说清楚

    例如「比较书中三种缓存策略，说明适用负载、成本和失败场景；面向有基础的工程师，用 10 页 PPTX 汇报，只用书内依据」。先分析诉求再确认简报，也可以跳过分析直接确认；分析本身可能调用模型。

  3. 3
    确认并启动

    核对研究深度、受众和材料偏好，创建后启动任务。任务进入本地持久化队列，离开页面不会取消，但运行服务的电脑必须保持开机。启动任务可能产生模型费用。

  4. 4
    查看阶段，而不是只等最终结果

    打开任务或阶段的查看图标，切换「阶段 / 报告 / 运行检查器」。阶段成果保留；错误页会指出停在哪一步，可取消或恢复未完成阶段，不能把部分输出当作完整交付。

  5. 5
    阅读报告或下载 PPTX

    报告在页面以 Markdown 展示。PPTX 先形成研究报告再编排幻灯片，生成后通过下载图标取得文件，用 PowerPoint 或其他兼容软件打开；当前没有应用内幻灯片预览。PPT 生成失败时，已完成的研究报告仍可查看。

  • 外部资料：外部研究默认关闭。只有专题研究任务中你明确开启，并指定允许的域名和请求次数后，才会读取受限的 HTTPS 文本；这些外部参考与书内引用分开标识。
  • 检查实际执行：在任务详情打开「运行检查器」，查看本次生效的 Prompt、Skill 快照、配置、工具白名单与事件时间线，便于追查任务为什么得出某个结果。
  • 写回知识：研究结果如需进入正式 Wiki，同样先形成候选并由你审核，不会直接修改原书或绕过审核。

配置文档与 Skills

「Wiki 配置 → 配置文档」先选择书籍，编辑领域、术语、边界等规则并保存。配置文档说明这本书的约束；Skill 说明某类工作如何做，两者作用不同。修改只影响后续运行，已经生成的报告不会自动重写。

在「Skills」选择同一本书，用眼睛查看完整正文、文件和来源；内置正文只读，需要改时点「复制为自定义」，再用铅笔编辑。不要仅凭名称判断能力，也不要把普通 Markdown 指令当作可以执行任意脚本的插件。

内置 Skill用途
book-ingest智能编译：从来源提取并整合可追溯的主题知识
book-query问答：按证据回答、处理冲突与不确定性
book-research研究：规划问题、整理证据并形成报告
book-lint质量检查：诊断引用、论断与知识结构问题
book-presentation演示交付：组织可生成 PPTX 的结构化内容
book-synthesis跨章节综合：归并主题、别名与关系
markdown-collectionMarkdown 文集：适配非传统章节式资料

7 个内置 Skill 保留当前发布内容，不要求用户从旧版本中挑选。自定义 Skill 可通过上传图标导入受限的 Markdown ZIP。先选择书籍，再启用 Skill 并设置「问答与研究」「仅问答」「仅研究」「仅智能编译」或「全部场景」；问答与研究只有对当前书籍启用且范围匹配时才加载。book-ingest 是智能编译兜底，PPT 任务有内置演示 Skill 兜底，所以关闭自定义 Skill 不等于关闭所有规则。

🔎先用一小份资料验证改动是否符合预期。页面提供自定义候选的评测、基准和发布状态，但这些状态不意味着任意新问题都能保证回答正确；内置正文也不冒充经过完整质量评测。

Token 用量、备份与排错

  • Token 用量：在「配置 → Token 用量」按时间范围和调用方查看。没有供应商精确明细时标为估算，通常只覆盖初始 Prompt 和最终输出，不包含 Agent 内部多轮、压缩和推理的全部消耗，不能当作账单。上下文占用也不等于计费 Token。
  • 数据保护：在「配置 → 数据保护」创建并下载 SQLite 一致快照；也可导出单本书的 JSON 或 Markdown Wiki。恢复备份会替换当前数据库，务必核对文件并先保留现有备份。
  • 编译卡住或失败：先看书籍知识库的阶段和最后错误，再检查 Runtime 连通性、来源同步状态；研究任务则可用「运行检查器」核对本次配置与事件。重新编译前不必删除原书或知识库。
🔒数据边界：Wiki 的实体、引用、候选、审计和任务产物存在本机 SQLite；导出不是实时同步。模型会接收到任务所需的检索片段，因此使用第三方供应商时请自行确认其数据政策。智能编译和研究流程不会直接写回或更改原书 Markdown 文件。
