# 演示策划（book-presentation）

把已完成的书籍研究报告编辑成适合真实沟通的演示文稿规格。你负责受众、中心主张、叙事节奏、页面角色和证据映射；ObsidianBrain 负责结构校验、本地渲染和 PPTX 下载。

本 Skill 受 PPT Master 的“策略→规格→校验→产物”方法启发，但专门适配阅境轩的数据库证据和受控 Rust 渲染器。不调用 Shell、PowerPoint、网络搜索或外部素材工具，也不声称已写入任何文件。

## 1. 定义沟通任务

在编排页面前，先在内部回答：

- 受众已经知道什么，又容易误解什么？
- 演示是要帮助理解、支持判断，还是推动行动？
- 听众离场时只能记住一句话时，那句话是什么？
- 哪些结论有强证据，哪些只是有条件的解释？
- 文稿更适合独立阅读还是现场讲解？

将答案压缩为明确的 `audience` 和 `core_message`。不要把任务标题原样重复为中心主张。

## 2. 先建叙事，再分页

按用户确认的用途编排材料。教学场景先解释必要概念与机制；决策场景突出选项、判据和条件；查阅场景方便定位事实与例外。默认采用连贯的论点式叙事，让每页承担一个不同的沟通职责，而不是把研究时的子问题依次写成问答页。只有用户明确确认演示编排为 `qa`，才可按真实沟通问题逐题讲解；仍须给出证据、答案、条件与收束，不能把提问当作内容。上述顺序都可按证据和受众调整，不是必须凑齐的模板。

只有当一项内容对受众有独立价值时，才给它一页。不按 Markdown 章节机械分页，也不保留“背景”“分析”“总结”这类不说明对象的空标题。背景、定义、过程和对照页的 `title` 直接命名具体对象或关系；发现页可使用证据支持的事实性结论。`takeaway` 说明该页最重要的信息、判断或适用边界，不复述标题，不用口号填空。封面标题也应像材料名称，不必照抄用户的问题。

## 3. 让构图表达关系

根据内容关系选择版式，不要把所有页面都写成同样的要点页：

- 需要被记住的强判断：`statement`。
- 两个方案、角度、时期或条件的同维度对照：`split`。
- 有明确先后、依赖或反馈的机制：`process`。不把并列观点伪装成步骤。
- 报告中真实存在且能改变判断的数字：`metric`。同时保留口径、范围、时间和限定。
- 报告中存在 2–6 个同口径非负数值：`chart`。类别、数值和单位必须来自同一证据语境，不能补齐缺失数字或混用不同口径。
- 一个中心概念与多个概念之间存在可命名关系：`relationship`。关系标签要说明连接的含义，不把顺序步骤换一种画法。
- 报告中可核对且值得单独呈现的原话：`quote`。不得为了版式编造引语。
- 支持、反对、限定条件或竞争解释：`evidence`。
- 收束为可记忆要点或行动：`summary`。

相邻页应有节奏变化，但多样性不能凌驾于事实。没有数据就不使用 `metric` 或 `chart`，没有明确概念连接就不使用 `relationship`，没有原话就不使用 `quote`。

## 4. 控制密度与层次

- 一页一个主要观点；`body` 只补充理由、条件或启示。
- 只填写所选布局会显示的载荷字段；`body` 仅用于 `statement`、`metric`、`evidence`、`summary`，收束页最多 4 条。图表、关系和流程页分别使用自己的结构字段，不要把重要内容另塞进隐藏的 `body`。
- 每条文字应能独立理解，去掉“首先”“值得注意的是”等无信息开头。
- 优先删除重复句，而不是堆满页面。
- 不输出复杂宽表、长代码、假图表、图片占位符、装饰指令或动画说明。

## 5. 逐页文字审校

先核对每页实际展示了什么，再定标题和结论。概念、背景与步骤页的标题可以是准确的主题名；只有展示了可靠发现的页面才使用结论式标题。不要为了显得有洞察，把定义页写成未经证明的因果判断。

- `takeaway` 必须说出该页已交付的信息、判断或明确边界，不以问句收尾。即使用户选择 `qa` 编排，问题也只能放在合适的标题中，`takeaway` 要回答它；证据不足时写出具体尚不能回答的部分。
- 检查每页在整份材料中的独立作用。同一句结论不能换标点、换同义词分散到多页；多页若都在讲同一件事，应合并，并把腾出的篇幅用于有证据的对照、限定、反例或影响。
- 把“本页介绍”“值得关注”“赋能增长”“从 A 到 B”这类空话改成具体对象、事实或条件。不要为凑节奏强行写整齐的三段式口号或三条并列动作。
- 报告有争议、时间范围、样本口径或仅适用于某种条件时，保留这些限定；不要把条件性解释缩成无条件建议。无法从材料核实的数字、原话和因果关系直接删掉，不用漂亮措辞掩盖缺口。
- 逐页通读标题、`takeaway`、正文和版式载荷是否互相支持；先删重复和弱句，再考虑字数。不以缩小字号或塞满图形解决信息过载。

## 6. 逐页绑定证据

把研究报告中的 `[S<n>]` 映射为页面 `citations`。数字、引语、比较、因果和强判断必须能在当页追溯。多个来源只有在共同支持当页论断时才并列，不把同一组来源复制到每页。

图表必须填写 `chart.context`，它直接显示在图表下方。写清会改变比较结论的版本、线程/并发、容量、样本数、工作负载、显式配置和统计口径，选取来源中真实提供的条件，最多160字符。没有测量条件则明示“来源未提供测试条件”，不补造配置。不能只放来源编号或藏进报告正文。`metric.context` 同样保留关键限定；对照页在左右实际显示的 points 中交代共同基线。平均时延不能改写为尾延迟，实验收益不能写成已达成上线目标。

最后收束页可以不带引用，但不得在收束页新增事实。证据不足时明确写成条件或待验证项，不得用设计感遮盖不确定性。

## 交付前自检

1. 封面标题是否准确命名这份材料，核心信息是否与受众和用途一致？
2. 前两页是否给读者必要的背景或判断依据，而不是重复题目？
3. 每页是否只有一个明确职责；标题是否准确描述内容，`takeaway` 是否给出信息或边界，而不是重复标题或留下问题？
4. 版式是否来自真实内容关系，而不是随机轮换？
5. 数字、引语、比较和关键判断是否都有有效 `S<n>` 引用？
6. 图表的类别、数值和单位是否来自同一口径，且没有为了视觉效果补造数据？
7. 是否存在跨页重复结论、空洞措辞、过密页面或报告中不存在的素材？
8. JSON 是否严格符合上层给出的合同，且没有未知字段、围栏或尾随说明？

上层任务提供的证据边界、输出 JSON 合同和字段上限优先于本 Skill。
