# 维护已有书目

已发布的主题构成读者正在使用的书目。根据 `changed_sources` 的原文变化逐项分配编辑任务。用 `existing_pages` 里的范围和摘要判断哪个主题已经承担该问题。应用会安排 `required_pages` 中的改写，覆盖所有直接分配或引用该来源的主题。它们省略在 `pages` 里即可。

`related_passages` 是从当前主题正文搜到的段落。核对它们实际讲的命题、对象和条件，再决定是否需要连带更新。题名或术语相似只能作为检索线索。

1. 新证据改变结论、前提、限制、例子或版本时，优先更新已有主题。一份来源可以修订多个主题。给出具体的事实变化或分歧，供编辑定位。
2. 只有当来源支持一个读者明确会问的独立问题，并且书目现有范围无法承载它时，才新增主题。标题写读者要理解的事，范围说明要解答的问题。每个新主题与至少一个已有主题建立有解释力的阅读关系。使用书目给出的稳定 ID。
3. 如果新增文本对 Wiki 没有实质贡献，让 `pages` 和 `new_pages` 为空，说明原因。例如只调整排版，或重复已有的结论和条件。节选不足以判断且没有可靠的页可分配时，标记 `needs_review`。
4. 遇到证据之间的冲突时，路由到解释这项结论的主题，在理由里点出冲突发生的对象、版本或条件。由主题编辑查证双方依据，再决定如何呈现。

只返回一个 JSON 对象。每个提供的原文编号出现一次。额外的更新目标写在 `pages`。每份来源最多建议两个新主题，每个新主题最多六条原文检索词。复用真实 ID。理由和范围用简短、具体的文字。

```json
{
  "sources": [
    {
      "source": 1,
      "pages": ["existing-page-id"],
      "new_pages": [],
      "reason": "新实验把平均延迟的适用条件限定为无淘汰压力的负载。"
    },
    {
      "source": 2,
      "pages": [],
      "new_pages": [
        {
          "title": "重试与淘汰如何相互影响",
          "focus": "解释请求重试在什么情况下改变回收顺序。",
          "queries": ["重试", "回收顺序"],
          "related": [{"page_id": "existing-page-id", "reason": "先了解正常请求释放缓存的条件。"}]
        }
      ],
      "reason": "新增资料解释了重试路径及其释放时机。"
    }
  ]
}
```
