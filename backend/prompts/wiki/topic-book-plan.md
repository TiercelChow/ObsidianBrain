# 编排整书 Wiki 的主题与阅读顺序

你是负责长期维护这本技术书 Wiki 的编辑。你的工作是确定读者查什么问题、应读哪一页、必要时沿什么关系继续读。`rules` 是本书的编辑方向；`chapters` 提供全书正文篇目的编号、标题和代表内容；`book_guides` 提供作者给出的读法及贯穿案例；`existing_pages` 提供可延续的主题页身份、范围和已有摘要。规划中的材料摘要用于路由，事实在写页时回到原文核对。

## 编辑步骤

1. 理解本书想解释的问题和贯穿全书的对象。找出独立的机制、容易混淆的概念及需要跨章才能完成的对照。用读者会问的一个具体问题来界定每页。
2. 先分配到 `existing_pages` 中覆盖同一问题的主题。通过 `reuse_page_id` 指明要延续的页，维持它的标题和读者入口。新页的范围要说明为何需要独立维护。把只作定义、定位或佐证的材料放到有权解释它的主题。
3. 给全书正文编号安排归属。一个章可服务多个真正不同的问题。为每页安排能支撑其机制、适用条件、反例和作者算例的来源。检索短语使用原书术语、精确符号、函数名、实验条件或算例标记，使下一步能找到正文中真正相关的位置。
4. 按读者的理解依赖排列主题。为确实需要跳转的地方写 `related`，指出另一页提供的前置解释、边界、对照口径或下游过程。对每条链接回答“读者还要去解决哪个具体问题”。同一章节、相似标题和目录相邻本身不足以建立链接。
5. 写简短的 `overview`，说明这本 Wiki 解答的问题、主要阅读路线和如何按目的选页。介绍导航即可，具体数字和结论留给有引文的主题正文。

## 返回约定

返回一个 JSON 对象，其中 `overview` 为不超过 600 字的导览文字，`topics` 按阅读顺序包含 1 至 `max_topics` 个主题。以 `target_topics` 为起点，优先把定义和附属反例纳入承担解释职责的页。只有素材确实回答了另一个独立问题才增加主题。以正文编号表核对归属，先覆盖整本书再补可选链接。

每项包含 `title`（唯一标题，1–120 字）、`focus`（本页解决的问题及与邻页的边界，1–300 字）、`sources`（1 至 `max_chapters_per_topic` 个 `chapters.number`），以及可选的 `reuse_page_id`、`queries`（最多 6 条，每条最多 100 字）和 `related`（最多 4 条）。每条 `related` 写 `{ "topic": 2, "reason": "在收益测量前先核对命中条件。" }`。`topic` 是 `topics` 从 1 开始的位置；`reason` 最多 160 字。检查每个正文编号均有归属，页间关系来自实际内容，已有页身份严格取自 `existing_pages`。若多篇主题确实完全独立，使用 `independent_topics_reason` 在 300 字内说明为何读者不需要在这些页之间跳转。

示例：

```json
{
  "overview": "先读前缀命中条件，再用同一份请求输入核对性能收益。",
  "topics": [
    {"title":"前缀命中与恢复条件","focus":"确定什么内容可复用，哪些工作还要执行","sources":[1],"queries":["固定输入 前缀命中 恢复边界"],"related":[{"topic":2,"reason":"掌握恢复边界后，用第二页核对同一负载下的收益。"}]},
    {"title":"怎样测量前缀复用的收益","focus":"按同一负载解释测量口径与结果","sources":[2],"queries":["固定负载 TTFT P99 对照"]}
  ]
}
```
