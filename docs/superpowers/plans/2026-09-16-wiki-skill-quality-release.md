# Wiki Skill 质量发布与编译审计实施计划

## 目标

把 Skill 从“可编辑提示词”提升为可追溯、可评测、可发布、可回滚的受控资产；同时让智能编译的每项变更都能解释它属于新增、更新、争议或无实质变化，并在审核前展示引用质量与级联影响。

## 批次一：Skill 质量发布闭环

1. 为 Skill 版本增加候选、已发布、已退役状态和父版本、变更说明。
2. 记录上游仓库、来源路径、提交引用、许可证、署名和本地适配说明。
3. 建立按用途划分的固定离线评测集，保存候选与当前版本的对比结果。
4. 候选版本只有在评测通过后才能发布；发布后可回滚到任一历史已发布版本。
5. 配置页展示来源、许可证、版本状态、评测分数和发布/回滚动作。

## 批次二：编译结果分流与审计

1. 每项编译结果标记为 `new`、`update` 或 `disputed`，无高价值变化则生成 `no_material` 编译记录。
2. 对条目引用和原子论断引用做完整性审计，保存可解释的问题列表。
3. 在变更集生成时计算受影响的条目、论断、关系和重定向数量。
4. 审核界面在应用前展示分类、引用审计和影响范围。

## 质量边界

- 固定评测首版是确定性的结构与安全规则评测，不冒充真实模型回答质量。
- 开源来源只有许可证明确时才允许成为可发布候选；许可证不明确的项目只作人工参考。
- Skill 不能扩大 Agent 的工具权限，后端引用校验、变更审核和事务写入始终优先。
- 发布动作只切换当前版本，不删除历史版本；回滚可逆且留有评测记录。

## 验证

- 数据迁移可从空库和已有 v25 数据库升级。
- Store 覆盖评测、未通过拦截、发布和回滚测试。
- 语义变更覆盖新增、更新、争议、无变化、无效引用和影响范围测试。
- `cargo fmt --check && cargo clippy -- -D warnings && cargo test`
- 前端单元测试与生产构建。
