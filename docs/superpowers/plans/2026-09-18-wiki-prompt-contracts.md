# Wiki 提示词与输出质量改进

## 目标

改善智能编译的 JSON/空结果稳定性，以及问答、研究的证据组织和回答质量。提示词不能保证模型一定正确，因此输出协议须与后端校验和有界修复配套。保留短输出、来源分批、人工审核、章节兜底及现有工具权限。

## 实施

1. 为单对象 JSON、围栏、重复对象、非法字段/引用、无理由空结果添加回归测试。
2. 将编译协议独立为可读提示词和可执行 JSON Schema，使用合法示例；按本批校验引用、论断和关系。区分空正文与有理由的无新增知识；失败合计最多修复一次，提供具体字段错误和失败响应。
3. 完善问答/研究的常驻规则与三份内置 Skill：意图拆分、证据质量、竞争解释、冲突条件、部分回答、可执行核验建议及交付物适配。
4. 为问题和证据保留上下文预算，避免配置/Skill 增长挤掉问题或后续证据。编译保留完整批次来源，不以截断来源推进检查点。
5. 新迁移按产品所有者要求直接覆盖三个内置 Skill 的当前版本正文、哈希和说明，不新增或冻结版本；同时失效引用旧正文的评测与模型基准，防止复用旧分数。更新编译指纹，下一次用户触发才重新编译。
6. 开发期仅保留每个 Skill 的当前内容：升级迁移清理所有非当前版本，后续编辑或发布完成后同步清理旧正文；候选只在发布前暂存。
7. 更新开发文档，执行相关回归、Rust 格式、Clippy 与完整测试，自审变更；不调用真实模型，不修改用户书籍与知识实体数据。

## 验证重点

- 不把多个 JSON 对象、截断内容或伪造引用静默当作成功。
- 文本/字段/引用错误都能进入同一有界重试；失败不推进检查点。
- 明确无实质变化仍能正常完成；空正文或无理由空数组不可混同。
- 新旧安装的三个内置 Skill 都使用本次正文，版本数量不增加。
- 多配置、多 Skill、长历史下当前问题与全部预载证据保留，截断有标记。
