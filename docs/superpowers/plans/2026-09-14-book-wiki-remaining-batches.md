# Book Wiki 剩余需求分批实施计划

> 日期：2026-09-14  
> 范围：仅 Markdown 书籍知识库、DeepSeek Harness；PDF 只保留阅境轩阅读；PPTX 只要求生成后下载。

## 总体目标

在不破坏现有书架、问答、研究任务、审核、Skill 和 PPTX 纵切能力的前提下，把 Book Wiki 从“可验证原型”推进到“可持续使用”的完整版本。每个批次都必须独立可测试、可回滚，并以失败测试、实现、回归、代码审查的顺序完成。

## 批次一：增量构建与全文检索底座（已完成）

目标：知识库规模增长后，同步和检索仍保持可预测的速度；修改单个 Markdown 文件时不再让模型重新分析全书。

- 为每个来源文档记录最近成功语义编译的版本检查点。
- 智能编译只读取新增或内容变化的当前来源；成功创建变更集后原子更新检查点。
- 没有来源变化时保持 `ready`，不把知识库误标为失败。
- 用 FTS5 承担实体与章节正文的主检索和相关度排序，保留中文/特殊查询的兼容降级。
- 增加增量编译、幂等、中文召回、标题优先排序和知识库隔离测试。

验收门槛：修改两文件书籍中的一个文件后，第二次编译只向 Runtime 发送该文件；无变化重复编译不发起 Runtime 调用；检索结果按标题/语义条目优先，现有自然语言中文查询继续可用。

## 批次二：DeepSeek Harness 受控工具与原生运行事件（已完成）

目标：让 Harness 在单次运行的权限范围内按需读取知识，而不是由 Rust 一次性把全部上下文塞入提示词。

- 实现短期 Run Capability，绑定 Run、知识库范围、工具集合和过期时间。
- 提供本机专用工具网关：上下文、来源列表/检索/读取、实体检索/详情/邻居、进展和变更候选。
- 为 DeepSeek Harness 固定 Profile 接入工具桥；默认无 Shell、任意文件和无限制网络。
- 将 ACP 原生文本 delta、工具事件、Usage 和取消映射到持久化事件；运行时不提供的字段继续明确标记为 estimated/unavailable。
- 问答与研究任务消费统一事件流，支持中断恢复和主动取消。

验收门槛：越权知识库、过期令牌和未知字段均被拒绝；取消能终止实际 ACP 运行；有原生 delta/Usage 时前端展示真实数据，无原生能力时不伪装。

## 批次三：知识工作台与阅境轩联动

目标：用户能高效查看、校正和利用数据库中的知识，而不只是运行自动流程。

- 完成实体详情编辑、别名、状态、论断、引用、版本、合并/拆分候选和审核差异。
- 实现关系邻居、路径、孤立节点和桥接节点查询；桌面图谱与手机洞察列表按需加载并释放资源。
- 阅境轩 Markdown 阅读页增加“询问、解释、添加知识候选、创建研究任务”，携带书籍、文件、标题、行号和选中文字。
- 完成知识库暂停、恢复、归档、删除和原书路径失效处理。
- 为长实体列表增加后端分页和前端虚拟化/分段加载。

验收门槛：手机和桌面均能完成阅读选文到问答/任务、实体查看编辑、关系导航和审核闭环；PDF 阅读页不出现 Book Wiki 操作。

## 批次四：备份、恢复、导出与可靠性

目标：数据库知识可保护、可迁移、可诊断，长时间运行不会损坏状态或持续占用资源。

- 使用 SQLite Online Backup API 做一致快照、迁移前备份、保留策略和完整性检查。
- 支持单书结构化 JSON、可浏览 Markdown Wiki、引用清单、问答/研究报告导出。
- 实现恢复前检查、恢复后迁移/外键/FTS 校验与 FTS 重建。
- 完善研究任务租约、崩溃恢复、退避重试、同书写任务互斥和 Harness 空闲回收。
- 对十万片段规模做查询计划、内存和移动端回归测试。

验收门槛：备份可以恢复实体、引用、配置、会话、任务和版本；导出不被原书同步重新摄入；服务重启不会把中断任务误标成功。

## 批次五：授权扩展与旧模块退役

目标：在核心闭环稳定后扩展研究能力，并消除双套知识产品造成的维护负担。

- 在每次任务显式授权的前提下提供域名范围、只读、限流的外部研究工具。
- 扩展安全的指令型/成果型 Skill；脚本型 Skill 必须先完成独立沙箱、审批和资源配额，不直接继承宿主权限。
- 补充 `book-synthesis`、`markdown-collection` 等内置 Skill 与输出契约。
- 删除旧知识五页面、旧 Wiki/Explore/Insights 路由和无使用方后端工具；保留一个发布周期的跳转与数据说明。
- 更新顶层设计、README、Website 和用户手册，完成全量回归。

验收门槛：旧模块删除后所有构建与测试通过；外部研究未经明确授权无法访问网络；新 Skill 不能绕过知识库范围和审核机制。

## 执行顺序与提交策略

按一至五顺序推进，不跨批次混合提交。每批至少形成一个 Conventional Commit，并在提交前运行：

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
npm test
npm run build
```

对项目中已知不稳定的文件监听测试单独记录平台原因，不用跳过其他回归来掩盖失败。
