# Book Wiki 演示文稿重构计划

## 目标

将现有“研究报告按 Markdown 标题拆成白底黑字要点页”的管道，重构为受控的两阶段流程：

1. 研究 Agent 生成有证据、有边界的完整报告。
2. 演示策划 Agent 将报告转换为严格 JSON `PresentationSpec`，本地 Rust 渲染器负责生成可编辑 PPTX。

设计参考 PPT Master 的“演示策略 → 中间规格 → 质量检查 → 文件输出”思路，但不向 DeepSeek Harness 开放 Shell，不引入不受控的脚本执行。

## 实施步骤

1. 定义可版本化的演示规格：受众、核心信息、视觉主题、页面角色、布局、要点、对比/步骤内容和来源引用。
2. 先写规格解析与质量校验测试，覆盖多余 JSON、未知布局、无效引用、文本过载和结构缺失。
3. 将研究任务的 presentation 交付改为二次受审计的 Agent 调用；第二次调用只允许使用已有报告和证据编号，不授权工具。
4. 重写本地 PPTX 渲染器，支持开场、观点、左右对比、过程、数字强调、引语和收束等不同构图，并保持文本和图形可编辑。
5. 扩展品质门禁：页数、字数密度、布局多样性、引用合法性、包结构与关键部件。
6. 重写 `book-presentation` Skill，并通过新迁移直接覆盖开发阶段的当前版本，同时记录 PPT Master 的 MIT 来源和适配边界。
7. 更新 LLM Wiki 开发文档，运行定向单测、格式化、Clippy 和相关回归测试。

## 非目标

- 本批不开放 Harness Shell，不让 Skill 直接写文件。
- 本批不引入 PDF 生成或 PyMuPDF。
- 本批不依赖云端图像生成；视觉质量首先由排版、层次、构图与可编辑信息图提升。
