# Book Wiki 演示文稿剩余两批实施计划

## 前提

第一批已经把旧的 Markdown 标题拆页替换为“研究报告 → 严格 `PresentationSpec` → 本地可编辑 PPTX”的受控流程。本计划继续提高信息表达和交付透明度，不向 DeepSeek Harness 开放 Shell，也不允许模型直接写文件。

## 批次二：可编辑数据表达与关系图

1. 为 `PresentationSpec` 增加受限的 `chart` 与 `relationship` 布局。
2. 图表只接受报告中已有的非负数值、单位和类别，限制数据点数量；没有可靠数字时不得使用。
3. 关系图只表达一个中心概念与 2–4 个相关概念，关系标签和节点文字均受长度限制。
4. 使用 PPTX 原生文本框、形状和连接线渲染，保持内容可编辑；不把图表或关系图烘焙成截图。
5. 更新 Prompt、内置 Skill、迁移和测试，用真实渲染检查新增构图没有截断或重叠。

## 批次三：质量报告与交付透明度

1. 将策划校验、包结构校验、引用覆盖、布局分布和文件哈希整理为结构化质量报告。
2. 质量报告与成果元数据一起持久化，下载仍只暴露受管 PPTX，不开放任意路径。
3. 研究任务结果页展示页数、布局数量、引用覆盖和校验结论；失败时保留研究报告并明确指出 PPTX 阶段失败。
4. 运行检查器可从研究 Run 跳到独立的演示策划 Run，查看实际 Prompt、Skill 快照和修复事件。
5. 补齐迁移、API、前端与回归测试，并分别提交两批改动。

## 保持不变的边界

- 不增加 PDF 交付。
- 不支持 Claude Code，只使用现有 DeepSeek Harness。
- 不隐式联网搜索图片，也不调用额外图像模型。
- 不在浏览器中执行 PPTX 渲染；桌面端和手机端只展示质量状态并下载成果。
