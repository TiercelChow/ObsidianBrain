# Book Wiki 问答与研究任务：Harness 原生能力落地计划

> 2026-09-25。基于 `docs/requirement/08-llm-wiki.md` 与 `docs/development/08-llm-wiki.md`。本计划以当前工作树为起点，不回退已有问答目录选择与会话改动。

## 目标与边界

- Harness 负责单次任务内的模型请求、工具调用、再次判断和输出；后端不实现固定轮数的 Agent 状态机。
- SQLite 仍是书籍实体、来源、会话、任务、Skill 版本和证据审计的唯一事实来源。书籍原文只读；跨书及外网访问必须显式授权。
- 编译知识优先；只有核对精确表述、消解冲突或补足缺口时读取原文。候选目录与旧工具结果不得无差别进入最终回答上下文。
- Skill 的业务版本与绑定由数据库掌控，Harness 只在本次 Run 的隔离范围内发现和按需读取已批准的文本 Skill。不开启 Shell、任意文件、通用 Web 或子 Agent。
- 问答保留流式输出与会话；研究保留持久队列、取消/重试、Markdown 报告与已有 PPTX 渲染流程。

## 批次一：Harness 能力与 Skill 接入

1. 使用固定 `@deepseek-ai/dsh@0.1.5-rc.1` 的 `skill-filesystem`/`tool-skill`。仅问答和研究 Run 在临时工作区物化当前书籍、用途、版本的 Skill，生成独立 Patch：`includeDefaultRoots: false`，只读取本次目录；其余 Run 保持禁用。
2. 将问答/研究 Prompt 中重复拼接的 Skill 正文改为最小调用契约和 Skill 名录，保留不可被 Skill 覆盖的应用级权限与引用规则；运行检查器标注实际应用方式和版本。
3. 验证 Patch、Skill 包结构、无默认目录泄露、无 Shell/文件工具以及多轮 MCP 调用。Harness 不可用时须明确失败，不伪称已完成真实集成验证。

## 批次二：统一检索与证据账本

1. 提供有界的“发现编译实体 → 取完整实体 → 按需读当前原文”工具；候选只带 ID、标题、别名、摘要、出处提示，不传整段正文。章节索引只作兜底。
2. 问答目录选择修复分批竞争：每批候选进入全局去重/重排，不因前批占满固定名额而忽略后批；超长目录限制输入和输出预算。研究对每个子问题使用相同的候选发现能力，不再只靠标题/说明的一次 FTS。
3. 在 MCP 网关服务端记录本次 Run 真正返回的实体 ID、revision、来源片段 ID/版本与外部 URL；预载证据亦记入同一账本。保存回答/报告时校验引用只指向可见证据；无证据可回答时允许明确“不足”，不造假引用。

## 批次三：问答体验与上下文

1. 简单寒暄、改写可跳过书籍检索；书籍事实问题默认走语义候选。Harness 可继续调用检索、关系与来源工具，自行判断充分性，而不是由后端指定轮数。
2. 每轮独立 ACP Session；应用保存对话并只注入必要的近邻上下文/指代信息，不重复塞入此前的完整目录和工具结果。版本变更后旧证据只作历史记录，不冒充当前事实。
3. SSE 展示理解、检索、核对、生成阶段与最终引用；流式正文是暂态，持久化前通过证据门禁。错误/取消不留下伪完成答案。

## 批次四：研究任务、验收与提交

1. 研究 Skill 驱动 Harness 拆解子问题、循环取证、交叉核验和成稿；仍由 SQLite 队列掌控生命周期。PPTX 继续由独立策划 Run 和受控 Rust 生成器交付。
2. 加入成本、工具次数、运行时间与单次结果长度上限；超限时返回有说明的部分结论或失败，不无限循环。外部研究授权保持逐任务域名和配额。
3. 单元/集成测试覆盖跨批召回、跨书拒绝、Skill 隔离、引用归属、追问/换题、研究无证据、取消/重试和 PPTX 回归。可用时用实际 Harness 做最小端到端烟测；记录模型、运行 ID、结果与未验证点。
4. 更新需求/开发文档，执行 `cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test`、前端相关测试与构建，自审后只提交本任务相关文件；保留工作树中的无关用户修改。

## 决策与风险

- 原生 Skill 只加载文本指令；资源文件需按需、经受控工具读取，不因为启用 Skill 而开放文件工具。Skill 提示不能扩大能力令牌。
- ACP 的通用工具生命周期事件不包含足以作为审计依据的完整返回证据；证据账本必须在受控 MCP 网关记录。
- 选择先用每轮新 Session 而不是长期保持一个 Session，避免目录/工具结果积累；持久 Session 待上下文隔离与版本失效经真实测试后再评估。
- 真实模型回答质量不能由单元测试证明；至少建立一组人工可复核的跨章、追问、冲突、无证据样例，并记录召回与引用结果。

## 本批实施与验证记录

- 已完成隔离原生 Skill、分页编译目录与原文、问答分批全局重排、近邻追问上下文、证据账本、引用归属检查、工具调用额度、研究空初始证据继续取证，以及研究检查器证据展示。没有在后端复制固定轮数的 Agent Loop。
- 固定 `@deepseek-ai/dsh@0.1.5-rc.1` 的真实 CLI `--dump-config` 烟测通过：当前 Run 的临时 Skill 目录可见，默认 Skill 根目录和 Shell/文件/Web/子 Agent 工具未开启。这验证的是配置组合，不是模型实际调用 `tool-skill` 或答案质量。
- `cargo fmt --check`、`cargo clippy -- -D warnings`、完整 `cargo test`、前端测试与构建通过。真实模型的跨章召回、冲突消解、Skill 使用率及引用语义正确率仍需在用户书籍上按固定样例人工评估；目前只保证引用标识属于本轮可见证据，不能宣称逐句事实校验。
