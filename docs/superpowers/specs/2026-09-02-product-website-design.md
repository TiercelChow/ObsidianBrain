# ObsidianBrain 产品官网设计

日期：2026-09-02

## 1. 背景

ObsidianBrain 当前的 `frontend/` 是依赖本地 Rust 服务与 `/v1` API 的业务应用，不能作为公开产品官网直接托管在 GitHub Pages。项目需要一套独立、纯静态、可公开访问的介绍站，完整解释产品价值、功能范围、安装配置和主要使用方法。

## 2. 目标

- 发布到 `https://tiercelchow.github.io/ObsidianBrain/`。
- 让首次接触项目的人在一个页面内完成“认识产品—判断适合自己—安装—配置—开始使用”。
- 官网视觉与业务应用保持一致，复用现有主题令牌、圆角、玻璃材质和动效语言。
- 桌面端与手机端都具备独立编排，不依赖本地后端。
- 每次 `main` 分支更新官网内容后，由 GitHub Actions 自动构建和发布。

## 3. 非目标

- 不把本地业务应用部署到 GitHub Pages。
- 不在官网调用 `/v1` 或暴露用户的本地数据。
- 第一版不提供在线演示、账号系统、遥测或表单后端。

## 4. 信息架构

页面采用单页滚动结构，主导航保持固定并提供锚点跳转：

1. 首屏：一句话定位、核心价值、GitHub 和快速开始入口。
2. 产品定位：解释本地知识工作台与普通笔记应用的差异。
3. 工作流：阅读、记录、组织、执行、回顾的闭环。
4. 核心功能：阅境轩、时光机、任务中枢、Wiki、知识库、代码仓、灵感熔炉、智识雷达。
5. 场景展示：使用 CSS 生成与真实产品一致的界面预览，不依赖运行中的后端。
6. 上手指南：环境准备、构建安装、启动、首次配置。
7. 模块用法：按模块说明入口、关键操作和数据落点。
8. 架构与隐私：浏览器、本地 Rust 引擎、Obsidian REST API、Vault 的数据流。
9. 常见问题：网络、局域网、LLM、数据与 GitHub Pages 能力边界。
10. 页尾：GitHub、README、Issue 和 License 状态。

## 5. 视觉系统

官网直接复用业务应用的主题变量：

- 浅色：`#f0f0f3` 背景、`#18181b` 主文字、`#6366f1` 强调色。
- 深色：`#000000` 背景、`#ffffff` 主文字、`#7c7cff` 强调色。
- 护眼：`#c5d5b8` 背景、`#152618` 主文字、`#2e7d4a` 强调色。
- 卡片：半透明背景、20–24px 模糊、细高光边框、低对比阴影。
- 圆角：按钮 12–14px，卡片 22–30px，展示窗口 32px。
- 字体：系统字体栈，标题使用紧字距，正文保持舒展行高。

主题切换按浅色、深色、护眼三态循环，并保存到 `localStorage`；首次访问遵循系统深色偏好。

## 6. 动效原则

- 交互反馈在按下时立即发生，按钮使用轻微缩放。
- 导航与材料层只动画 `transform`、`opacity`，避免滚动时触发布局抖动。
- 内容进入视口时采用克制的上移淡入；每组最多使用很短的错峰。
- 页面不使用持续运行的大面积背景动画。
- `prefers-reduced-motion: reduce` 下取消位移、平滑滚动和错峰动画。
- `prefers-reduced-transparency: reduce` 下关闭模糊并提高背景不透明度。

## 7. 响应式策略

- 桌面端最大内容宽度 1180px，功能卡片为 4/2 列混合布局。
- 低于 900px 时，首屏、架构和使用步骤改为单列。
- 低于 720px 时，主导航折叠为可关闭的移动菜单。
- 手机按钮最小触控区域 44px，并考虑安全区。
- 手机端代码块横向滚动，流程卡片纵向排列，界面预览缩减非核心装饰。

## 8. 技术实现

- 使用独立的 Vanilla Vite 站点，目录为 `website/`。
- HTML 保持语义化和渐进增强；JavaScript 只负责主题、移动导航、复制命令、功能切换和进入视口动画。
- 图标使用内联 SVG，避免远程字体与图标依赖。
- Vite `base` 设置为 `/ObsidianBrain/`，产物输出到 `website/dist/`。
- GitHub Actions 在 `website/` 执行 `npm ci`、测试、构建并发布 `dist/`。

## 9. 可访问性与 SEO

- 提供跳过导航、清晰焦点、语义标题层级和 ARIA 状态。
- 所有图标按钮都有可访问名称，折叠菜单同步 `aria-expanded`。
- 颜色不作为唯一信息载体，正文对比度满足常规阅读要求。
- 提供描述、关键词、canonical、Open Graph、Twitter Card 和结构化数据。
- 页面在 JavaScript 失效时仍能阅读全部核心内容。

## 10. 验收标准

- 页面覆盖产品定位、全部主要模块、完整安装配置和使用说明。
- 页面不存在对本地 `/v1` API 的请求。
- 三套主题可切换并持久化。
- 桌面端 1440px 和手机端 390px 下无横向溢出。
- 锚点导航、移动菜单、功能展示切换和复制命令可用。
- `npm test` 与 `npm run build` 通过。
- GitHub Pages 工作流具备正确权限、构建路径和部署产物。
