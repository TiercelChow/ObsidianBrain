# 移动端体验统一优化方案

> 日期：2026-09-08 · 状态：设计提案，尚未实施
> 基线：`86e97b9` · 范围：`frontend/` 的全部应用页面；官网 `website/` 不在本次范围内。
> 目标：延续桌面端的品牌、配色和材质，以手机的阅读空间、触控方式和使用节奏重新组织界面。

## 1. 设计结论

建议将现有移动端升级为一套统一的「知流 Mobile」体验：**单一标题、单列内容、底部导航与情境操作栏、统一弹层、连续可打断的动效**。

视觉延续现有浅色、深色、护眼三套主题，保留柔和圆角、紫色／绿色强调色和轻玻璃功能层。变化集中在信息层级、操作位置和反馈机制：常用功能靠近拇指，阅读内容获得更多宽度，页面切换和返回具有稳定的空间关系。

“丰富的动画”指按下、切换、展开、拖动、保存、返回都有恰当反馈。阅读正文和已经浏览过的列表不反复播放入场动画；用户连续操作时，界面能立即改变运动方向。

### 1.1 保留的既有产品偏好

- 阅境轩不恢复左右悬浮的文件／目录按钮；操作集中在底部。
- 阅读工具栏在滚动时出现，静止后隐藏；刚打开文件夹而尚未选中文章时，选择入口常驻。
- 时光机手机端继续采用页面自然滚动，不套用桌面端“仅小记面板滚动”的布局。
- 任务列表不显示描述；详情显示描述。任务信息修改集中到一个编辑入口。
- 任务拆解不重复列出最顶层任务；手机端不用桌面双列挤压内容。
- 日历网格只统计／展示顶层任务；当日明细默认只列顶层，展开后显示子任务。
- 手机端农历位于公历数字下方，今日圆形同时包裹二者；选中日期使用圆角色块。
- 字段选择菜单贴着输入栏展开，日期选择器延续阅境轩的主题语言。
- 输入框不出现脱离控件轮廓的矩形焦点框，同时保留可辨认的键盘焦点。

### 1.2 本版提出的主要结构变化

1. 手机主导航改为底部「阅境轩 / 时光机 / 任务中枢 / 全部」，替代左上角侧栏作为主要导航。
2. 手机只保留一个页面标题区，撤掉重复标题和每页固定展示的宣传性副标题。
3. 阅境轩和任务页现有“顶部工具栏收成小拉手”机制退出主流程，由稳定页头与底部操作入口承接。
4. 手机根页面显示主导航；阅读、任务详情、编辑等专注场景在同一底部区域显示情境操作，避免堆叠两条栏。

以上是本次设计建议，不是现有实现。桌面端继续使用现有侧栏及适合宽屏的信息布局；两端共享视觉变量、组件状态和业务数据。

## 2. 现状检查与问题依据

本次检查了路由中的 12 个页面及公共组件代码，实看了 390×844 的阅境轩书架、任务列表／详情／日历、时光机及写小记面板，并补查了 320px 日历布局。浏览器窄视口不等同于真机：本轮没有测量 iOS／Android 的触摸延迟、软键盘、帧率和峰值内存，以下将实测尺寸、代码事实与待验证风险分开说明。

| 发现 | 依据 | 用户影响及设计响应 |
| --- | --- | --- |
| 全局标题与页面标题同时显示 | 390px 阅境轩实测：顶部标题 16px、正文页头标题 18px，各占一行；`App.vue` 与各页 `page-header` | 重复占用纵向空间；统一为一个标题区 |
| 内容开始位置偏低 | 390px 任务日历外框从约 y=270px 开始；任务页还展示两行类型／状态筛选 | 首屏很大部分用于控制区；将筛选收为摘要入口，减少常驻行 |
| 同类动效参数分散 | `styles/motion.css` 的 `--motion-*` 与 `App.vue` 的 `--duration-*` 并存，各页另有局部时长 | 同类操作节奏不同；建立唯一语义化动效表 |
| 手势释放主要由 CSS 过渡接管 | `MotionDrawer.vue`、`MotionModal.vue` 计算了手势速度，但回位／离场仍走固定 transition | 存在释放速度断裂、途中重新抓取不连续的风险；统一运动驱动器，真机验证 |
| 折叠会改变文档布局 | `App.vue` 同时过渡 max-height、margin、padding；`stores/app.ts` 含 800ms 展开保护和滚动基线补偿 | 逻辑复杂，容易与滚动位置互相影响；移除滚动驱动的工具栏高度变化 |
| 弹层体系未完全统一 | Tasks 和 Timeline 复用 MotionModal；书籍表单／路径选择仍用 Element Plus，历史路径和媒体预览还有独立实现 | 关闭位置、底部留白、背景模糊、内容滚动不一致；公共层负责行为和材质 |
| 日历小屏可读性不足 | 公历 17px、农历 8px；390px 日期格约 45px，320px 约 35px；手机隐藏“今天”按钮 | 容易误触且难看清农历；精简外围留白、扩大日期区、恢复今天入口 |
| 子任务详情缺少明确关闭按钮 | 当前 `child-task-dialog` 标题区只有编辑入口 | 需要猜测下滑或点击背景；统一返回／关闭入口 |
| 全局手势可能与局部手势竞争 | `App.vue` 在 app-shell 监听侧栏手势，手机样式为 `touch-action: pan-y` | PDF／图表平移、表格横滑、浏览器边缘返回需要重新划分所有权 |
| 次要模块仍有局部硬编码颜色与小字 | CodeRepo 的品牌紫、Inspiration 的编号／提示色；多个页面 11–13px 内容字 | 护眼／深色主题容易出现例外；统一语义色与文字等级 |

已有的安全区变量、44px 控件基线、阅读滚动边界处理、PDF 渲染窗口、减少动态效果样式、任务手机列表／详情分层均作为基础保留和增强，不重复推翻已完成的修复。

## 3. 全局信息架构与导航

### 3.1 页面骨架

根页面只有三层：顶部身份与必要操作、主要内容、底部导航。搜索、视图切换属于内容上方的轻控制区，不再把它们包在多层玻璃卡片里。

```text
根页面                         任务详情                       阅读页面
┌────────────────────┐        ┌────────────────────┐        ┌────────────────────┐
│       任务中枢      │        │ ‹ 任务列表      编辑│        │ [书架｜阅读]        │
│ [任务｜日历] [筛选]│        │ 任务名称           │        │                    │
│ 搜索任务           │        │ 状态 · 重要性      │        │    文档正文        │
│ 全部  逾期 今日受阻│        │ 日期／描述／进度   │        │                    │
│                    │        │ [拆解｜进展]       │        │ 表格／代码局部横滑 │
│ 分组任务列表       │        │                    │        │                    │
│                    │        │ 子任务或进展列表   │        │                    │
│                    │        │                    │        │                    │
│ 阅境轩 时光机 任务 全部│     │ 添加子任务  记录进展│       │ 文件 目录 文档 全屏 更多│
└────────────────────┘        └────────────────────┘        └────────────────────┘
固定主导航                    情境操作替换主导航             操作栏可自动隐藏
```

示意图表达层级，不代表最终像素比例。根页创建入口随业务控制区放置；任务详情的主要操作下移并固定在内容层底部，根页不额外叠一条创建栏。

### 3.2 底部导航

- 四项使用同一套线性图标和文字标签，触控区均分，实际高度约 56–60px，另加底部安全区。
- 当前项以柔和填色胶囊和强调色标识；切换时指示块连续移动，图标不做夸张跳跃。
- 点击「全部」从屏幕底部升起功能抽屉，按日常、知识、管理分组展示功能按钮；抽屉不改变当前页面位置。
- 从抽屉进入的模块仍保留根级导航；再次点击「全部」或下滑／点击遮罩可关闭抽屉。
- 根页导航保持可见，避免用户需要滑动才能寻找模块入口。
- 同级导航保留各页筛选和位置；不通过把所有页面常驻 DOM 来实现。阅读位置和表单草稿保存为轻量状态，重型渲染按需恢复。

### 3.3 页头、返回与滚动

- 页头默认 52px 加顶部安全区，标题居中 19px／700，左右各预留一致的操作宽度。
- 根页右侧最多一个主入口；复杂命令放入明确命名的菜单。详情页左侧返回、右侧编辑。关闭临时预览统一放在右上角；同时需要返回与编辑的子任务面板用左侧返回退出层级。
- 同一个场景只提供一个可见标题。超长详情标题放在正文，可换行；页头显示短上下文。
- 普通页面采用单一纵向主滚动；时光机沿用页面自然滚动。阅读器由文档容器负责滚动；PDF 生效时只让 PDF 容器拥有纵向滚动。
- 搜索／筛选随内容自然滚出；必要时在紧凑页头提供原位置的搜索／筛选入口。时光机不重新启用拉手式折叠。
- 固定栏覆盖内容的部分，底部留出准确的栏高与安全区；不叠加多份补偿 padding。
- 返回恢复来源、筛选、选中日期和滚动锚点。浏览器返回先退出当前详情／临时层；有草稿时遵循统一保留规则，不用重复 history 条目困住用户。

## 4. 统一视觉规范

### 4.1 主题与材质

沿用项目现有主题值：浅色强调色 `#6366f1`，深色 `#7c7cff`，护眼 `#2e7d4a`。所有按钮、开关、勾选框、日期、进度和选中态消费语义变量，业务组件不再自行写一套紫／绿。

| 表面 | 外观与用途 | 性能约束 |
| --- | --- | --- |
| 页面底色 | 延续浅灰、深色、护眼底色与低强度环境渐变 | 手机背景不持续漂移 |
| 内容表面 | 高不透明度、低阴影；正文、任务、记录以清晰优先 | 长列表卡片不逐张使用 backdrop-filter |
| 浮动功能层 | 导航、操作栏、小菜单使用同一轻磨砂材质、细亮边 | 建议静态 blur 12–18px，实测调整，不逐帧改变模糊半径 |
| 模态面板 | 更厚的近实色表面；一层遮罩聚焦当前任务 | 多级面板不叠加全屏模糊，使用不透明度表达层级 |

液态玻璃感主要由透光边缘、有限背景透色和表面运动共同表达，不添加局部大光斑、循环扫光或跟随滚动的滤镜动画。深色／护眼主题分别校验文字对比，不简单对白色表面降低透明度。

### 4.2 尺寸与排版

| 项目 | 建议规范 |
| --- | --- |
| 页面左右留白 | 常规手机 16px；≤360px 12px；日历小屏允许局部满宽 |
| 间距阶梯 | 4 / 8 / 12 / 16 / 24 / 32px，以 rem 实现文字相关空间 |
| 圆角 | 输入／按钮 12px，内容块 18–20px，底部面板 24px，胶囊自适应 |
| 图标 | 常规 20px，主导航 22px；同一套线性图标；触控区至少 44×44px |
| 按钮与表单行 | 常规 44–48px，主提交按钮 48px；文字放大后可增高 |
| 页面标题／详情标题 | 18px／600；详情正文标题 22–24px／650 |
| 正文／输入 | 常规 16px；长文阅读默认 17px，行高约 1.75–1.85，可调整 |
| 卡片标题 | 16–17px／600，允许两行 |
| 次要信息 | 13–14px；独立短标签最低 12px；农历例外 10–11px |
| 段落与长文本 | 正文正常换行；路径、长链接允许断行；代码、表格保留局部横向滚动 |

输入聚焦时通过与圆角贴合的细边、背景变化表达状态，避免矩形外框。键盘 `focus-visible` 保留清晰焦点。统一 input、select、checkbox、radio、switch、slider、date-picker 的默认／按下／聚焦／错误／禁用状态。

## 5. 动效与手势系统

### 5.1 统一运动语法

按下即出现视觉反馈，业务动作在有效松手时触发；手指滑走可以取消点击。手势驱动的位移从当前画面位置开始，携带释放速度，允许反向操作。普通透明度／颜色变化可用 CSS；抽屉、底部面板、交互式切换使用共享的可中断弹簧驱动。

这是对 [Apple Motion 指南](https://developer.apple.com/design/human-interface-guidelines/motion) 中“运动表达反馈并符合手势预期”的产品化应用。以下数值是项目拟定的调校起点，不是引用的苹果固定参数或已达成的性能结果。

| 场景 | 拟定表现 | 参数起点 |
| --- | --- | --- |
| 按钮按下／松开 | 小按钮缩到 0.97；大卡片最多 0.99；正文不整体缩放 | 按下 80–100ms，松开约 160–220ms |
| 同级模块切换 | 内容 4–8px 轻移与淡变，导航位置稳定 | 180–240ms，不串行等待旧页退完 |
| 列表进入详情／返回 | 沿进入方向推进，返回逆向还原；来源行保留 | 弹簧 response 0.30–0.36s，damping≈1 |
| 底部面板 | 从底部进入；拖动跟手，松手吸附或关闭 | response 0.32–0.40s，默认 damping≈1；有甩动时可降至约 0.85–0.9 |
| 分段切换 | 选中胶囊连续滑移；内容轻淡变，保留容器锚点 | 指示块约 180–220ms，内容约 140–180ms |
| 任务树展开 | 箭头旋转、子项局部展开；连续点击可反转 | 180–220ms；只更新局部分支，不全树做高度动画 |
| 日历切月 | 日历区域跟手横移，释放后完成或回位 | response 0.28–0.34s；日程数据独立更新 |
| 新增／移除条目 | 新条目进入自己的位置；移除后相邻条目补位 | 160–220ms；只对当前可见条目执行 |
| 保存／完成反馈 | 按钮原位忙碌，成功后更新记录与状态 | 状态立即反馈；结果动画 180–260ms |
| 阅读栏出现／隐藏 | 8–12px 底部轻移与透明度变化 | 出现 160–200ms，隐藏 180–220ms |
| 图片／图表预览 | 从来源位置轻展开，关闭回到来源 | 220–280ms；来源不可见则短淡变 |

Spring response 是响应参数，不等于固定动画总时长。实现阶段先在现有 Vue 架构内验证一个共享驱动器；若引入依赖，先核实包体积、取消与速度续接能力，不在每个页面手写物理循环。

### 5.2 “丰富”出现在哪里

- 新条目、进度变化、勾选状态、分段指示器、展开箭头、菜单来源、面板吸附都有反馈。
- 首次呈现可对首屏 4–6 个轻量条目使用约 20ms 的错峰，总额外等待不超过 100ms。
- 反复滚回同一条内容不重播进场动画；分页只让新内容出现，刷新不把整个列表闪空。
- 加载状态按真实阶段展示；不为展示动画制造等待，不播放假百分比。
- 重型 Markdown／PDF 不跟随整个视图大幅缩放，不同时保留多份完整渲染树来做转场。

### 5.3 手势所有权

| 用户操作 | 所属范围 | 防冲突规则 |
| --- | --- | --- |
| 纵向滚动 | 当前页面或文档的唯一主滚动容器 | 使用浏览器原生滚动，不用 JS 模拟整页惯性 |
| 横向滑动切月 | 日历网格内部 | 移动约 8–12px 且横向意图明确后接管；纵向交还页面 |
| 底部面板下拉 | 拉手／标题区 | 正文区域以滚动和文本选择优先，不全表面抢拖动 |
| 表格／代码横滑 | 对应内容块 | 不触发换页、侧栏或返回；保留纵向滚动能力 |
| PDF／图表缩放平移 | 查看器内部 | 缩放后单指平移；多指状态禁止触发面板关闭／换图 |
| 系统边缘返回 | 浏览器／操作系统 | 默认不自定义全屏边缘导航手势；显式返回按钮始终可用 |

不把滑动、长按或双击作为唯一操作路径。首版不为任务加入“滑一下立刻完成”：短期待办仍须填写或确认关闭说明。图表与图片的单击操作不因全局双击识别而延迟。

### 5.4 减少动态效果与可访问性

- 减少动态效果：取消位移、缩放、视差、弹跳，保留 100–160ms 淡变和颜色／状态反馈。
- 减少透明度：使用近实色功能层；浏览器不支持相关媒体查询时仍有清晰的默认背景。
- 高对比度：加深正文与边界，状态同时用文字／图标表达。
- 字号放大至 200% 时重排，按钮可增高，日历必要时提供同等信息的议程优先模式。
- 隐藏的导航／工具栏同步退出焦点与命中范围。媒体查看器提供明确关闭按钮，弹层管理焦点进入／返回。
- 不依赖震动或声音；平台支持时可后续评估轻反馈，默认视觉就能完整表达状态。

## 6. 弹层、表单与软键盘

### 6.1 三类面板，一套行为

| 类型 | 场景 | 手机呈现 |
| --- | --- | --- |
| 字段菜单 | 状态、重要程度、类别、日期 | 贴字段展开，宽度随字段／内容合理扩展，受可视区边界约束 |
| 底部面板 | 文件／目录、命令菜单、简短确认、子任务详情 | 短内容按需高；长内容可到约 88% 可视高度；标题与操作区稳定 |
| 大编辑面板／全屏预览 | 长小记、任务编辑、复杂路径选择；图片、Mermaid | 编辑接近全屏，预览使用完整可用空间，保留明确返回／关闭 |

字段选择不统一粗暴改成底部选择器：继续满足“贴输入栏展开”。下方空间不足时贴字段向上，左右碰撞时在可视区内对齐；仍不足则在字段下方内联展开并滚动到可见位置。避免沿用页面局部强制 `left: 8px` 的全局覆盖。

日期范围在手机展示单月面板，在同一面板内明确当前选择“开始／结束”，保留日期标签、清除与今天入口；选中与今日语义同任务日历一致。菜单需跟随面板滚动／键盘变化重新定位，并纳入当前弹层的焦点范围。

### 6.2 多级弹层

- 一个可操作前景面板、一层遮罩；子任务详情打开编辑时，以同一面板容器切到编辑步骤，保留前一页状态。
- 子任务继续下钻只替换面板内容并保留路径栈，不每深入一级增加一块玻璃。
- 左侧返回到上一层；顶级临时面板用右侧关闭。若右侧已有编辑，左侧使用明确的“返回任务”入口。
- 外部点击、下拉、返回按钮、浏览器返回、Escape 走同一个关闭请求；嵌套日期菜单先关闭最上层。
- 锁住实际背景滚动容器，避免仅锁 body 仍可拖动 app-main。释放滚动锁时恢复原位置。

### 6.3 草稿和提交

- 编辑内容输入后先进入会话草稿；下拉收起保存草稿，重新打开恢复。成功提交才清空；显式“放弃草稿”才丢弃。
- 草稿按操作类型和目标实体隔离，避免把子任务 A 的内容带到 B。首版会话内保留，不宣称刷新后可恢复，也不保存凭证到通用草稿。
- 保存中仅锁本次提交相关控件，显示真实忙碌状态。失败原位保留内容、展示可重试错误；不能只播成功动画。
- 归档与关闭保留现有确认语义。撤销只用于已经具备恢复能力的操作；暂不以设计文案承诺所有操作都可撤销。

### 6.4 键盘与可视高度

键盘可能缩小 visual viewport 而布局 viewport 不变，因此仅使用 `100vh` 或固定底部定位不足以覆盖手机表单场景。参见 [MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)。

- 以可视区域高度、偏移和安全区定位编辑面板；`dvh` 为基础，VisualViewport 作为增强，能力缺失时回退到自然可滚动布局。
- 键盘出现时主导航隐藏，编辑面板可增高；提交栏跟随键盘上沿，不能遮住当前输入行。
- 标题输入 16px 起；日期／数字使用适合的输入模式。中文输入法组字期间不发起中间搜索，不误提交 Enter。
- 只把焦点字段滚动到可见范围，不强制把整个页面拉回顶部；键盘收起后恢复原锚点。
- 横屏或低高度可视区优先全高编辑页，减少非必要说明和装饰间距，内容仍完整可达。

## 7. 各页面的设计

### 7.1 阅境轩：书架 → 选择 → 阅读

**书架**：顶部保留“书架／阅读”切换；搜索框与唯一的添加按钮同处一行，类别为可横滑但不挤压内容的轻标签。常规手机两列，≤360px 或大字模式降为单列；长书名两行，进度位置固定，卡片菜单使用常显的 44px 命中入口。书封可保留现有色彩，去掉重复外框和过强投影。

**打开内容**：优先最近阅读、历史路径与已登记书籍。路径输入清晰说明指向“运行 ObsidianBrain 的电脑上的文件”，不能暗示可直接访问手机本地路径。首次打开文件夹没有活动文档时，正文给出“选择文章”，底部文件入口保持可见。

**阅读页面**：正文在手机取消桌面面板式双重内边距。非全屏时继续显示顶部“书架／阅读”切换与阅读控制，确保随时可返回；只有进入全屏／沉浸阅读后才隐藏顶部工具栏。底部工具栏采用对称的“两侧各两个大图标 + 居中文档名”：左侧固定为文件、全屏；Markdown 右侧为目录、当前目录搜索，PDF 右侧为缩小、放大。搜索覆盖已打开目录下的 Markdown 与 PDF，并支持按文件名或相对路径匹配。图标按钮填满栏内高度，文档名下显示 PDF 页码且点击可恢复适宽。

**阅读栏状态**：

| 状态 | 栏行为 |
| --- | --- |
| 无文件夹、无文档 | 正文空态显示打开入口；保留返回书架 |
| 已打开文件夹、未选中文档 | 文件入口常驻，不启动隐藏计时 |
| 正在阅读 | 任意实际文档滚动立即显示；最后一次滚动／操作结束约 3 秒后隐藏 |
| 菜单打开、控件有焦点、正在拖动、发生错误 | 暂停隐藏，处理完成后重新计时 |
| 静止且需要工具 | 点击正文非链接／非选择区域可唤出；可访问的工具入口与退出入口保留 |
| 沉浸状态 | 沿用同一底栏；安全区内保留最小退出入口，不新增左右悬浮按钮 |

计时期间继续滚动会续期；目录跳转、恢复阅读位置不让页头反复折叠。不用定时器改变文档高度。工具栏的隐藏不改变可阅读末尾空间，滚到底后不产生永久空白。

**内容适配**：

- Markdown 正文默认 17px；文档长标题换行、代码与宽表格局部横滑，靠边渐隐提示还有内容。
- 表格默认保持列关系，不强制把所有列缩到无法阅读；较大表格提供“展开查看”入口。数学公式和长链接同样检查横向溢出。
- 图片约束到内容宽，点击放大；图表预览共用媒体容器，顶部关闭始终可见，底部提示为“拖动查看 · 双指缩放”。
- 选择正文、点击链接、复制代码时不触发工具栏之外的导航手势；内容实际可达而不是简单用 overflow hidden 掩盖问题。

**PDF 的清晰与连续**：

- 保留按可视窗口加载及手机单并发渲染策略，优先当前页清晰度，避免靠降低整份 PDF 的分辨率来换动画速度。
- 放大过程中短暂使用当前页图像跟手，停稳后重渲染对应倍率；新图完成前保留旧图，防止白闪。预览缩放与清晰渲染具有明确的短暂状态。
- 切换倍率保持手指／阅读中心对应的文档位置；适宽后恢复原生纵向滚动。
- 超大页按像素预算处理，必要时采用可视区域精细渲染；实施前专项验证画质／内存取舍，不承诺所有极端页面都能满 DPR 全页保留。
- 离开文档取消过期渲染、回收离屏 canvas；切回书架可保留页码与尺寸元数据，无需让整份 PDF 一直绘制。

### 7.2 时光机：浏览轻、记录快

- 首屏使用加粗大标题；搜索框、“＋”写小记按钮与最右侧“三点”时间范围入口同处一行。“三点”通过辅助标签提示当前为“全部时间／最近 7 天”等范围，展开后才呈现预设与起止日期。
- 小记使用自然页面滚动，日期分组为轻标题；回到页面恢复浏览位置。原桌面时间轴与独立内容滚动继续只服务桌面。
- 卡片正文 16px、时间左上 12–13px、标签在正文后；单图保留合理长宽比，多图稳定排布，提前预留尺寸减少跳动。
- 浏览到深处仍通过搜索行旁的“＋”入口打开编辑；不在页头或下方重复放置创建按钮。
- 编辑面板先显示正文，标签与图片作为辅助工具；软键盘上方保留发布按钮，图片删除命中区扩大，上传失败可单独重试。
- 同步作为次要菜单项，有明确忙碌与结果反馈；分页加载不替换现有内容。
- 新小记保存后：若位于顶部则插入并轻微强调；若正在回看历史，显示“已发布，查看”提示，由用户决定跳转，不强制滚回最新。

### 7.3 任务中枢：列表做判断，详情做推进

**列表**：

- 单页头只显示“任务中枢”；新建入口保留在“我的任务”列表栏内，避免页头重复按钮。下面为“任务／日历 + 筛选”，再是一行搜索。
- 快捷筛选保留全部／逾期／今日／受阻；类型与状态收为带当前条件摘要的筛选入口，展开区域内各选择框仍贴字段。
- 列表保留标题、类型、状态、重要性、截止提醒与必要进度；不显示描述、不新增统计大卡片。
- 标题 16–17px，关键日期 13px，辅助标签 12px 起；同类字段对齐，避免百分比和日期随标题长度漂移。
- 一个任务只进入一个紧迫程度分组，沿用现有业务规则；筛选计数需说明数据范围，不把已加载数量冒充全库数量。

**详情**：

- 单独内容层，顶部“返回任务列表 + 编辑”，标题／属性／日期／描述完整展示；修改属性仍统一到编辑入口。
- 下面为“任务拆解／进展记录”分段切换，两块内容共享全宽；各自记住浏览位置，切换不从头展开整棵树。
- 底部长期任务为“添加子任务 / 记录进展”，短期待办为“完成待办”；归档、状态和其他修改仍在编辑流程内明确呈现。
- 子任务默认看直属层级，缩进有上限；深层节点通过路径与下钻面板呈现，移动端不依赖拖拽重排，保留编辑中的移动入口。
- 点子任务打开近全高底部详情面板，显示上级、标题、属性、直属子项、该节点进展；顶部提供编辑与关闭，只有继续下钻到更深层级时才显示“返回上一级”，不再放置冗余的“返回任务”按钮。
- 时间统一在每条进展右上角。类型、所属任务、内容分层；长备注显示合理摘要，点击看全文，不能靠极小字塞满。
- 保存子任务进展后回到该子任务记录位置；保存根任务进展后切到根任务进展区并显示新条目。关闭后不意外跳回第一条任务。

**日历**：

- 单月六行固定网格，不因任务多少改变日期位置；去掉硬划线与多余内框。
- 公历 20–22px，农历 10–11px，在同一圆形容器上下排列。今日填主题色圆形，非今日无圆形填色；选中的日期格使用淡主题色圆角方块，选中今日时两种语义同时成立。
- 少量任务用轻指示点，超过阈值显示数量；网格仅计算顶层任务，下方明细默认顶层，点展开才显示子任务。
- 明细顶部固定表达“某月某日 · N 项”，提供“添加”，预填所选日期；从任务返回日历恢复月份、日期与展开状态。
- 恢复“今天”按钮；上一月／下一月与局部滑动切月同时可用，点击日期只选择，不让手机依赖双击新建。
- 390px 下日期触控格至少约 46–48px；320px 下日历局部近满宽、每边约 4px、取消格间隙，保持每列约 44px。外观圆角留在格内，不通过缩字维持嵌套卡片。

### 7.4 其他页面同步覆盖

这些页面复用同一导航、页头、字体、输入、菜单、面板和状态反馈，避免核心三页优化后其他页面仍像另一套产品。

| 页面 | 信息排布与手机操作调整 |
| --- | --- |
| 控制面板／首页 | 状态摘要在前，配置按 Obsidian、模型等分组；点击组进入全宽编辑，标签置顶；保存／验证动作明确。凭证继续掩码，不进入通用草稿机制 |
| 知识库 | 多列洞察改为单列分组，重点数量在标题行；长笔记路径按名称＋次要路径展示，可展开；外部 Obsidian 跳转标识清楚 |
| Wiki 工作台 | 摄入／问答／检查／配置按清晰分段进入；单列字段，日志折叠摘要，结果优先阅读；高级 Schema 使用独立全屏编辑层 |
| Wiki 看板 | 指标按重要性两列或单列重排，健康度和下一步先展示；复杂分布配文字列表，提供前往工作台的明确入口 |
| 知识探索 | 缺口、研究问题、概念碰撞分段展示；一次聚焦一种结果，生成按钮有当前模块名称，长结果可完整阅读 |
| 外部摄入 | 单列文章流，标题／来源／摘要／状态层级一致；批量操作进入明确选择模式后显示底部批量栏 |
| 代码仓 | 单列卡片，详情全宽，提交记录允许自然换行；“在电脑 VS Code 打开”明确环境，手机优先查看详情／复制路径，不能默认本机能打开电脑工作区 |
| 灵感熔炉 | 模式切换使用统一分段组件；输入到结果线性排布；生成中显示真实状态，失败可重试；结果和历史保留位置 |
| 智识雷达 | 单列文章，来源／日期清晰；收藏与忽略是文字可理解的动作，长标签有展开入口；移除反馈沿用现有可撤销能力 |

涉及 Obsidian／VS Code 的外部跳转保留现有业务能力，增加移动端环境说明与失败回退。本方案不新增手机本地文件服务、后台任务、提醒或同步能力。

## 8. 统一组件与迁移方案

以下是拟定职责，名称可在实施时按现有目录调整：

| 组件／模块 | 统一负责 |
| --- | --- |
| MobileScaffold / MobileHeader | 安全区、单页头、内容宽度、根页与详情模式 |
| MobileDock | 根导航／情境操作／键盘隐藏三种模式，统一底部占位 |
| AdaptivePanel | 基于现有 MotionModal／MotionDrawer 收敛：材质、拖动、关闭、内容与底部操作布局 |
| FieldPopover / DateField | 锚定、边界避让、日期主题、焦点关联、键盘后重定位 |
| SegmentedControl / SearchField | 阅境轩、任务、时光机及次要页面统一控制样式 |
| MediaViewerShell | 图片、Mermaid 的安全区、关闭、缩放、移动端提示 |
| motion tokens / motion driver | 语义化时长、弹簧状态、手势采样、释放速度、减少动态效果 |
| overlay / viewport / navigation state | 顶层弹层、背景滚动锁、焦点、草稿、键盘、返回与位置恢复 |

实施约束：

1. 先收敛 tokens 和公共行为，再迁移页面；不继续向 App.vue 追加针对页面类名的全局覆盖。
2. 公共容器决定面板外框，业务页仅负责内容；清除各页作用到所有 `.el-dialog`／`.glass-picker` 的无范围样式。
3. CSS 响应式布局和触控能力分别判断。小窗口桌面不等于触屏；大屏触摸设备也要有完整非 hover 操作。
4. 所有手势监听可取消，离场清理 rAF／计时器／观察器／渲染任务；`will-change` 仅在需要运动时启用。
5. 优先 transform／opacity；树展开等必须改变布局的场景限制到小区域。不得在滚动回调里交错大量 DOM 读写。
6. 设计状态与业务请求状态分离；返回、快速切换、重复开关时忽略过期响应，避免旧请求重新打开已退出的详情。
7. 不为手机导航对全部路由统一 KeepAlive，重型内容按需释放，保留必要业务位置即可。

## 9. 性能与验收

### 9.1 目标预算

以下为实施后的验收目标，需要建立同文档、同设备、同操作基线，不是本轮测量结果。

- 触摸按下尽量下一帧反馈，常规操作可见反馈目标 <100ms；网络与 PDF 解码耗时单独记录。
- 在选定 60Hz 真机上，常见导航、面板、日历和工具栏动画以稳定 60fps 为目标；连续手势期间不出现 >50ms 的应用主线程长任务。
- CSS 动效不绑定全文 Markdown／多页 PDF 的每帧布局；不引入持续耗电的背景动画。
- 相同阅读任务下，新增动效不能导致内存明显高于基线。连续切换 20 次后检查 retained objects、canvas 和监听器数量，确认没有随次数持续增长。
- PDF 清晰度与内存分别验收：保持当前页文字可读；离屏渲染释放；低端设备先减少预渲染、取消大面积模糊，再考虑极端页渲染策略。

### 9.2 测试矩阵

| 维度 | 覆盖 |
| --- | --- |
| 尺寸 | 320、360、390／393、430px；手机横屏；768px 邻界；1024px 触屏；桌面 1280／1440px |
| 浏览器 | iOS Safari 真机、Android Chrome 真机；浏览器工具用于尺寸与结构自动化，不能替代真机手势／键盘 |
| 外观 | 浅色、深色、护眼；减少动态效果、减少透明度／回退、高对比、大字 |
| 数据 | 空内容、长标题、长路径、长表格、代码、公式、多图、复杂 Mermaid、大 PDF、多级任务与大量记录 |
| 异常 | 网络慢／断开、接口报错、保存冲突、连续点击、快速返回、窗口旋转、键盘反复开合 |

### 9.3 必须通过的用户流程

1. 第一次打开文件夹，无需先滚动即可选文章；阅读静止后底栏隐藏，滚动可唤出，目录打开时不消失。
2. 文档滚到最后继续滑动，不出现无法恢复的底部空白；长表格最后一列、代码最后一个字符均可访问。
3. PDF 放大后文字最终清晰；图表关闭可见，双指缩放不误触关闭或模块导航。
4. 时光机保留整页浏览；深处写小记、上传图片、取消恢复草稿、失败重试均不丢失内容。
5. 任务列表进入详情、子任务、编辑／进展后逐层返回，来源任务与位置正确；顶层只有一个编辑入口。
6. 日历 320px 不重叠；今日圆含公历与农历，选中态清楚；返回今天、切月、展开子任务明细均可直接操作。
7. 任意表单在软键盘出现后仍能看到当前字段与提交入口；字段菜单不出屏、不被弹层裁切。
8. 快速打开／关闭面板或反向拖动时无跳点、无输入锁死；连续切换页面不会误触隐藏控件。
9. 手机显示一个主标题和一条底部导航／操作层；桌面布局与已确认的任务双列、时光机滚动方式保持正确。
10. VoiceOver／TalkBack 可读出控件名称和状态，浏览器返回与显式返回可用；系统缩放与文本选择不被全局手势禁用。

## 10. 实施顺序与交付边界

| 阶段 | 工作内容 | 可评审结果 |
| --- | --- | --- |
| 第一批：基础统一 | tokens、单页头、底部导航、滚动容器、面板与键盘、控件状态 | 三个核心页的导航／输入／弹层可以连续操作，三主题一致；先用交互样板调好手感 |
| 第二批：核心流程 | 阅境轩阅读栏与内容、任务列表／详情／日历、时光机浏览／写入 | 从打开内容到完成操作的完整手机流程；所有既有偏好回归通过 |
| 第三批：其余页面 | 控制面板、Wiki、知识库、探索、摄入、代码仓、灵感、雷达 | 全系统页头、排版、字段、返回、加载与错误反馈一致 |
| 第四批：细节与性能 | 手势速度续接、列表局部动效、PDF专项、低端降级、无障碍与桌面回归 | 真机测试记录、资源对比、关键流程自动化与构建验证 |

功能上不修改任务和小记的数据存储模型，不扩展后端能力。本轮交付为设计文档；实施时按组件与页面分批形成可体验版本，再根据真机表现微调弹簧和材质参数。
