# LRU 与 CLOCK 淘汰

精确 LRU 每次命中都更新顺序。在本书的四线程实现中，命中更新需要持有共享锁。它更精确地保留近期使用的项，但写锁竞争可能影响低延迟服务。

CLOCK 在访问时置引用位，淘汰扫描时先清除引用位再检查下一项。命中路径不维护完整顺序，淘汰行为是近似的。扫描最坏开销可能增加，不能因此宣称所有负载下尾延迟更低。

两者都可能在顺序扫描或复用距离超过容量时表现差。v1.1 的淘汰策略实现未随默认 TTL 变更而改变。

本文的建议条件是：重复热点、锁竞争明显时优先验证 CLOCK；若精确近期性对业务更重要且锁竞争低，可验证 LRU。建议不是所有工作负载的绝对结论。
