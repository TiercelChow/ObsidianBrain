# 时光机 — 需求设计

> REQ-04 · v3.0 · 2026-10-04 · 已实施
> 上游：[顶层设计](../top_design.md) · 对应：[开发设计](../development/04-timeline.md)

## 1. 产品边界

时光机用于记录碎片想法、图片与标签，并按日期和关键词回看。系统独立运行，不依赖 Obsidian、Vault 或 Local REST API 插件，不再同步或回写月份 Markdown。

- SQLite 是小记和附件元数据的唯一事实来源。
- 原图是用户数据，保存到数据库同级 `timeline/images/`。
- 缩略图是可重建缓存，位于 `timeline/cache/`，容量淘汰不能删除原图。
- 已有小记的 ID、时间、内容、标签和图片引用保留。只复制旧图片，不删旧库文件、不用旧 Markdown 覆盖数据库。
- 书架、Book Wiki、任务、代码仓的存储不变；旧搜索/连接/同步工具退役，历史 SQLite 迁移保留。

## 2. 小记生命周期

### 新增与浏览

正文或图片至少有一项。支持常用 Markdown、标签、图片选择和剪贴板粘贴。最多 9 张图片，每张最多 20 MiB；接受实际可解码的 PNG、JPEG、GIF、WebP，不能只信任后缀或 MIME，需限制解码尺寸和内存。

页面每批加载 20 条，按时间倒序，使用持久化的本地日期分组，避免 UTC 跨天错位。支持今天、7 天、30 天、本月、上月和自定义范围；正文和标签搜索可与日期组合，翻页不能重复第一页。

### 编辑

可以修改正文、标签和附件，保留 ID 与原记录时间。复用新增编辑器，已有附件不重复上传；失败保留草稿，保存期间阻止重复提交和误关闭。

编辑携带当前 revision；其他设备已修改同一记录时报告冲突，不覆盖较新的内容。

### 删除与移除图片

删除前确认，明确不可恢复和图片清理规则。失败不提前移除卡片。删除同样校验 revision。

事务先完成小记修改/删除和清理队列写入；没有其他小记引用才删除系统内原图与缓存。图片数组和正文嵌入都要保护，共享图片直到最后引用消失才清理。

磁盘清理失败保留持久化队列，显示待清理数量，启动和每 5 分钟重试。取消编辑释放本次新增的未发布图片；异常中断留下的未引用暂存图片 24 小时后回收。

## 3. 有界缓存

- 默认 256 MiB，时光机「图片存储」可配置 0–4096 MiB；首页只展示状态，不再提供系统配置卡片。
- 按文件字节数而非张数限制；命中更新 LRU 次序，超限淘汰最久未使用的缩略图。
- 单张超过预算则不缓存，0 表示禁用缓存。
- 缩小容量立即淘汰，清空缓存不影响原图。
- 缓存不可写仍能生成并显示图片，不损坏原图。
- HTTP 图片响应不形成另一份长期浏览器磁盘缓存，不使用无限常驻图片内存缓存。

## 4. 旧图片迁移

启动时保留旧目录作为手动导入的默认值，并退休旧连接设置；不自动扫描、复制或尝试访问旧库。图片只在用户通过页面或一次性 CLI 明确触发时搬运。页面可重新选择含 Timeline/ 的旧库根目录、手动重试缺图。

迁移发现 JSON 图片数组及正文嵌入。安全相对路径 canonicalize 后必须在所选目录内；拒绝路径穿越。只复制，不覆盖本地原图，不重建或覆盖小记。缺失、过大、格式不支持均报告，记录仍保留。

可重复运行。复制与删除并发时，刚复制但已无引用的原图也要清理。旧库永远不是 GC 目标。

## 5. 交互

桌面卡片右上角编辑/删除；手机更多按钮打开底部操作抽屉。编辑、删除确认复用系统 MotionModal，保持现有材料和减少动态效果设置。

大图查看支持关闭、前后切换、缩放、重置；加载/失败/重试状态明确，旧图缺失提示重新迁移，不仅显示空白。

图片存储面板显示实际目录、原图大小、缓存用量/容量、缺失和待清理数量，提供容量设置、清缓存及旧图复制。

## 6. 备份边界与验收

SQLite 一致快照不包含照片，数据库恢复不能找回已物理删除原图。完整备份需要一致数据库快照与同级 timeline/images/，备份时暂停写入；缓存可重建。迁移前自动数据库备份，旧库保留至确认迁移完成。

验收使用独立临时数据：无 Obsidian 服务也可上传→创建→浏览→编辑→删除；版本冲突不覆盖；共享图片及正文引用不误删；最后引用删除后原图和缓存清净；失败队列跨重启重试；LRU 热访问、超额、0 容量和降容量有效；迁移只复制、可重试、拒绝越界；桌面与手机均可操作。
