## 1. 模块概述

### 1.1 定位

个人任务管理模块用于管理两种不同时间尺度的工作：

- **短期待办 (Short Task)**：快速记录一件近期需要完成的事情，强调低录入成本和明确截止时间。
- **长期任务 (Long Task)**：管理需要持续推进的目标，支持多级子任务拆解和按节点记录进展。

模块提供统一的 **任务视图** 与 **日历视图**。任务数据以 SQLite 为唯一权威存储（`task_documents` 等四张表），模块不再读写任何 Markdown 文件。

### 1.2 核心价值

| 用户痛点 | 解决方式 |
|---|---|
| 临时待办散落，容易遗忘 | 用最少字段快速创建短期待办，统一展示未完成与逾期事项 |
| 长期目标只有标题，缺少可执行路径 | 支持任意层级的子任务拆解，并保留父子关系和顺序 |
| 任务推进过程不可追溯 | 根任务和每个子任务都可追加带时间戳的进展记录 |
| 列表难以反映时间冲突 | 日历视图用日程形式展示任务的开始、结束和跨日跨度 |
| 任务数据分散在多个文件、难以保持一致 | SQLite 单一权威存储，每次写入在单个事务内原子完成 |

### 1.3 设计原则

- **两种心智模型分离**：短期待办保持轻量；长期任务才暴露拆解和进展能力。
- **可追溯而非覆盖历史**：状态、关闭说明、进展都保留时间信息。
- **SQLite 唯一权威**：任务数据只存储在 SQLite `task_*` 表中，不再读写任何 Markdown 文件；SQLite 不可由 Vault 重建，数据库备份属基础设施话题，另行立项。
- **单一身份**：任务、子任务、进展均使用稳定 UUID，不依赖标题定位。
- **日历不是第二份数据**：任务视图与日历视图消费同一任务模型，修改后同步更新。
- **渐进呈现**：默认只显示完成当前操作需要的信息，高级拆解和历史放到详情层。

### 1.4 核心使用场景

1. **快速记一件事**：用户在数秒内创建短期待办，在任务到期前通过列表或日历再次看到它，完成时补充结果说明。
2. **推进长期目标**：用户创建长期任务，逐层拆成可执行子任务，在根节点或任一子节点持续追加进展。
3. **安排今天与本月**：用户从日历查看任务时间重叠、开始和截止情况，并从某一天直接创建任务。
4. **数据可靠**：每次写入在单个 SQLite 事务内原子完成，失败即整体回滚，不产生半写状态；数据库文件本身即可作为备份单元。

## 2. 范围与关键决策

### 2.1 MVP 范围

MVP 包含：

1. 短期待办的创建、编辑、关闭、重新打开、归档、查询。
2. 长期任务的创建、编辑、状态管理、归档。
3. 长期任务多级子任务的新增、编辑、排序、移动、关闭。
4. 长期任务根节点和子任务的进展记录。
5. 任务视图与日历视图。
6. 搜索、状态/类型/重要程度/日期筛选。
7. SQLite 持久化（唯一权威存储）与文档级版本并发控制。
8. LLM Tool API，使对话前端可以创建、查询和推进任务。

### 2.2 MVP 明确不做

- 重复任务、提醒通知、闹钟。
- 任务依赖、关键路径、甘特图、工时统计。
- 团队协作、负责人、评论、权限。
- 与系统日历（Apple Calendar、Google Calendar）双向同步。
- Calendar 中拖拽改期；MVP 通过编辑表单修改日期。
- 附件、富文本协作编辑。

这些能力保留为后续扩展，避免首版把个人任务管理演变为项目管理平台。

### 2.3 日期与时间语义

- MVP 使用 **本地时区的全天日期**，格式为 `YYYY-MM-DD`。
- 所有任务节点都必须有 `start_date` 和 `end_date`。
- 创建时若用户只选择一天，`end_date = start_date`。
- 日期范围为闭区间，任务在 `start_date <= day <= end_date` 的每一天都属于该日历范围。
- `end_date < start_date` 必须拒绝保存。
- `created_at`、`updated_at`、`closed_at`、进展时间使用 RFC 3339 时间戳并以 UTC 存储，展示时转换为本地时间。

### 2.4 文档归属规则

- 每个短期待办在创建时生成独立文档，文档键为 `db:short:{uuid}`，文档种类为 ShortMonth，并记录创建月份 `storage_month`。
- `storage_month` 创建后不可变；修改开始日期不会改变文档归属。
- 每个长期根任务对应一个文档，文档键为 `db:long:{uuid}`。
- 存量数据行保留原有的 `Tasks/...` 路径字符串作为文档主键；该字符串仅为文档主键，无任何文件系统语义，系统不再据此读写文件。
- 短期待办不再合并进月份文件；每个待办独立成文档，避免共享文档带来的并发竞争。

## 3. 领域模型

### 3.1 通用任务节点 (TaskNode)

短期待办、长期根任务和长期子任务共享以下字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | UUID string | 是 | 稳定身份，创建后不可修改 |
| `root_id` | UUID string | 是 | 短期为自身；长期子任务指向根任务 |
| `parent_id` | UUID string / null | 否 | 根节点为空，子任务指向直接父节点 |
| `kind` | `short` / `long` | 是 | 任务类型；长期子任务继承 `long` |
| `role` | `root` / `subtask` | 是 | 节点角色；短期只能为 `root` |
| `title` | string | 是 | 1–200 字符，去除首尾空白 |
| `description` | Markdown string | 否 | 0–10000 字符 |
| `start_date` | date | 是 | 本地全天日期 |
| `end_date` | date | 是 | 不得早于开始日期 |
| `importance` | enum | 是 | `low` / `normal` / `high` / `urgent` |
| `status` | enum | 是 | 见 §3.2 |
| `position` | integer | 是 | 同一父节点下的显示顺序，从 0 开始 |
| `closure_note` | Markdown string / null | 否 | 完成或取消时填写的关闭说明 |
| `closed_at` | timestamp / null | 否 | 进入终态的时间 |
| `created_at` | timestamp | 是 | 创建时间 |
| `updated_at` | timestamp | 是 | 最后修改时间 |
| `revision` | integer | 是 | 节点最近修改时对应的文档 revision；并发校验使用顶层 `document_version` |
| `archived_at` | timestamp / null | 否 | 根任务归档时间；长期子任务随根任务隐藏，不单独归档 |

### 3.2 状态模型

#### 短期待办状态

| 状态 | 中文 | 可进入 | 可离开 |
|---|---|---|---|
| `open` | 待办 | 新建、重新打开 | 完成、取消 |
| `completed` | 已完成 | 从待办关闭 | 重新打开 |
| `cancelled` | 已取消 | 从待办关闭 | 重新打开 |

短期待办关闭时弹出关闭面板，用户选择“完成”或“取消”，并可填写 `closure_note`。关闭说明可为空，但界面必须明确提供输入位置。

#### 长期任务与子任务状态

| 状态 | 中文 | 语义 |
|---|---|---|
| `planned` | 计划中 | 已记录但尚未实际开始 |
| `in_progress` | 进行中 | 正在推进 |
| `blocked` | 受阻 | 暂时无法继续，应配合进展说明原因 |
| `completed` | 已完成 | 工作完成，终态 |
| `cancelled` | 已取消 | 不再继续，终态 |

状态规则：

- 新建长期任务默认为 `planned`。
- 添加第一条进展时，若状态仍为 `planned`，界面提示是否切换为 `in_progress`，但不自动强制修改。
- 根任务进入 `completed` 前，其所有未归档后代必须为 `completed` 或 `cancelled`。
- 若仍有活动后代，用户可取消操作，或显式选择“同时完成剩余子任务”。批量操作必须二次确认。
- 根任务进入 `cancelled` 时可选择是否级联取消活动后代，默认不级联。
- 终态任务允许重新打开；重新打开不删除历史关闭说明，而是把旧关闭事件保留在审计记录中，当前 `closure_note` 清空。

### 3.3 长期任务拆解

- 长期任务可拥有任意业务层级的子任务，服务端安全上限为 20 层。
- 每个子任务拥有与根任务相同的标题、描述、日期、重要程度和状态字段。
- 子任务可添加子任务、添加进展、移动到同一根任务下的其他父节点、调整同级顺序。
- 禁止把节点移动到自身或任一后代下，防止循环。
- 子任务不能跨长期根任务移动；跨任务复用在后续版本通过“复制”实现。
- 子任务日期超出父任务日期时允许保存，但界面显示日程风险提示，不进行静默裁剪。

### 3.4 进展记录 (ProgressEntry)

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | UUID string | 是 | 进展记录 ID |
| `root_id` | UUID string | 是 | 长期根任务 ID |
| `task_id` | UUID string | 是 | 进展所属根任务或子任务 |
| `recorded_at` | timestamp | 是 | 记录时间，默认当前时间 |
| `note` | Markdown string | 是 | 1–10000 字符，描述本次推进、阻塞或结果 |
| `percent_after` | integer / null | 否 | 本次记录后的进度，0–100 |
| `created_at` | timestamp | 是 | 系统创建时间 |

规则：

- 短期待办不支持进展记录，只保留关闭说明。
- 进展为追加式历史；MVP 不修改或删除既有进展，纠错时追加一条说明更正对象的新进展。
- 当节点完成时，展示进度固定为 100%。
- 当节点取消时，不参与父节点的聚合进度。
- 非终态节点若有最新 `percent_after`，使用最新显式值；若无显式值但有子节点，使用未取消直接子节点进度的等权平均；叶子节点默认 0%。
- 长期根任务同时显示“聚合进度”和“已完成叶子数 / 有效叶子数”，避免百分比掩盖真实拆解情况。

### 3.5 审计事件 (AuditEvent)

状态变更、重新打开、归档、恢复归档和批量完成会写入审计事件：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | UUID string | 是 | 审计事件 ID |
| `root_id` | UUID string | 是 | 所属根任务 |
| `task_id` | UUID string | 是 | 被操作的任务节点 |
| `event_type` | enum | 是 | `status_changed` / `reopened` / `archived` / `unarchived` / `cascade_completed` |
| `from_status` | status / null | 否 | 原状态 |
| `to_status` | status / null | 否 | 新状态 |
| `note` | Markdown string / null | 否 | 关闭说明或操作补充 |
| `occurred_at` | timestamp | 是 | 事件发生时间 |

审计事件与任务文档保存在同一 SQLite 事务中，随写入原子落盘。MVP 不提供审计事件编辑或删除。

### 3.6 派生状态

- **逾期**：今天晚于 `end_date` 且状态非终态。
- **今日开始**：`start_date == today`。
- **今日截止**：`end_date == today`。
- **进行区间**：`start_date <= today <= end_date` 且状态非终态。
- **活动任务**：未归档且状态非 `completed` / `cancelled`。

这些状态只用于查询和展示，不落盘存储，避免跨时区或日期变化产生无意义写入。

## 4. 功能需求

### 4.1 通用任务操作

#### 4.1.1 创建

- 用户选择“短期待办”或“长期任务”。
- 表单必须包含标题、描述、开始日期、结束日期、重要程度。
- 默认值：开始日期为今天、结束日期为今天、重要程度为 `normal`。
- 长期任务创建后进入详情页，可立即添加第一个子任务或进展。
- 保存成功后返回任务详情，其中包含任务 ID、所属文档键和当前 `document_version`。

#### 4.1.2 编辑

- 支持修改标题、描述、日期、重要程度。
- 长期任务和子任务可修改状态；短期待办的终态变更必须走关闭流程。
- 编辑请求携带所属文档的 `expected_version`，由 `revision + content_hash` 组成。任一项不一致时不得覆盖，返回冲突并提示刷新后重试。
- 修改日期后，日历视图必须立即更新。

#### 4.1.3 关闭与重新打开

- 关闭面板显示当前任务摘要、目标状态和关闭说明输入框。
- 成功关闭后卡片原位更新，不立即从视图消失；若当前筛选仅显示活动任务，则使用退出动画后移除。
- 重新打开需要选择恢复后的状态：短期固定为 `open`，长期默认为 `in_progress`。
- 关闭和重新打开均记录审计事件。

#### 4.1.4 归档

- 归档用于隐藏已经结束且不再需要频繁查看的根任务，不删除任务数据；长期子任务不可单独归档。
- 默认列表和日历不显示归档任务，可通过筛选查看。
- 活动任务归档前必须确认。
- 支持取消归档。

### 4.2 短期待办

#### 4.2.1 快速创建

- 在任务视图顶部提供“快速待办”入口。
- 首次只展示标题、日期和重要程度；描述通过“添加描述”展开。
- 在日历某日创建时，开始和结束日期默认选中该日。
- 提交后创建以 `db:short:{uuid}` 为键的独立文档，并记录不可变的 `storage_month`。

#### 4.2.2 列表操作

- 卡片展示：完成控件、标题、日期范围、重要程度、逾期状态。
- 桌面端支持悬浮显示编辑/关闭菜单；手机端通过长按或更多按钮打开操作表。
- 点击完成控件不能直接静默完成，必须打开关闭面板，以便填写关闭说明。

### 4.3 长期任务

#### 4.3.1 任务详情

详情页包含：

1. 标题、状态、重要程度、日期、聚合进度。
2. 根任务描述。
3. 可折叠的任务树。
4. 全树聚合的进展与记录时间线：根任务与所有子任务的进展、审计条目按时间倒序展示，每条标注所属任务名；点击任务名可聚焦该任务（子任务打开详情抽屉，根任务回到总览）。
5. 编辑、添加子任务、添加进展、移动、关闭等操作。

#### 4.3.2 多级拆解

- 在根任务或任一子任务上执行“添加子任务”。
- 新子任务默认继承父节点日期和重要程度，用户可修改。
- 树默认展开到最近操作节点，其他分支记忆上次展开状态。
- 桌面端支持拖拽同级排序和重设父节点；拖动全程提供目标位置反馈并可中断。
- 手机端不依赖精细拖拽，通过“移动到…”选择父节点和位置。
- 移动后必须保持选中节点可见，并支持撤销最近一次移动。

#### 4.3.3 添加进展

- 用户可针对根任务或选中的子任务添加进展。
- 输入项包括进展说明和可选进度百分比。
- 进展按时间倒序展示，每条标注所属任务名。
- 新进展保存后立即插入任务详情的进展时间线，并更新聚合进度。
- 记录 `blocked` 状态时，界面优先提示添加阻塞原因。

#### 4.3.4 子任务详情抽屉

- 详情面板固定展示根任务总览；点击任务树中的子任务，从右侧滑出抽屉展示该子任务的标题、状态、描述、日期、优先级与其专属进展记录。
- 桌面端（≥1150px）抽屉压缩详情面板让位；较窄屏幕与手机端以浮层从右侧滑入，点击遮罩关闭。
- 抽屉内提供记录进展、添加子任务、更改状态、编辑、移动操作，复用统一的表单弹层。
- 抽屉打开时点击其他子任务，抽屉内容直接切换；点击根任务行、关闭按钮或 Esc 收起抽屉。

### 4.4 任务视图

#### 4.4.1 顶层结构

```
┌──────────────────────────────────────────────────────────────┐
│ 个人任务    [任务视图 | 日历视图]   [搜索] [筛选] [+ 新建] │
├──────────────────────┬───────────────────────────────────────┤
│ 分组/列表             │ 任务详情                              │
│ 今天                  │ 长期任务标题      进度 42%            │
│ 即将到期              │ 描述 / 日期 / 重要程度                │
│ 长期任务              │ ┌─ 子任务 A                           │
│ 已完成                │ │  └─ 子任务 A.1                      │
│                       │ └─ 子任务 B                           │
│                       │ 进展时间线                             │
└──────────────────────┴───────────────────────────────────────┘
```

#### 4.4.2 默认分组

- 逾期：结束日期早于今天的活动任务。
- 今天：今天开始、今天截止或正在日期区间内的活动任务。
- 即将到期：未来 7 天内截止。
- 长期任务：未进入上述时间分组的活动长期根任务。
- 之后：未进入上述分组的其他活动任务。
- 已完成：最近完成的任务，默认只加载 30 天。

每个根任务只进入一个默认分组，优先级依次为“逾期 → 今天 → 即将到期 → 长期任务 → 之后”，避免同一任务重复出现。

#### 4.4.3 筛选与排序

筛选项：

- 类型：全部 / 短期待办 / 长期任务。
- 状态：活动 / 计划中 / 进行中 / 受阻 / 已完成 / 已取消。
- 重要程度：低 / 普通 / 重要 / 紧急。
- 日期范围：开始日期或与查询区间重叠。
- 是否包含归档。
- 长期任务是否展开子任务。

排序项：截止日期、开始日期、重要程度、最近更新、创建时间。默认规则为：逾期优先，其次重要程度降序，再按结束日期升序。

### 4.5 日历视图

#### 4.5.1 桌面端

- 默认月视图，顶部支持上一月、今天、下一月和月份跳转。
- 右侧为所选日期的日程面板。
- 单日任务显示为日程块；跨日任务显示为连续日期条。
- 短期待办和长期根任务默认显示；“显示子任务”开关打开后显示全部长期节点。
- 任务类型使用图标/标签区分，重要程度使用边缘色和文字共同表达，不能只依赖颜色。
- 点击日程打开任务详情；点击日期空白区域打开新建菜单并预填日期。

#### 4.5.2 手机端

- 使用紧凑月历 + 选中日期议程列表，不在窄屏强行绘制跨列长条。
- 日期格只显示事件点、最高重要程度和数量；完整标题显示在下方议程列表。
- 左右滑动月份时保持手势连续，动画可中断；减少动态效果模式下改为短淡入淡出。
- 议程卡片触控目标不小于 44px。

#### 4.5.3 日历查询规则

- 查询采用区间重叠：`task.start_date <= range_end && task.end_date >= range_start`。
- 跨月任务在每个覆盖日期可见，但仅有一个任务实体。
- 已完成/已取消任务默认以降低强调度显示，可通过筛选隐藏。
- 归档任务默认隐藏。
- 月视图最大查询 42 天；Tool API 自定义查询范围最多 366 天。

### 4.6 搜索

- 搜索范围包括标题、描述、关闭说明和进展说明。
- 输入防抖 250ms，结果按标题命中、状态、更新时间综合排序。
- 搜索结果显示任务路径，例如“长期任务 / 子任务 A / 子任务 A.1”。
- 点击结果直接定位并展开对应节点。

## 5. SQLite 存储规范

### 5.1 数据表

任务数据保存在 SQLite 的四张表中：

| 表 | 职责 |
|---|---|
| `task_documents` | 文档聚合头：主键 `path`、`document_kind`、`root_id`、`storage_month`、`revision`、`content_hash` |
| `task_nodes` | 任务节点行（短期根、长期根、长期子任务），含进度派生指标列 |
| `task_progress` | 进展记录 |
| `task_audit_events` | 审计事件 |

后三张表通过 `storage_path` 外键关联文档（`ON DELETE CASCADE`）。一次写入在单个事务内整体替换文档的全部行，失败即回滚，不存在半写状态。

### 5.2 文档键与数据权威

- 数据权威在 SQLite；`task_documents.path` 仅为文档主键，无文件系统语义。
- 新建文档使用合成键：短期待办为 `db:short:{uuid}`，长期根任务为 `db:long:{uuid}`。
- 存量数据行保留 `Tasks/...` 形式的历史路径字符串作为主键；系统不再据此读写任何文件。
- 短期待办每个任务独立一个文档（ShortMonth 种类，记录 `storage_month`）；不再把多个待办合并进月份文件。
- 长期根任务与其全部子任务、进展、审计事件同属一个文档。

### 5.3 Schema 演进

- 表结构演进通过编号迁移脚本完成：`009_tasks.sql` 建表，`010_remove_task_sync.sql` 删除同步队列表和文档同步错误列。
- 迁移按顺序执行且只运行一次；结构变更必须通过新迁移脚本表达，不允许运行时改表。
- SQLite 不可由 Vault 重建：数据库是唯一权威，备份与恢复属基础设施话题，另行立项。

## 6. 交互与视觉设计

### 6.1 与现有系统一致性

- 复用全局液态玻璃变量、圆角、阴影、排版和深浅/护眼主题。
- 任务详情是内容层，筛选栏和操作栏是轻量半透明功能层，不叠加多层玻璃。
- 重要程度通过文字、图标和颜色共同表达。
- 关闭、移动、保存都提供即时状态反馈；失败时原位保留用户输入。

### 6.2 动效

- 列表插入、移除使用短距离位移 + 淡入淡出，基于当前位置执行。
- 树节点展开采用高度/透明度的克制过渡，不使用弹跳。
- 拖拽重排应 1:1 跟随指针，释放后使用无过冲弹簧落位，可在动画中重新抓取。
- 任务移动、批量关闭支持撤销条，撤销时间 5 秒。
- `prefers-reduced-motion` 下取消位移和弹簧，只保留 120–180ms 淡入淡出。
- `prefers-reduced-transparency` 和高对比度模式使用近实色背景和清晰边框。

### 6.3 可访问性

- 任务树使用 `role="tree"` / `role="treeitem"`，提供层级、展开和选中状态。
- 所有图标按钮必须有可访问名称。
- 键盘支持上下移动、左右展开/折叠、Enter 打开详情、Space 切换选择。
- 状态、重要程度、逾期不能只用颜色表达。
- 日期、进度和保存状态更新通过适度的 `aria-live` 通知。

## 7. Tool API 需求

### 7.1 工具清单

| 工具 | 说明 |
|---|---|
| `create_task` | 创建短期待办或长期根任务 |
| `list_tasks` | 按类型、状态、重要程度、日期、关键词分页查询 |
| `get_task` | 获取任务详情；长期任务包含完整任务树和进展 |
| `update_task` | 更新根任务或子任务字段，要求 expected_version |
| `set_task_status` | 关闭、取消、阻塞、重新打开，可携带关闭说明和级联选项 |
| `add_subtask` | 在长期任务指定节点下添加子任务 |
| `move_subtask` | 调整子任务父节点和顺序 |
| `add_task_progress` | 为长期根任务或子任务追加进展 |
| `get_task_calendar` | 查询与日期范围重叠的日程条目 |
| `archive_task` | 归档或取消归档根任务 |

除 `create_task` 和只读查询外，所有修改工具都必须携带最近一次读取返回的：

```json
"expected_version": {
  "revision": 18,
  "content_hash": "sha256:6a6f…"
}
```

双因子版本令牌由服务端在每次写入时重新生成，用于发现读取之后发生的并发写入，避免丢失更新。

```json
  "end_date": "2026-08-22",

}
```

## 8. 非功能需求

### 8.1 性能

| 操作 | 目标 | 数据规模基线 |
|---|---:|---:|
| 活动任务首屏 | P95 < 300ms | 10,000 个已存储节点，返回 50 条 |
| 单任务详情 | P95 < 500ms | 500 子节点、1,000 条进展 |
| 月历查询 | P95 < 200ms | 42 天、2,000 个重叠节点 |
| 写入任务 | P95 < 500ms | 单文档事务写入 |

前端任务树和议程列表超过 200 个可见节点时必须启用虚拟化或分段渲染，避免一次性创建大量 DOM。

### 8.2 可靠性

- 每次写入在单个 SQLite 事务内整体替换文档的全部行；事务失败即整体回滚，不产生部分写入。
- 每次写入前校验 revision、重复 ID 和树结构（循环、孤儿、深度）。
- 同一文档的写操作通过按路径的异步互斥锁串行化，避免本地并发覆盖。
- 修改类请求必须通过 `expected_version` 乐观并发校验，冲突时拒绝写入并提示刷新。

### 8.3 隐私与安全

- 任务数据只保存在本地 SQLite 数据库中，不写 Vault、不访问外部服务。
- Tool API 不接受任意路径或 SQL 参数；文档键由服务端生成。
- 描述、关闭说明和进展在前端按 Markdown 渲染时继续执行现有 HTML 清洗策略，禁止脚本执行。

### 8.4 兼容性

- 支持当前桌面端和 ≤768px 手机端布局。
- 数据库文件可直接用标准 SQLite 工具查询和备份。

## 9. 错误与冲突体验

| 场景 | 用户体验 |
|---|---|
| 标题为空或日期非法 | 字段旁即时提示，不发送请求 |
| 文档版本冲突 | 显示“任务已在别处更新”，提供刷新和复制当前输入 |
| 数据库写入失败 | 保留表单内容并提示重试；事务已回滚，无半写数据 |
| 文档内出现重复任务 ID | 拒绝写入并返回校验错误，不产生静默覆盖 |
| 子任务形成循环 | 拒绝移动并恢复原位置 |
| 根任务尚有活动后代 | 提示剩余数量，提供查看或显式批量完成 |

## 10. 验收标准

### 10.1 短期待办

- [ ] 可以创建包含标题、描述、起止日期、重要程度的短期待办。
- [ ] 新任务创建以 `db:short:{uuid}` 为键的独立文档，并记录不可变的 `storage_month`。
- [ ] 关闭时可选择完成/取消并填写关闭说明。
- [ ] 已关闭任务可以重新打开，历史关闭事件可追溯。
- [ ] 修改任务日期不会改变其 storage_month 或产生重复 ID。

### 10.2 长期任务

- [ ] 每个长期根任务对应一个稳定文档（`db:long:{uuid}`）。
- [ ] 可以创建至少 5 层子任务，并正确保存父子关系。
- [ ] 子任务移动不能形成循环或跨根任务。
- [ ] 根任务和任意子任务都可以追加进展说明及可选百分比。
- [ ] 聚合进度、完成叶子统计符合 §3.4 规则。
- [ ] 有活动后代时不能静默完成根任务。

### 10.3 双视图

- [ ] 任务视图支持类型、状态、重要程度、日期和关键词筛选。
- [ ] 日历视图正确显示单日和跨日任务。
- [ ] 手机端使用月历 + 当日议程，所有核心操作单手可达。
- [ ] 任一视图修改任务后，另一个视图无需整页刷新即可更新。

### 10.4 持久化与数据安全

- [ ] 每次写入在单个事务内完成；写入失败后数据库中无部分结果。
- [ ] revision 或内容哈希冲突不会覆盖较新内容。
- [ ] SQLite 为唯一权威存储，全模块不产生任何 Vault 文件写入。
- [ ] 数据库备份方案已明确（备份属基础设施话题，另行立项）。

### 10.5 可访问性与动效

- [ ] 键盘可以浏览任务树并执行核心操作。
- [ ] 屏幕阅读器可以读出层级、状态、重要程度和日期。
- [ ] 减少动态效果、减少透明度和高对比度偏好均有替代样式。
- [ ] 拖拽动画可中断，失败时节点回到原位置。
- [ ] 查看根任务详情时，进展与记录时间线能看到所有子任务的条目，且每条标注所属任务名；点击任务名能聚焦对应任务。
- [ ] 点击子任务从右侧打开详情抽屉（桌面端主面板被压缩），抽屉内可完成记录进展、更改状态等操作，操作后数据即时刷新。
