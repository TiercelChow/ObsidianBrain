> **最后更新**: 2026-09-25

## 0. 当前交付状态

截至 2026-09-25，Markdown 书籍已经完成本需求的第一阶段闭环：来源同步保留不可变版本与历史引用；智能编译跨文件归并语义主题并形成结构化变更集；用户审核后才原子写入条目、论断、关系、引用和版本。Wiki 工作台可查看这些结构并执行确定性的知识体检。

问答会优先检索语义条目、再使用当前章节证据兜底，会话和引用可恢复，回答可以显式保存为待审核知识候选。研究任务已改为持久化后台队列，支持取消、重试和服务重启恢复，可交付 Markdown 报告或由受控 Rust 生成器生成的真实 PPTX；PPTX 完成结构校验后提供下载，并展示页数、构图、引用覆盖和逐项质量检查，成果文件与知识回写分别记录状态。

问答和研究现把绑定的文本 Skill 作为本次隔离的 DeepSeek Harness 原生 Skill 提供，由模型按需读取，不再把全部 Skill 正文重复塞入回答 Prompt。问答的编译目录选择支持分批候选全局重排与近邻会话指代；研究可从空初始证据出发，借助分页目录与受限知识工具继续查找。工具返回的实体和原文版本写入运行证据账本，引用在完成前检查是否属于本轮真实可见证据；这不等于对每句话做语义真伪验证。工具次数、来源返回长度和运行时间均有上限，外部研究仍需逐任务授权。

Skill Registry 已在 SQLite 中保存内置、自定义和 ZIP 导入的版本化指令包，并按书籍与问答/研究用途绑定。除建库、问答、审校、研究和演示文稿外，现已内置跨章综合与 Markdown 资料汇编输出契约。当前安全级别仅支持 UTF-8 指令与参考文本，不执行脚本，不开放任意文件或 Shell。Agent Runtime 通过受限 DeepSeek Harness ACP 调用已配置的兼容模型供应商。需要知识工具的交互式运行会获得短时、按 Run、知识库和工具白名单绑定的能力令牌，通过本机 MCP 工具网关按需读取来源与实体；令牌仅以哈希保存并在运行结束时撤销。智能编译直接接收服务端裁剪后的来源批次，不挂载无用工具，也不签发工具能力令牌。

Book Wiki 正式限定为 Markdown 文件夹，不规划 PDF 抽取或 OCR；PDF 仅保留在阅境轩阅读功能中。Agent Runtime 正式限定为 DeepSeek Harness，不再规划第二套 Runtime Adapter。问答现通过专用 SSE 接口消费 ACP 原生文本增量、工具阶段和上下文 Usage，断开问答流会中止对应运行；研究任务取消会立即发送 ACP 取消通知。供应商没有报告精确输入/输出 Token 时，统计仍明确标记为估算值，不用上下文占用伪装精确计费数据。

语义编译现按来源文档保存最近成功分析的版本检查点。首次构建读取全书，后续只把新增或内容变化的 Markdown 来源交给 Runtime；候选被驳回时释放对应检查点，允许重新分析。实体和当前来源片段已使用带中文二元组的 FTS5 索引，标题、别名、摘要、正文按权重排序；没有全文查询条件时使用普通分页，有查询条件时不再回退到全表 `LIKE` 扫描。

智能编译现作为独立后台任务执行，启动接口立即返回，页面关闭或跳转不会中断模型调用。知识库持久化记录队列、来源准备、Harness 连接、思考、工具调用、生成、批次完成、保存和待审核阶段，以及来源/批次进度、当前 Run、心跳与取消请求。知识库页面轮询这些状态并提供停止、失败重试和审核入口；服务异常退出后旧任务不得继续显示为运行中，而应明确标为可重试失败。智能编译使用独立的长任务截止时间，并限制单批来源和候选规模；普通知识问答继续使用较短截止时间，避免两类负载互相牵制。

知识库生命周期现已真正约束同步、问答、研究任务、Agent Run 与审核写入，而不再只是展示字段；原书目录失效时保留数据库历史并进入只读告警。工作台采用后端分页与前端分段加载，实体编辑、合并和拆分统一先形成高风险候选：合并批准后归档来源并迁移关系，拆分批准后归档原实体并建立继承原始引用的新实体。桌面端按需加载有限图谱快照，支持拖动、缩放、路径高亮和实体跳转；手机端只加载孤立/枢纽洞察列表，关闭弹窗后释放图谱数据。阅境轩只在 Markdown 正文选区显示知识操作，可把原文带入问答、解释、研究任务或生成带当前片段引用的审核候选；PDF 不出现这些操作。

数据库现使用 SQLite Online Backup 创建包含 WAL 最新写入的一致快照，迁移、知识库删除、大批量变更和恢复前自动备份，保留数量可配置。恢复会先检查完整性、外键和迁移版本，拒绝在问答或研究任务运行时执行，完成后重新运行迁移并强制重建 FTS。Wiki 配置页可以创建、下载及恢复快照，也可把单本书导出为流式 JSONL 结构包或可浏览 Markdown Wiki；导出包含来源片段、实体、论断、关系、引用、问答和研究报告，且位于原书目录之外。

研究任务使用数据库租约、十五秒心跳、过期重领和最多三次指数退避；同一本书由数据库唯一约束保证只运行一个写任务。实体列表改为 SQL/FTS 原生 LIMIT/OFFSET 分页，有全文索引查询时不再追加全表 LIKE 扫描；十万来源片段规模回归已验证 FTS 虚拟索引查询计划。

Skill 管理现可直接查看内置、自定义与导入 Skill 的完整文件树、文本资源、权限、依赖和全部版本；内置 Skill 只读，但可复制为自定义版本后调整。研究任务结果可查看本次 Run 的最终有效 Prompt、Prompt 哈希、Skill 与配置快照、工具白名单和事件时间线。智能编译会实际注入当前书籍启用的 `ingest` Skill；没有自定义编译 Skill 时使用内置 `book-ingest`。Skill、配置文档、模型或编译协议变化都会改变编译指纹，使旧来源检查点失效并触发全书重新分析，避免“页面显示已绑定但运行仍使用旧 Prompt”。

Skill 版本现区分候选、已发布和已退役状态，并记录父版本、变更说明、上游仓库、来源路径、引用、许可证、署名和本地适配说明。内置质量升级先作为候选进入固定离线评测，再由已配置的 DeepSeek Harness 对当前版与候选版运行同一组固定真实样例；建库、问答、研究和演示分别内置 12、8、6、6 个样例。真实基准在只读、无工具权限的隔离 Run 中聚合执行，保存逐样例回答、引用、指标和 Agent Run，候选分数达到评测集门槛、至少 80% 的样例通过且相对当前版回退不超过 3 分才能人工发布。发布后可回滚到任一历史已发布版本。智能编译结果按新增、更新、争议和无实质变化分流：前三类进入带引用审计和级联影响摘要的审核变更集，无实质变化会记录一次已完成编译并更新检查点，不制造空审核任务。

七个内置 Skill 的正文现已按实际运行协议扩充并保存为可查看的独立 `SKILL.md`。产品所有者要求本次直接替换当前内置版本，因此该次数据库迁移直接启用新版；既有用户自定义 Skill 和书籍绑定保持原样。后续从页面发布候选版仍遵守上面的评测门槛。

专题研究可由用户在创建任务时单独开启外部资料研究，并必须同时填写授权域名和请求上限。未开启时能力令牌不包含外部工具；开启后也只允许标准 443 端口 HTTPS、文本响应、授权域名及其子域名，不跟随重定向，并拒绝 IP 直连、内网/回环/保留地址和超过 512 KiB 的正文。每次尝试都会原子消耗任务额度并写入 Run 事件。外部资料只能单列为参考，不能伪装成书内引用或绕过知识变更审核。

原 `Memory.vue`、`WikiDashboard.vue`、`WikiWorkbench.vue`、`Explore.vue`、`Ingest.vue` 及对应旧后端工具已删除。旧地址在一个发布周期内分别跳转到新的知识库、Wiki 工作台、问答或研究任务页面。旧 Obsidian `Wiki/*.md` 原样保留但不会自动导入，也不会与数据库 Book Wiki 双写。

## 1. 产品定位

### 1.1 一句话定义

以阅境轩书架为入口，把每一个 Markdown 文集维护为一个相互隔离、可持续演化的 LLM Wiki 知识库。

### 1.2 核心关系

```text
阅境轩负责阅读原书
    ↓
书籍知识库负责理解、组织、检索和维护知识
    ↓
Agent Harness 负责分析、问答和研究任务的执行
```

每一本书都是独立知识库。默认情况下，一本书的实体、检索结果、对话、任务和 Agent 上下文不得进入另一本书。跨书查询必须由用户显式选择参与的知识库。

### 1.3 LLM Wiki 原则在本产品中的映射

| LLM Wiki 原则 | 本产品实现 |
|---|---|
| 原始资料保持可追溯 | 阅境轩 Markdown 文集路径只读；记录来源版本、哈希、标题与行号 |
| 知识持续积累 | 结构化实体、论断、关系、引用和综合内容写入 SQLite |
| Purpose 决定方向 | 每个知识库有独立 purpose 配置文档 |
| Schema 约束结构 | 每个知识库有独立 schema 配置文档和实体类型约束 |
| Ingest / Query / Lint 闭环 | 摄入、问答、维护均通过任务与审核机制进入同一知识模型 |
| 人负责判断，Agent 负责维护 | 高风险变更必须审核；Agent 不能直接执行 SQL 或绕过权限 |

### 1.4 核心价值

1. 阅读不再止于打开文件，而会逐步形成可检索、可验证的书籍知识体系。
2. 每个回答都能回到原书的具体文件、标题、行号或文本片段。
3. 知识以数据库实体管理，支持筛选、合并、版本、图谱和结构化检索。
4. 长时间摄入、研究和维护由成熟 Agent Harness 执行，不在业务层重复实现 Agent Loop。
5. 知识内容、业务状态和安全边界由 ObsidianBrain 掌控，DeepSeek Harness 只负责执行 Agent 工作流。

### 1.5 与直接打开文档文件夹的通用 Agent 相比

不把“能读文件、调用 Skill、拆分子代理或接入 MCP”包装为本产品独有能力；[Claude Code 官方文档](https://code.claude.com/docs/en/features-overview)已经提供这些扩展方式。通用 Agent 在临时探索、自由推理和任意格式产出上仍可能更灵活，本产品不声称模型本身更聪明。

本产品应在反复阅读同一本书的工作中形成可验证的差异：书籍与知识库自动对应，编译知识跨会话积累；原文版本、实体、论断、引用和失效影响能够逐项追踪；研究子问题、综合、报告和演示成果作为可恢复阶段保存；用户在启动前确认受众与材料目的，在执行中看到预算、取证和缺口，在结束后能审核知识回写。优势应通过同一组真实任务的来源可追溯性、遗漏率、恢复成本和用户修订量验证，而不是只比较回答篇幅。

## 2. 范围与非目标

### 2.1 首版范围

- 将现有书架条目升级为稳定的书籍身份。
- 为 Markdown 文件夹建立一对一知识库；PDF 不进入 Book Wiki。
- 管理知识库的初始化、同步、暂停、健康、审核、归档和删除。
- 从原书提取来源文档和可定位片段。
- 生成并维护实体、论断、关系、引用、综合内容和版本历史。
- 提供单书问答、显式跨书问答和回答回写。
- 提供可由 Agent 执行的研究任务。
- 提供 LLM、Harness、配置文档、Skill、模板和安全策略管理。
- Agent Runtime 仅接入 DeepSeek Harness，并继续支持其兼容的模型供应商。
- 支持桌面与手机端完整操作。

### 2.2 明确非目标

- 不继续维护旧的全 Vault 知识洞察、随机概念碰撞和雷达专用摄入页面。
- 不把原书复制或改写为 Wiki Markdown 目录作为主存储。
- 不让 Agent 直接修改 SQLite、原始书籍或正式知识实体。
- 不实现任意网站爬取、通用 RAG 平台或多人协作权限系统；外部研究只提供逐任务、逐域名、只读限额文本读取。
- 不把研究任务和现有个人待办强行合并；只提供可选关联。
- 不支持 PDF、EPUB、Word 等非 Markdown 来源进入 Book Wiki；PPTX 只作为可下载研究成果。

## 3. 信息架构

“知识”分组保留五个入口，但全部替换为新页面：

| 页面 | 路由建议 | 职责 |
|---|---|---|
| 知识库 | `/knowledge` | 管理书架中所有书籍知识库的状态与生命周期 |

从知识库列表、书架卡片或问答结果进入 Wiki 工作台时，当前知识库必须明确显示，不允许以隐含的“最近一本书”作为写操作目标。

## 4. 核心领域概念

### 4.1 书籍（Reader Book）

阅境轩中的阅读对象仍可以是 Markdown 文件夹或 PDF 文件；只有 Markdown 文件夹可以启用知识库。

### 4.2 知识库（Knowledge Base）

与书籍一对一绑定的逻辑空间。知识库拥有独立配置、来源版本、实体、关系、对话、任务、审核和运行记录。

### 4.3 来源文档与来源片段

- Markdown 文集：每个 Markdown 文件是来源文档，标题区块或分段是来源片段。
- 每个片段必须能够跳回阅境轩中的原位置。

### 4.4 知识条目（Knowledge Entry）

可独立查看和管理的知识对象，类型至少包括：

- 章节摘要 `chapter`
- 人物、组织、地点、作品等实体 `entity`
- 概念 `concept`
- 方法 `method`
- 事件 `event`
- 对比 `comparison`
- 综合论述 `synthesis`
- 问题 `question`
- 已保存回答 `answer`
- 全书概览 `overview`

条目正文以 Markdown 字符串存入数据库，用现有安全 Markdown 渲染方案展示；条目不是磁盘上的 Markdown 文件。

### 4.5 论断（Claim）

可独立验证的最小知识陈述。论断必须可以关联来源、支持证据、反对证据、可信度和验证状态。

### 4.6 关系与引用

- 关系表达条目之间的语义连接，如“属于”“支持”“反驳”“解释”“比较”“前置知识”。
- 引用连接条目或论断与原书来源片段。
- 图谱来自数据库关系，不依赖解析 `[[wikilink]]`。

### 4.7 变更集与审核

Agent 的新增、修改、合并、拆分、归档建议必须形成结构化变更集。变更集通过校验后自动应用或进入人工审核。

### 4.8 研究任务

知识工作流中的可执行事项，区别于个人任务中枢的日程型任务。研究任务可以选择关联到个人任务，但知识结果仍归属书籍知识库。

## 5. 知识库状态模型

知识库状态拆分为三个正交维度，避免单一枚举表达不清。

### 5.1 生命周期

```text
uninitialized → active ⇄ paused → archived
```

- `uninitialized`：书已在书架，但尚未建库。
- `active`：允许同步、问答和执行任务。
- `paused`：保留全部数据，停止自动同步和新任务。
- `archived`：只读保留，不进入默认列表。

### 5.2 同步状态

```text
clean | outdated | scanning | extracting | ingesting | failed
```

### 5.3 智能编译状态

```text
queued → preparing → invoking → runtime → thinking/tool/generating
       → batch_completed → finalizing → waiting_review → completed
                                     ↘ cancelling → cancelled
                                     ↘ failed
```

### 5.4 健康状态

```text
healthy | warning | needs_review
```

健康状态由确定性检查得出，不使用不可解释的单一 LLM 分数。主要指标包括：

- 无来源论断数量
- 待验证论断数量
- 矛盾论断数量
- 孤立实体数量
- 重复实体候选数量
- 失效来源引用数量
- 待审核变更数量
- 失败任务数量

## 6. 页面需求

### 6.1 知识库页面

#### 页面目标

快速看清所有书籍知识库当前是否可用、是否需要同步、是否需要人工处理。

#### 顶部摘要

- 已启用知识库
- 正在处理
- 原书有变化
- 待审核
- 运行失败

#### 主列表

支持书架卡片和高密度列表两种视图；桌面记住用户选择，手机默认卡片。

每项显示：

- 书名、类别、封面色和阅读进度
- 生命周期、同步和健康状态
- 最近同步时间
- 来源文档、知识条目和论断数量
- 有来源论断比例
- 待审核和失败数量
- 当前模板、Harness 和模型概要
- 运行中任务及进度

#### 操作

- 初始化知识库
- 打开 Wiki 工作台
- 问这本书
- 扫描原书变化
- 增量同步
- 暂停或恢复
- 执行健康检查
- 重新构建
- 归档
- 删除知识库

批量操作首版支持扫描、同步、暂停和恢复。重新构建与删除不允许批量静默执行。

### 6.2 Wiki 工作台

#### 桌面布局

- 左侧：类型、标签、状态、来源和搜索导航。
- 中间：知识条目或来源片段正文。
- 右侧：引用、关系、论断、版本和快捷操作。

左栏允许压缩为窄轨；右栏允许关闭。中间内容始终获得主要宽度。

#### 手机布局

- 默认只显示主体内容。
- 导航、关系、版本和操作通过底部抽屉打开。
- 不把桌面三栏直接压缩到手机宽度。

#### 主要视图

- 概览：全书目的、概览、关键概念、健康和最近变化。
- 实体：按类型和状态浏览知识条目。
- 来源：查看 Markdown 文件、标题片段和同步状态。
- 图谱：查看关系；手机默认先显示洞察列表，再进入全屏图谱。
- 审核：查看 Agent 变更差异并批准、驳回或编辑。
- 运行：查看任务步骤、工具调用、Token、耗时和错误。

#### 实体详情

实体详情至少展示：

- 标题、类型、别名、状态、可信度
- Markdown 正文
- 原子论断及验证状态
- 来源与原文位置
- 关联实体和关系理由
- 支持与反对证据
- 相关问答和研究任务
- 版本历史

支持编辑、合并、拆分、添加别名、标记过时、提问和创建验证任务。

### 6.3 书籍问答

#### 查询范围

- 默认单书，必须有明确的知识库选择。
- 跨书问答需要用户勾选多个知识库，并在会话头部持续展示范围。
- 阅读上下文入口自动带入当前书籍、文件、标题、页码和选中文字。

#### 回答要求

- 流式显示正文。
- 回答正文使用与阅境轩一致的安全 Markdown 语义，至少支持 GFM 表格、列表、代码块、链接和 LaTeX；流式阶段允许节流重渲染，但最终结果必须完整重渲染。
- 引用知识条目和原始来源片段。
- 点击引用先在当前页面打开来源预览；只有用户明确选择“在 Wiki 工作台打开”或“在阅境轩定位”后才执行跳转。
- 会话、消息和消息引用持久化到 SQLite；再次进入页面时恢复最近会话，也可从历史列表切换或新建会话。
- 区分“直接来源支持”“知识库综合”“Agent 推断”。
- 当证据不足或冲突时明确提示。

#### 后续操作

- 保存为知识条目
- 更新已有知识条目
- 创建研究或验证任务
- 标记回答有用、存疑或错误
- 导出 Markdown

任何回写都必须形成变更集，不允许聊天结果直接覆盖正式知识。

### 6.4 研究任务

#### 任务类型

- 建库初始化
- 增量摄入
- 全书或章节总结
- 实体提取与去重
- 论断验证
- 概念比较
- 知识缺口研究
- 健康检查与修复
- 自定义研究

#### 状态

```text
draft → queued → running → waiting_review → completed
                       ├──→ failed
                       └──→ cancelled
```

#### 任务内容

- 所属知识库和来源范围
- 目标、约束和验收说明
- 创建前可对题目做一次不读取书籍证据的预分析，指出影响成果的关键编辑决策，并就每个重点字段说明具体要决定什么、选择将如何改变材料；用户明确确认受众、用途、表述方式、深度和（PPT 时）视觉主题与论点式/问答式编排后才写入任务简报。预分析建议不是用户决定，也不是研究结论；模型不可用或旧响应缺少决策说明时仍可手动确认偏好。旧任务没有确认标记时沿用原有默认行为。
- Harness、模型、配置文档和 Skill 版本快照
- 执行步骤、实时进度和当前等待事项
- Token、耗时、重试次数和错误
- 生成的变更集和最终结论

用户可以取消运行中任务、重试失败任务、编辑草稿任务、批准变更后继续任务。

研究和演示策划必须把用户确认的简报作为编辑合同：决策材料强调方案、权衡与适用条件，教学材料强调概念递进，查阅材料强调结论和定位；任何风格都不能牺牲引用、反例或适用边界。PPT 必须遵守用户选定的主题和编排方式；论点式材料若多数页面仍是问句标题，应按策划合同错误修复一次，用户明确选择问答式讲解时允许真实问题引导，但每页仍要交付有证据的内容。

研究子问题是后台取证分工，不应直接成为交付材料的逐题问答目录或 PPT 的逐题页面。规划阶段应分别给出内部研究目标、面向读者的材料标题与章节标题，避免把提问原文直接当作成品标题；旧任务没有材料标题时仍可用原目标组装报告。确认用途为决策或查阅时，报告应先给有条件的综合判断或要点速览，再展开各主题证据；教学材料与未确认偏好的旧任务维持逐层展开、末尾综合的顺序。报告组装只去掉完全重复的包装标题和摘要，不删改已保存的正文或引用。确认后的用途、受众与语气应转成具体的写作与演示路径，而不只是把枚举值原样交给模型。

#### 大上下文与阶段输出预算

- 问答与研究未声明模型上下文时，以 1M 作为可覆盖的应用默认值，而不是模型能力保证；明确配置的较小或更大容量不被替换，运行时上报实际容量后校验真实空间。
- 最大输出单独约束，不能把 1M 上下文误当作 1M 输出。研究按必要正文、JSON 结构和推理余量分配请求预算；问答把规划的可见正文长度与模型推理余量分开。估计不足时只扩大当前阶段，不为了更短而删掉论证、公式或条件。
- 供应商明确声明单次最大输出时，新的研究规划必须给每个子问题估计必要正文篇幅；保存前按该上限、发现矩阵结构和推理规划余量检查可行性。明显超出的主题应在规划阶段拆分，不能让章节执行时静默裁剪预算再反复截断。未声明输出能力时不把上下文默认值推断成供应商输出上限；旧任务已保存的规划不因新增规则失效。
- 每个规划/章节/综合阶段有独立且有限的输出扩容机会，不共享整项研究的全局退避次数。格式修复单独计数，取消、拒绝、权限及数据库故障不自动重复请求。
- 运行失败必须区分可恢复的临时供应商/网络错误和需要用户处理的确定性错误。只有明确的限流、服务端 5xx、连接中断或偶发空回答才允许后台退避；凭据/额度/权限、无效请求、上下文硬限、格式校验耗尽、取消和阶段截止时间不能靠无差别重放解决，应停止并保留失败阶段供用户显式恢复。问答的临时运行错误只重试回答 Run 一次，不重复目录规划。
- 截断正文标为未完成并保留；已完成章节不重跑。达到真实硬限或本阶段扩容机会耗尽时明确停止，用户可以调整配置或拆分主题后显式恢复。
- 跨章节综合的初始输入也必须按实际 Prompt 空间分配：完整发现矩阵可容纳时直接提供；过大时仍保留全部章节身份与版本，只投影可容纳的摘要/发现并明确标出遗漏数量。Agent 应通过仅限本任务综合阶段的分页工具定向读取需要复核的完整矩阵，不得把未预载或未读内容当作不存在、已核验或本轮引用。
- 综合输出按实际章节数为逐章对照合同预留空间，而不是把正文估计直接裁到供应商上限。若声明的单次输出可容纳完整合同但小于原综合篇幅估计，可压缩重复的综合表述，不能删逐章检查、冲突和条件；完整研究章节仍作为交付物保留。若连最低可用综合都容纳不了，应在模型调用前说明需调整输出能力、推理策略或任务范围，不反复发送注定截断的请求。
- PPT 策划作为独立交付阶段也必须处理 `max_tokens`：仅扩大演示策划 Run 的输出预算、重新生成完整策划合同，不重复已完成的研究章节或综合报告；演示结构修复与输出扩容分别计数，硬上限内仍无法完成时保留报告并提示调整模型或演示范围。手动恢复时不能用未改变的模型硬限再次发送同预算请求；调整配置后才继续策划。
- 问答若在 `max_tokens` 时没有正文或仅有部分正文，最多自动扩大两次当前回答的输出预算，不重新运行意图规划，也不把未完成结果存入会话；部分草稿只作为下次完整重写的提示，不复制旧引用。流式界面切换到新尝试时清除上一轮未完成正文，避免把两轮增量串接成伪完整答案。供应商/实际容量封顶；耗尽扩容机会后保留部分输出供用户显式恢复，取消、凭据或其他错误不触发自动扩容。
- 运行检查器区分配置容量、实测容量和应用默认值，展示正文估计、结构/推理预留、实际请求上限、扩容次数和父运行记录；预留与估算不冒充供应商账单。

### 6.5 Wiki 配置

配置按以下层级合并：

```text
系统默认 → 场景模板 → 单书覆盖 → 单次运行覆盖
```

页面必须显示每个最终值来自哪个层级，并支持恢复继承。

#### Agent Runtime

- DeepSeek Harness
- 可执行程序、版本和健康检查
- Profile、最大轮次、并发、超时和取消策略
- 沙箱、网络、Shell、文件系统和审批策略

#### 模型配置

- Provider、Base URL、Model
- API Key 的环境变量或系统密钥引用
- 推理模式、温度、上下文和最大输出
- 超时、重试和 Token 预算
- 可分别配置摄入、问答、维护和研究模型

#### Token 用量

- 支持按日期范围筛选，并按调用方区分知识问答、研究任务等场景。
- 展示总 Token、输入、输出、有效调用、未上报运行、每日趋势和调用方分布。
- 运行时提供 Usage 时保存实测值；运行时未提供时允许按输入/输出文本本地估算，但页面和 API 必须明确标记 `measured`、`estimated`、`mixed` 或 `unavailable`，不得把估算值伪装成供应商账单数据。
- 缓存读取、缓存写入和推理 Token 独立保存；总 Token 不重复叠加属于输入或输出组成部分的桶。

#### 配置文档

以文件式标签编辑，但永久存储在数据库：

- `purpose.md`
- `schema.md`
- `instructions.md`
- `AGENTS.md`

每次保存形成版本；支持差异、恢复和模板重置。

#### Skill 管理

- 内置、导入和自定义 Skill
- Skill 文件树与 `SKILL.md` 编辑
- 版本、来源、内容哈希和权限声明
- 全局启用和单书启用
- 支持按问答、研究、智能编译或全部场景绑定
- 依赖工具检查
- 运行历史和最近使用时间
- 内置 Skill 可查看但不可原地修改，可复制为自定义 Skill 后编辑
- 运行快照必须标明 Skill 是实际注入 Prompt，还是仅作为声明/归因记录

当前已内置：`book-ingest`、`book-query`、`book-lint`、`book-research`、`book-presentation`、`book-synthesis` 与 `markdown-collection`。它们都是受控指令型能力；`book-presentation` 只负责从完整研究报告生成有受众、主线、多版式和逐页证据的结构化演示规格，实际二进制 PPTX 由 Rust 生成器产生。演示规格可以表达受限数据图和中心关系图，但不得补造数值、混合口径或把无关系的要点包装成图。演示策划不获得工具、Shell 或任意文件权限，严格 JSON 合同与证据编号由服务端复核。脚本型 Skill 在独立沙箱、审批和资源配额落地前保持不可执行。

#### 处理策略

- 来源变化检测与自动同步
- 分块策略
- 低风险自动应用范围
- 高风险强制审核范围
- 备份、保留和导出策略

## 7. 阅境轩集成

### 7.1 书架

书架卡片增加轻量状态标记：未建库、构建中、已就绪、有更新、待审核、失败。

卡片菜单增加：

- 建立知识库
- 打开 Wiki
- 问这本书
- 增量同步
- 暂停知识库

添加书籍不默认启动耗时建库。用户可在添加流程中勾选“立即建立知识库”，或稍后从书架和知识库页面初始化。

### 7.2 阅读页

选中文字后的上下文操作：

- 询问
- 解释
- 添加为知识候选
- 创建研究任务

Markdown 带入文件、标题和选中文字。阅读页不常驻复杂 Wiki 面板，避免压缩正文；PDF 阅读不显示这些 Book Wiki 操作。

### 7.3 删除关系

- 删除书籍时询问保留、归档或删除知识库。
- 删除知识库不删除书籍及原始文件。
- 选择保留或归档知识库时，书籍记录采用软删除，仅从书架隐藏，以维持来源、阅读跳转和知识库外键完整性。
- 原书路径失效时知识库进入警告状态，已有知识仍可只读查看。

## 8. 数据权威与导入导出

### 8.1 唯一事实来源

| 数据 | 权威存储 |
|---|---|
| 原始 Markdown | 用户本地文件 |
| 来源版本和抽取片段 | SQLite |
| 知识条目正文 | SQLite Markdown 字段 |
| 论断、关系和引用 | SQLite 结构化表 |
| 对话、任务、审核和运行 | SQLite |
| Purpose、Schema 等配置文档 | SQLite Markdown 字段 |
| Skill 内容和版本 | SQLite |
| Agent 临时配置文件 | 临时工作区，不是权威数据 |
| Obsidian / 标准 LLM Wiki 目录 | 按需导出 |

禁止同时把数据库与 `wiki/*.md` 作为可编辑主存储。

### 8.2 导出

每个知识库支持导出：

- 可浏览的 Markdown Wiki
- 结构化 JSON 包
- 数据库备份包
- 引用清单
- 问答与任务报告

导出是单向快照，不自动反向同步。

### 8.3 备份

因为知识数据库不能从原书完整重建，必须提供：

- SQLite 在线一致性备份
- 迁移前自动备份
- 可配置保留数量
- 恢复前完整性检查
- 单书 JSON/Markdown 可移植导出

## 9. Agent Runtime 产品要求

### 9.1 Runtime 与模型解耦

Harness 是 Agent 执行环境，模型是推理提供方。配置和运行记录必须分别保存。

正式支持 DeepSeek Harness Adapter，不再维护第二套 Runtime 适配器。

### 9.2 DeepSeek Harness

- 作为固定版本的 Node.js Sidecar 运行。
- 使用专用 `obsidianbrain-wiki` Profile，只加载必要插件。
- 通过 ACP/stdio 管理会话、提示、审批和取消。
- 通过 ObsidianBrain 专用工具插件访问知识能力。
- 不使用 Harness 自身存储作为产品业务事实来源。

## 10. 安全与隐私

- 服务继续仅监听 `127.0.0.1`。
- 每次 Agent 运行使用短期、仅限单书和单次运行的能力令牌。
- Agent 不能看到其他知识库，除非跨书任务明确授权。
- API Key 不进入 Markdown、日志、聊天正文或普通数据库字段。
- 原书目录默认为只读。
- Agent 不获得数据库文件路径和 SQL 工具。
- 外部研究默认关闭，只能由用户在单次专题研究任务中显式授权域名和请求额度。
- 外部读取只允许 HTTPS 文本，不跟随重定向；DNS 解析到回环、内网、链路本地或保留地址时拒绝访问。
- 所有外部写操作、权限提升、删除与高风险变更均可审计。
- 日志输出必须对密钥、请求头和敏感路径做脱敏。

## 11. 非功能要求

### 11.1 性能

- 知识库列表首屏 P95 < 300ms，不等待 Agent 或全量统计。
- 单书实体列表 P95 < 200ms。
- FTS 首批搜索结果 P95 < 300ms（十万来源片段规模目标）。
- 打开实体正文 P95 < 150ms，不含外部资源。
- Agent 任务全部异步，不阻塞页面请求。
- 前端长列表必须分页或虚拟化。
- 没有运行任务时不常驻 Harness Sidecar；允许短暂保温，但到期后必须自动退出，使基础应用空闲资源目标不因 Book Wiki 被永久抬高。

### 11.2 可靠性

- Agent 重复提交同一变更不能产生重复实体。
- 所有知识变更在单个 SQLite 事务中提交。
- 崩溃恢复后运行任务不得被误标为成功。
- 来源扫描和摄入支持取消、重试和幂等恢复。
- 版本冲突不得静默覆盖用户修改。

### 11.3 可观测性

每次运行记录：

- 知识库、任务、Harness、模型和版本
- 最终有效 Prompt、字符数和 Prompt 哈希
- 配置文档与 Skill 的内容、版本、权限和快照哈希
- Skill 的应用方式：已注入 Prompt 或仅声明
- 开始、结束、耗时和状态
- 工具白名单、调用摘要和有序事件时间线
- Token 与重试
- 产生的变更集
- 错误类别和可恢复建议

## 13. 验收标准

1. 书架中每本书最多绑定一个知识库，数据库层强制唯一。
2. 两本书同时建库时，实体、会话、检索和 Agent 工具访问完全隔离。
3. Markdown 引用可跳到正确文件、标题和行号。
4. 修改 Markdown 文件后，知识库进入 `outdated`，增量同步只处理变化来源。
5. Agent 生成实体、论断、关系和引用后，必须通过结构校验与事务写入。
6. 高风险变更未经审核不能改变正式知识。
7. 实体支持全文检索、类型筛选、来源筛选、状态筛选和关系导航。
8. 问答回答包含可点击引用；证据不足时不能伪造来源。
9. 研究任务支持排队、进度、取消、失败重试和审核后继续。
10. 配置页可以管理继承关系、配置文档、Skill 和不同任务模型。
11. DeepSeek Harness 可使用 OpenAI/Anthropic 兼容协议接入第三方模型供应商，而不迁移知识数据。
12. 删除知识库不影响书籍和原始文件；删除书籍时必须明确选择知识库处置方式。
13. 数据库备份可恢复出实体、引用、配置、对话、任务和版本。
14. 桌面和手机端均能完成建库、搜索、问答、审核和任务管理主流程。
15. 未显式授权的任务不能看到或调用外部研究工具；已授权任务只能读取允许域名且不能突破请求额度。

## 14. 实施优先级

### Phase A：领域底座

书架正规化、知识库生命周期、来源模型、数据库迁移、备份和基础 API。

### Phase B：摄入闭环

Markdown 抽取、增量检测、变更集、审核、实体/论断/关系/引用和 FTS。

### Phase C：DeepSeek Harness

Sidecar、专用 Profile、工具桥、Skill 物化、运行队列、进度、取消和权限。

### Phase D：五个新页面

知识库、Wiki 工作台、书籍问答、研究任务、Wiki 配置及阅境轩联动。

### Phase E：导出与恢复

跨书查询、Markdown/JSON 导出和完整恢复验证。

### Phase F：旧模块移除

路由迁移、旧前后端删除、文档与产品介绍更新、性能与移动端回归。
