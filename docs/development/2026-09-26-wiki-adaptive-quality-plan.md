# Book Wiki 自适应质量优化实施计划

日期：2026-09-26。依据 REQ-08 / DEV-08，以及产品所有者对知识库、Wiki、问答、研究任务的整体优化要求。

## 目标与边界

- 根据问题范围、证据缺口和交付目标动态分配候选、取证、上下文、输出与总执行预算，不把所有场景写死为同一个 top-k。
- 保留 DeepSeek Harness 原生 Agent Loop、流式、Skill 和压缩能力；应用负责业务状态、数据、权限、预算与证据。
- Markdown 原书只读，SQLite 唯一权威；PDF 不进入 Wiki，PPTX 只需可靠生成和下载。
- 所有验证使用临时书架、临时 SQLite / mock Runtime；不覆盖真实书架、不修改真实知识库、不提交密钥。
- 每批先写测试、实现、自审、验证后单独提交本地；不自动推送。无关用户修改保留。

## 批次 1：可靠性与预算基础

1. 为预载和工具补查证据分配同一 Run 内稳定引用编号；记录对象版本和实际可见文本范围。搜索候选不等于已读证据。
2. 最终引用、问答历史、保存到 Wiki、研究结果回看统一使用证据账本，支持来源更新后回看历史快照；回写前验证当前版本。
3. ACP 返回结构化完成状态，非空但 token 截断不得伪装完成；保留可见部分并明确告知。
4. 模型配置增加上下文、最大输出和推理能力，输出上限/推理/重试独立设置；能力与用量出现在运行检查器。
5. 计费 Usage 与上下文占用分开，能测量则保存实测；不能测量则明确估算范围，不伪造全轮用量。
6. 本次失败不永久禁用后续对话；用户取消/凭据拒绝/服务故障区分处理，保留已有流式文本。

验收：工具新增证据引用可点击、保存/回看不丢；跨书/未读/版本不匹配引用拒绝；截断与正常结束可区分；第二轮可从临时失败恢复；老数据库迁移无损；供应商能力往返一致。

## 批次 2：自适应问答

1. 轻量规划输出目标、约束、子问题、证据类型与回答深度；大小目录按 token /主题规划，候选数量随问题变化。
2. 提供分层预算策略（起始软预算、按缺口扩展、模型/成本/时间硬上限），覆盖规划与工具增长，不只计算初始 Prompt。
3. 提供证据覆盖与预算反馈工具，由 Harness 自主多轮补查；扩大预算不扩大 scope、网络和写权限。
4. 候选目录与最终回答隔离；结构化会话记忆保存用户目标、约束、未解决问题，旧回答不自动变证据。
5. 按复杂度组织答案，截断时支持明确恢复；记录选择、扩展和停止原因。

验收：跨章问题可召回超过原固定数量；简单问题不被强制多轮；目录不污染最终上下文；追问保留约束；缺证明确停止；权限和硬上限不可突破。

## 批次 3：知识库与 Wiki 质量

1. 结构化 Markdown 切分与定位，保留标题路径/相邻上下文，避免拆断表格、公式与代码；搜索返回命中附近文本。
2. 编译知识包含导航、知识正文和原子证据三层，按实体类型保留机制、步骤、条件、公式与反例，不强制压缩成同一短摘要。
3. 各批检索相关已有实体并维护主题身份；跨批归并、关系/冲突检查与覆盖报告，动态编译批次与输出。
4. 来源变更建立派生影响与过期标记；区分扫描、分析、候选待审核、正式可用及无实质变化。

验收：公式/表格/步骤完整；后批主题可对齐非前 20 个实体；同义归并与条件差异保留；来源变化影响可见；增量/审核/人工保护/事务不回退。

## 批次 4：可恢复研究交付

1. 持久化研究目标、子问题、证据矩阵、分主题结论、报告与核验结果；它们是业务成果，不是隐藏思维链。
2. 动态研究预算，按阶段/章节恢复；review 输入具体主张、refresh 比较旧版依据，报告与演示策划指令分离。
3. 长报告分主题交付并统一术语/引用，PPT 输入按报告结构选择而非只取开头；已完成成果在失败时保留。
4. 运行检查器与任务页面展示真实阶段、范围覆盖、预算与未完成项；复用 Harness 扩展点，不另造 Agent Loop。

验收：阶段失败恢复不重做已完成阶段；核验与刷新有真实输入；长报告后段关键证据进入演示；取消/租约/重试安全；研究和 PPTX 均可回看/下载。

## 每批验证与最终审计

- Rust：`cargo fmt -- --check`、`cargo clippy -- -D warnings`、`cargo test`。
- 前端：`npm test`、`npm run build`；涉及交互时验证桌面和手机界面。
- 样例覆盖定义、跨章比较、公式推导、全书总结、多轮追问、证据不足、运行失败和恢复。核查必要证据覆盖/引用/完整性，不将篇幅增长当质量提升。
- 真实模型验证只在可用配置下进行，记录模型、预算、结果和用量性质；不可用时明确说明验证边界，不把 mock 结果宣称为真实模型质量证明。
- 逐项核查本计划全部要求及真实权威状态后才能标记整体完成。
