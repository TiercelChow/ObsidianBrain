# 移除 Wiki 数据保护入口与清理历史快照

## 范围

- 桌面端删除数据保护导航，手机端删除对应信息流卡片。
- 删除快照列表、创建/下载/恢复、该分区内的单书导出控件及仅供其使用的前端接口、状态、样式。
- 旧 `?section=protection` 链接回落至运行配置，不产生快照请求。
- 更新产品文案与使用手册，保留其余五类配置及现有 Skill 阅读交互。
- 保留基础设施层迁移、删库和大变更前的自动安全备份，以及 Agent Run 的审计快照；不修改数据库结构。

## 实施与验证

1. 先更新回归测试，确认旧实现不能满足无数据保护分区、五张移动卡片的要求。
2. 删除前端专属实现，更新隔离浏览器验证及产品文档。
3. 核实运行进程打开的数据库、快照命名、SQLite 文件头及占用情况，只把确认的历史数据库快照（含旧照片迁移快照的 sidecar）移入独立废纸篓目录。
4. 运行前端测试、类型检查与构建、模拟后端的跨端浏览器验证，以及网站测试与构建。测试不得连接真实后端或改变用户数据。
5. 自查差异，确保真实数据库、书架、照片、任务与运行审计未改动，保留已有未提交修改。

## 备份说明

历史快照清理是一次性操作，不在每次启动时执行。SQLite 快照不包含照片及 PPTX；用户如需完整备份，应退出应用并复制整个系统数据目录，原书目录另行备份。

## 验证结果

- 更新回归测试后，旧实现在页面残留和选择框数量检查中失败；实现删除后通过。
- 前端 464 项测试通过，类型检查与生产构建通过。
- 独立模拟 API 的浏览器验证通过：320、390、667、769、900、1100、1440 像素视口、旧分区链接回落、空书架、暗色与减少动态效果，以及配置文档与完整 Skill 阅读；全过程未调用快照接口。
- 网站 59 项测试与生产构建通过；未修改后端和数据库结构。
- 实际运行进程使用的数据目录中确认 9 份 SQLite 历史快照和 2 个附属文件，共 2,263,363,584 字节；验证文件头、活动数据库身份与文件占用后移入用户废纸篓的独立目录。原快照目录为空，活动数据库未移动。没有清理运行审计或照片。
