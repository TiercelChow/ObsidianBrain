# 研究阶段兼容迁移与错误修复边界

## 根因

只读检查已应用 v51 的数据库发现，研究阶段 `kind` 的 CHECK 约束仍为
`plan/section/report/validation/presentation`，缺少后续加入的 `synthesis`。
修改原迁移文件不会升级已应用该迁移的数据库。研究规划第一次返回合法 JSON，
但事务创建综合阶段时失败；应用将数据库错误送入模型格式修复，第二次返回多余
`kind` 字段，导致最终错误遮蔽真正原因。

## 实施与验证

1. 先用临时数据库复现旧 v51 约束，补充升级、已有成果/历史版本保留、外键与重复启动测试。
2. 补充研究运行测试：存储故障不得再次请求模型；真实 JSON 合同错误仍最多修复一次。
3. 新增 v52，不改写 v51。事务重建阶段表，先保存并重建依赖的历史版本表，
   防止外键级联删除版本。保留规划、正文、证据、运行身份、租约、基线和书架。
4. 格式修复仅限知识合同校验失败，且当前执行器仍能写入失败检查点；
   数据库/运行故障、取消或失去阶段所有权直接返回原错误。
5. 更新开发设计；执行针对性测试、cargo fmt、cargo clippy 和完整 cargo test，审查并简化。

不操作真实用户数据库，不启动真实模型调用。新版启动时由既有迁移流程先备份，
再执行兼容迁移；用户可恢复失败研究任务。项目指定的调试/TDD 等技能未在当前
技能目录提供，采用相同的定位、红绿测试和完成前验证流程。
