# PDF 清晰度与手机阅读空间优化

范围：阅境轩 PDF 查看器；不改书架数据、PDF 原文件或 Markdown 布局。

## 问题与方案

- 适宽固定减 40px，与手机实际 padding 不一致；改为按实际容器可用宽度计算，手机 PDF 面板取消双重边距。
- 手机默认全页适宽使 PDF 自带空白进一步缩小正文；有可靠文本边界时温和聚焦正文（最多 1.4 倍）。原页面仍可横滑访问，不裁掉图表、页边注或扫描图。文件名按钮恢复整页适宽。
- 放大后全页画布触及 4M 像素预算会软化；保留有界全页底图，对可见区域追加高清小画布。底图/精细层串行绘制，离屏回收，保留旧图直至新图完成。不得取消预算、为整本书保留高清画布。
- 放大上限由适宽 2 倍提升到 4 倍，支持双指跟手预览、松手高清重绘、双击放大/适宽。锚点按页内坐标保存，不拼接整份文档比例；旋转屏幕重新计算适宽基线。
- 手机继续保留顶部书架/阅读切换，底部四个大图标与自动隐藏规则不变。横向平移只属于 PDF，不影响 Markdown 表格滚动或根导航。
- 混合尺寸 PDF 按实际页面尺寸更新占位，不将所有页强制拉伸为首页尺寸。

## 实施和验证

1. 为实际适宽、正文聚焦、4 倍缩放、页内锚点、可视高清区补失败测试。
2. 完善渲染与回收队列，补触摸交互及手机空间样式。
3. 用隔离、只读 PDF 夹具检查 320/390px 和桌面，验证放大、横滑、返回、主题、页码及离屏回收。
4. 全部前端测试、类型检查和构建；审查取消任务/计时器/监听器与预算上限。

浏览器窄视口不能替代真机触摸与帧率验收。扫描件原始分辨率不足无法凭渲染恢复细节；本次消除查看器导致的额外模糊。

## 验证记录

- 352 项前端测试通过；类型检查和前端构建通过。
- 隔离只读夹具包含 14 页原生文字/细线和一张横版页，不调用真实书架写入接口。
- 390×844 / 320×740：正文面板满屏宽，普通模式保留书架切换；320px 沉浸模式文档区域为 320×740，外层页面没有额外纵向空白。
- 模拟渲染器 3× DPR（浏览器自身显示密度仍为 1×）：250% 时底图 1680×2380（约 4M 像素），可见高清区 1347×2448（449×816 CSS px，3× 密度）。不是为整页分配 3× 高清画布。
- 翻至第 7 页，首页画布已回收至 1×1，只保留附近 4 页；横版页保留实际宽高比；横向滑动能够回到页面左缘。
- 桌面 1440×900：适宽画布为 2× 密度，缩放控件没有超出顶部栏；浅色/深色/护眼主题可切换。
- 尚未进行 iOS/Android 真机双指、系统返回、低内存及帧率测试；不以窄视口或模拟 DPR 代替真机指标。

参考：[PDF.js 高清画布示例](https://mozilla.github.io/pdf.js/examples/)，使用安装版本 4.10.38 的本地类型定义核实渲染参数。
