# Wiki 手机端布局优化

范围：书籍知识库、Wiki 工作台、问答、研究任务、配置及相关弹窗；不改动数据、编译与检索逻辑。

## 实施

1. 用隔离 API 和长标题、长路径、研究阶段数据复现手机布局，新增回归约束。
2. 共享导航五项完整可见，统一 44px 触摸目标、16px 输入字号、安全区及弹窗内容滚动。
3. 知识库统计收紧，书籍主体使用完整宽度；次要操作进入底部抽屉，编译进度仍在卡片可见。
4. Wiki 单列实体阅读：返回入口始终保留，阅读时隐藏重复搜索工具；元信息、长路径、审核与图谱保持可访问。
5. 问答只常驻知识库选择和历史入口，把历史／Runtime 边界放入抽屉；对话占据余下视口，输入不被导航遮挡。
6. 研究任务正文全宽、底部操作；阶段目录可折叠，选中后聚焦成果。配置用紧凑分区选择替代横向长菜单，消除重复容器内边距和长文本溢出。
7. 前端测试、类型检查与构建；隔离浏览器验收 320、390、短屏与桌面，检查五页和弹窗。

## 约束

- 复用现有 MotionModal 的底部抽屉及降级动画，不新增动画库。
- 不隐藏唯一操作入口，不更改桌面信息结构。
- 真实书架、SQLite、凭据与模型均不参与测试；所有 API 在本地隔离测试中 mock。
- 本次只实施和验证，不自动提交。

## 2026-10-15 知识库卡片入口调整

按用户补充要求，本次卡片入口调整仅限手机端；电脑端保留原来的纯文本标题、底部「打开 Wiki」、建立和维护快捷按钮，不增加右上角三点或整卡跳转。复用系统 `usePhoneViewport` 的断点，旋转／调整窗口时同步切换。

后续电脑端仅重新分组和对齐上述按钮，见[桌面卡片操作布局](2026-10-15-knowledge-card-desktop-actions.md)；不影响本节手机入口。

按 apple-design 的分端交互一致性和减噪原则，将手机已初始化卡片的标题设为原生 Wiki 链接，并以伪元素扩展到卡片主体，支持键盘、新标签页和整卡点击。更多操作置于卡片右上角；更多与编译进度中的操作位于链接上方，不能触发跳转。不将含按钮的卡片伪装成另一个按钮，不自动建立知识库。手机端移除整行底部按钮；未初始化卡片的「建立知识库」收进三点菜单，点击后复用原初始化流程。

执行顺序：先补失败回归，最小修改模板和共享断点样式，再全量测试、构建、隔离浏览器核对整卡跳转、更多不跳转、未初始化入口、长标题、窄屏和桌面。工作流 TDD/计划/验证技能当前不可用，执行等价流程；保持已有未提交修改，不操作真实数据、不自动提交。

本次验证：先确认分端行为的 4 项回归失败，修正后全量前端测试 448 项通过，类型检查与生产构建通过（既有大包提示保留）。隔离浏览器验证 1280px 电脑保留建立／打开与维护按钮、无整卡链接和三点；390px 手机无底部按钮行、三点可打开含建立入口的抽屉、已初始化卡片可进入对应 Wiki；320px 长标题无重叠／横向溢出，切回电脑宽度可恢复原入口。全部使用内存 mock，无真实建库、编译或数据修改。
