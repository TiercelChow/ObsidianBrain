# Wiki 手机端布局优化

范围：书籍知识库、Wiki 工作台、问答、研究任务、配置及相关弹窗；不改动数据、编译与检索逻辑。

## 实施

1. 用隔离 API 和长标题、长路径、研究阶段数据复现手机布局，新增回归约束。
2. 共享导航五项完整可见，统一 44px 触摸目标、16px 输入字号、安全区及弹窗内容滚动。
3. 知识库统计收紧，书籍主体使用完整宽度；次要操作进入底部抽屉，编译进度仍在卡片可见。
4. Wiki 单列实体阅读：返回入口始终保留，阅读时隐藏重复搜索工具；元信息、长路径、审核与图谱保持可访问。
5. 问答只常驻知识库选择和历史入口，把历史／Runtime 边界放入抽屉；对话占据余下视口，输入不被导航遮挡。
6. 研究任务正文全宽、底部操作；阶段目录可折叠，选中后聚焦成果。配置用紧凑分区选择替代横向长菜单，消除重复容器内边距和长文本溢出。
7. 前端测试、类型检查与构建；隔离浏览器验收 320、390、短屏与桌面，检查五页和弹窗。

## 约束

- 复用现有 MotionModal 的底部抽屉及降级动画，不新增动画库。
- 不隐藏唯一操作入口，不更改桌面信息结构。
- 真实书架、SQLite、凭据与模型均不参与测试；所有 API 在本地隔离测试中 mock。
- 本次只实施和验证，不自动提交。

## 验证

- `cd frontend && npm test`：221 项通过。
- `cd frontend && npm run build`：通过类型检查与生产构建（保留现有大包提示）。
- `verify-wiki-reliability.mjs` 默认模式：桌面／手机的问答历史引用、截断恢复、编译报告、审核与研究阶段流程通过。
- 同一脚本设置 `WIKI_MOBILE_LAYOUT_ONLY=1`：320×568、390×844、667×375、1440×1000 的五页、六个配置分区、操作抽屉及长表单通过；覆盖下拉日历宽度及模拟键盘 visualViewport 缩小。
- 浏览器验证使用隔离 Vite 服务、内存 API 和外部请求拦截，无真实数据库或模型调用；不等同于 iOS／Android 真机测试。
