# 独立本地存储与时光机完整生命周期

本方案覆盖旧的 Timeline/Infra 文档中的 Obsidian 存储约定，2026-10-04 起以此为准。

## 边界

- 产品不再连接 Obsidian、使用插件、发起健康检查或同步回写。旧的笔记搜索工具退役，书架、Wiki、任务、代码仓数据不变。
- SQLite 是小记唯一权威数据。原图永久保存在数据库同级 `timeline/images/`，缓存独立保存在 `timeline/cache/`。
- 只复制旧小记已引用的图片；保留小记 ID、日期、内容和标签。不删旧库文件，不从 Markdown 同步覆盖用户的修改或恢复已删除记录。
- 不在每次启动时尝试迁入。迁入仅由存储面板或一次性 CLI 显式触发，启动/定期维护只负责本地 GC 与缓存。
- 原图不属于缓存。缓存默认 256 MiB，按字节而非张数限制，读取更新 LRU，超限淘汰最久未使用的缩略图。单张超过预算则不缓存。
- 默认 brain.db 使用同级 timeline；自定义数据库名使用独立 timeline-<文件名哈希>，避免多个数据库同目录时 GC 互相误删。相对数据库路径也只使用其同级目录，不回落到全局用户目录。

## 完整性

1. 上传使用 UUID 名称、临时文件落盘后原子发布，验证图片格式、尺寸与路径；原文件名不作为落盘路径。
2. 编辑/删除通过 SQLite 事务维护小记、版本和持久化待清理队列。并发编辑携带版本令牌，冲突不覆盖。
3. 删除/移除附件只有在没有其他小记引用时才删原图和缩略图。失败保留清理队列并提示，启动与定期维护重试。
4. 未发布上传作为暂存资源，取消立即释放；异常中断的未引用暂存 24 小时后回收。
5. 旧图从原保存路径安全复制，不修改原记录引用。缺图保留记录，页面展示缺失数并提供重新选择旧目录、重试迁移入口。
6. 导出/备份必须明确区分数据库快照与完整数据目录：SQLite 备份不含原图，迁移前自动数据库快照；完整备份复制数据库和 `timeline/images/`，缓存无需备份。

## 交互

- 小记右上角统一操作入口，桌面编辑/删除，手机底部操作抽屉；编辑复用写小记面板，保留时间、标签和已上传图片。
- 删除确认明确告知不可恢复及图片清理规则，失败不提前移除卡片；保存期间阻止重复提交和误关闭。
- 首页仅保留系统状态与数据概览；时光机「图片存储」展示实际目录、原图大小、缓存大小/容量与迁移状态，提供容量配置、清缓存和旧图片导入。首页原有的存储/通用 LLM 配置卡片、配置请求与专属样式移除，已有配置不删除；模型供应商仍由 Wiki 配置管理。

## 实施顺序与验证

1. 先写资产隔离、LRU、共享引用、失败重试、迁移路径安全和编辑冲突测试。
2. 本地图片存储、数据库迁移、持久化垃圾回收；替换上传与图片读取。
3. 小记 CRUD 工具与前端编辑/删除、上传失败/取消处理。
4. 移除 Obsidian 运行时、配置和旧工具，更新手册。
5. 独立临时数据目录验证上传→创建→编辑→删除和原图/缓存完整清理；前端类型检查、测试、构建以及 Rust fmt/clippy/test。

测试只使用隔离数据，不自动提交或重启用户服务。实际旧图迁移必须得到用户明确授权，核实正式数据库及来源，先备份，再复制和校验；源文件不删除。

### 一次性迁移补充

- 按用户要求移除启动时的旧图导入，只保留显式手动迁移；启动/定期维护只处理系统内原图清理和缓存。
- 新增一次性 CLI，缺少数据库/目录时不创建数据库；在线快照先于 schema 与图片写入，FTS 校验在私有快照进行，已有备份不裁剪。
- 新增 3 项 CLI 测试：参数、输入边界、只复制与记录保留/重复执行；全套 Rust 572 通过、6 项原有忽略，fmt、clippy 与 release 构建通过；官网 38 项测试与构建通过。
- 用户明确授权后完成正式数据迁入：38 张原图（193002344 字节）逐张 SHA-256 一致，无缺失、无待清理项；30 条小记以及 30 张业务表与迁移前一致快照核对无变化，供应商配置保留。
- 旧库文件与所有已有快照保留。正式服务仍为原运行进程，未安装替换、重启或提交代码。
