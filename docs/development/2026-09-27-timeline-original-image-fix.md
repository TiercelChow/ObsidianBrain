# 时光机原图加载修复

## 根因与范围

只读实测：缩略图缓存返回 200，原图代理返回 404。原始照片仍存在；直接请求 Obsidian 的 `/vault/Timeline/images/...` 返回图片，整条路径编码后的 `/vault/Timeline%2Fimages%2F...` 返回 404。

修复共用 Obsidian 客户端的路径段编码，保留目录分隔符，统一二进制读写、笔记读写及目录访问。图片、小记、数据库与用户配置不迁移、不删除、不重建；不增加绕过 Obsidian 的本地原图读取。

## 实施计划

1. 更新路径单元测试，并增加 wiremock HTTP 回归：多级图片、中文及 URL 保留字符、上传与读取路径一致、真实 404。
2. 确认旧实现失败，按路径段编码后重跑测试。
3. 执行格式、Clippy、完整后端测试及构建；临时隔离数据目录验证原图代理和桌面／手机预览。
4. 自审共用调用点与改动范围，保留无关 `CLAUDE.md` 修改；不自动提交、推送或替换运行中的服务。

项目要求的调试、计划、TDD 与验证流程技能不在本会话可用目录，按对应的根因验证、失败测试、最小实现、回归与自审流程执行。

- `cargo fmt --check`、`cargo clippy -- -D warnings`、完整后端测试与开发构建通过：447 项通过，3 项既有集成／规模测试忽略。

- 使用临时数据目录和数据库启动新版后端，三张实际照片的原图代理均返回 200，JPEG 类型正确，SHA-256 与原始文件一致。正式服务、数据库、图片和小记未被替换或改写。
