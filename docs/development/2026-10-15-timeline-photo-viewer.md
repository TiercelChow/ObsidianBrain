# 时光机图片查看交互修复

## 根因与边界

依据顶层设计、REQ/DEV-04 与全局 UI 方案。现有 panzoom 的 smoothZoom 接受父容器局部坐标，但按钮传入页面坐标；图片同时由 flex 居中和左上原点的矩阵定位，坐标模型不统一。缩放下限 0.1 允许图片消失般缩小，入场 CSS 也写入同一 transform；没有独立的手机切图手势。

只更改前端查看器，不读写真实小记、原图、缓存和数据库。不改变原图读取、失败重试、焦点管理、页码与工具栏独立占位。旧原图迁移文档只是历史背景，不恢复 Obsidian 访问。

## 方案与步骤

1. TDD：先覆盖适屏尺寸、中心/指针锚定缩放、最小/最大缩放、拖动边界、左右滑动、回弹、双指缩放、手势取消和快速反向操作。
2. 查看器使用唯一局部坐标模型。首次显示及重置适屏居中；缩放限制为适屏 1–8 倍，按钮围绕画布中心，滚轮/双击/双指围绕交互点。缩放后拖动不能移出整个视口。
3. 适屏单指左右拖动跟手切图；放大后单指只平移；双指用于缩放，双指转单指不会误触翻图。相邻页只展示缩略图预览，不预加载多张原图；释放按距离/速度判定，通过连续弹簧接续，取消则回弹。
4. 保留桌面箭头、键盘、缩放/重置、手机按钮和安全区；只让外层遮罩淡入，避免 CSS 与照片变换竞争。减少动态效果立即落位。
5. 全量前端测试、构建、源码自审；使用隔离图片夹具验证桌面和手机尺寸、中心稳定、缩放/重置、前后切换、错误恢复及页码/底栏不重叠。手势状态用可控时钟自动测试，尺寸模拟不宣称真机触屏测试。

使用 apple-design 的直接操作、空间一致性、速度交接与减少动态效果原则。所要求的调试/TDD/计划/验证技能不在可用目录中，执行等价流程，不委派子任务。

## 验证结果

- 新增 14 项几何/运动/手势行为测试及 2 项页面接线合同；全量 440 项前端测试和生产构建通过，仅有既有大分包提示。
- 1280×720 隔离浏览器中，放大前后图片与画布中心均为 `(640, 334.5)`；缩小回到适屏，重置、横竖图切换与关闭正常。
- 390×844 尺寸下双向拖动切图成功；放大后纵向拖动仍保留当前页，重置后居中；竖图底部 735px、序号底部 776px、按钮顶部 788px，互不重叠。320×640 无页面横向溢出。
- 缺失图片显示错误与重试，仍可切回正常图片。测试也覆盖加载过程中切图、快速反向、指针捕获丢失、多指转单指及取消；清除一条遗留减少动态效果 CSS，避免覆盖照片定位。
- 验证仅用内存夹具和生成图片，不访问或改动用户小记、原图、缓存、数据库；浏览器拖动和尺寸模拟不能替代 iOS/Android 真机双指操作、软键盘及帧率验收。
- 自审保留前序未提交的无边框图标、页头、搜索栏及 Wiki 改动，未提交或推送。
