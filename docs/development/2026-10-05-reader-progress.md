# 阅读状态统一存储修复

## 合同

- SQLite reader_books.progress_json 为权威状态，保留兼容的 lastFile/position/pageCount/updatedAt，增加 byFile（带 kind 和位置更新时间）及 lastReadAt。无需破坏性迁移或扫描原书。
- 新工具 save_reader_progress 只更新一个活动书籍的状态；按文件时间戳合并增量，旧请求不能覆盖新位置。lastReadAt 独立于位置，成功打开即更新，不重置已保存位置。
- save_reader_books 是书架元数据操作，已有阅读状态不会因字段缺失或陈旧请求而被清空。
- 浏览器 localStorage 保留作恢复缓存；首次加载阅读器时按时间合并旧缓存与服务器，迁移失败保留副本并提供重试，不删除任何旧记录。
- Markdown 滚动停止 1.5 秒后写入；切换文件/书籍/视图/路由之前立即采集，后台和关闭页保留同步本地副本。PDF 成功加载后记录打开，按实际可见页写入，恢复跳页不记录中间页；文件夹中的 PDF 属于当前文件夹书。
- 顺序写队列合并高频增量，失败保留待写数据。主页监听保存完成刷新摘要，不加载整本正文或全书架，不写数据。
- API 验证文件归属、类型、位置、时间与体积边界；只更新数据库，不读写文档磁盘文件。删除书架书籍后，不接受迟到的进度写入。

## 实施与验收

1. 测试先行覆盖位置/阅读时间拆分、MD/PDF 文件归属、服务器/旧缓存合并、失败重试、写入顺序、元数据保护。
2. 单书增量 Tool 与事务合并存储，保留旧进度格式并投影为现有首页摘要。
3. 共享书架加入写队列、缓存合并与同步错误，Reader 修复打开/切换/恢复事件边界；首页接收保存通知。
4. 前端测试及类型构建、后端测试/格式/零警告检查；隔离 UI 验证阅读→首页，不启动或替换真实服务，不接触用户数据库。

## 验证结果（2026-10-05）

- 前端类型检查与生产构建通过；379 项测试通过。
- 后端完整测试：586 通过，6 项既有外部依赖测试忽略；格式检查和 Clippy 零警告通过。自审后又通过 5 项阅读状态专项测试。
- 临时 SQLite 的真实 HTTP 集成覆盖：写入逐文件状态 → 首页最近阅读摘要 → 修改书名 → 再读取书架，进度和原有章节均保留。
- 隔离浏览器以合成目录验证：Markdown 滚动到 1440px 后立即切章，返回原章恢复到 1440px；首页仅展示实际打开过的书籍，阅读时间及时更新。
- PDF 覆盖文件夹/独立书归属、页码校验、逐文件持久化、恢复过程及迟到事件来源保护；未用用户的 PDF 或数据库进行端到端测试。
- 未改动用户运行中的服务或真实记录。新版首次进入阅境轩时才会合并当前浏览器旧缓存；不属于现有书籍的旧缓存仍在一次性备份中保留。
