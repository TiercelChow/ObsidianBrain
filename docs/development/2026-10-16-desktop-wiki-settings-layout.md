# 桌面 Wiki 配置：导出与 Skill 阅读布局

## 问题与范围

只调整电脑端（>768px），保留手机信息流及抽屉交互。单书导出的 Grid 列可收缩，但 `.knowledge-select.is-compact` 仍保持 220px，导致控件侵入下载按钮。Skill 的文件、版本说明、两种评测全部放在右侧正文上方，正文样式又没有穿透 MotionSwap 包装，造成拥挤、溢出与低效阅读。

## 方案与顺序

1. 先补导出控件不重叠、桌面正文有界、元数据默认收起及手机保持原交互的失败回归。
2. 桌面导出采用说明与操作两层布局。选择器占据可收缩的剩余列；窄容器主动分行，下载按钮不能被覆盖，不修改导出接口。
3. Skill 桌面弹窗适度加宽，顶部显示名称与说明。左侧为文件目录、权限和版本；右侧为文件信息、独立滚动正文，版本与评测放在可展开的次要区域。保持头部、操作区可见，不新增阴影或多层毛玻璃。
4. 复用当前弹窗与 MotionSwap，桌面正文显式建立 flex/min-height/overflow 链；手机仍为原来的文件导航、元数据开关和单滚动抽屉。
5. 全量测试、类型检查、生产构建；隔离浏览器检查 900/1100/1440px 与短窗口、长文件名、完整正文末行、元数据展开及手机回归。

## 约束

- 不改变 Skill 内容、版本、权限、发布流程及备份/导出行为。
- 使用内存 mock，不访问真实模型、凭据、数据库，不自动提交。
- apple-design 用于阅读优先的层级和分组；当前计划/TDD/验证/审查技能不可用，执行等价流程。

## 验证结果

- 先确认 3 项布局回归失败；隔离浏览器复现导出选择框与 JSON 按钮水平重叠约 53px。
- 修复后全量前端 462 项测试通过，类型检查与生产构建通过，保留既有大包提示。
- `scripts/verify-mobile-wiki-settings.mjs` 扩展为手机及桌面共同验收：769×700、900×700、1100×800、1440×1000、1440×600 的导出区无重叠；弹窗实际宽度正确应用 1080px 上限，正文独立滚动到最后一行，长行不横向溢出，文件切换、元数据展开和候选版全部底部操作可达。
- 文件导航以文件名为主、路径为辅，长名称最多两行，完整路径在按钮 title 和选中文件头部保留；导航使用平面选中态，不叠加玻璃阴影。增加实际样式断言，避免被全局材质样式覆盖。
- 320×568、390×844、667×375 的既有手机卡片／抽屉与切库检查通过；另核对桌面和手机暗色、减弱动画、空知识库与分区链接。
- 已目视检查导出区、默认阅读弹窗、暗色元数据展开和短窗口。使用内存模拟 API，未读取或修改真实数据、凭据、模型。隔离浏览器和服务均已关闭。
