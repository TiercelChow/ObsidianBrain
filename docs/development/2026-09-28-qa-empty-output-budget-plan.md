# 问答无正文输出截断的预算与恢复

## 证据与目标

只读检查最近失败的问答 Run：请求上限 13912 tokens，规划正文估计 7000、推理策略 auto，ACP 返回 `stop_reason=max_tokens` 且没有 `run.text_delta`。目前研究阶段能扩容，但问答只提供有正文草稿的手动恢复；无正文时不能继续。

目标：为问答初始输出预留推理空间；仅在确认为无正文的 `max_tokens` 后，有界地扩容并重做本轮回答，不重新规划，不接续不完整引用。已发出正文的截断继续沿用用户显式恢复；能力上限、取消、凭据和其他错误不自动重试。

## 实施步骤

1. 添加预算和 Fake Runtime 红灯测试，覆盖无正文自动扩容、供应商硬限停止、有正文不自动重跑和父子 Run 记录。
2. 为问答加正文/推理分离的初始预留，按配置和实测容量计算；最终阶段无正文截断最多两次独立重试，每次生成新 Run、重新装配当轮证据，结果只在成功后保存到会话。
3. 检查器记录扩容原因和父 Run；前端无正文时给出准确提示与重新提问入口。更新 Wiki 需求/开发说明。
4. 完整运行 Rust fmt、clippy、test、build 与前端测试和构建；不调用真实模型、不修改用户数据库。

项目列出的调试/TDD/验证 Skill 当前未提供，按同等红绿回归和自查流程执行。

## 实施结果与验证

- 初始问答把正文估计与有界推理余量分别计算：例如单主题正文估计 7000、
  推理策略 auto 时请求上限 21000；推理关闭时仍为 7000，明确供应商上限优先。
- 只有 DeepSeek Harness 明确报告 `max_tokens` 且未返回正文才在原问题的最终回答
  阶段自动重试，最多两次。扩容使用新 Run 和新的已读证据编号，规划结果保留，
  已有正文的截断仍留给用户显式恢复。ACP 观测容量进一步收紧下一次请求。
- 检查器保存父 Run、实际请求、扩容事件及有效上下文；流式状态提示扩容，最终
  没有正文时显示准确说明和重新提问入口。失败尝试不写入正式会话。
- Fake Runtime 回归覆盖无正文截断后成功、连续截断有界停止、输出硬上限停止、
  部分正文不自动重播、ACP 实测容量和父子 Run 可追溯。
- `cargo fmt -- --check`、`cargo clippy -- -D warnings`、`cargo build` 均通过；
  `cargo test -- --quiet` 为 447 通过、3 个既有测试忽略。前端 `npm test` 为
  267 通过，`npm run build` 通过（既有 Rollup 警告仍存在）。
- 仅只读检查用户最近失败 Run 的技术元数据，没有修改用户数据库或调用真实模型。
