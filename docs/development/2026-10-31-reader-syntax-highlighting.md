# 阅境轩代码高亮恢复与三主题配色

## 问题与边界

Markdown 解析器为代码输出 `class="hljs language-…"`，但 DOM 增强器以 `pre code:not(.hljs)` 查找未高亮代码，导致普通围栏和缩进代码全部被跳过。`.hljs` 是表现类，不是执行完成的证明。

另外，阅境轩的高亮颜色和代码布局依赖 Reader 路由样式；时光机还会加载全局固定 `github-dark.css`，使代码颜色受到入口和路由加载顺序影响。

本次只调整前端代码增强、代码样式和验证，不改变书架、阅读进度、文件内容或数据库。

## 实施顺序

1. 先添加未处理状态和三主题样式的失败回归测试。
2. 按 `data-highlighted` 识别执行结果；依赖加载完成后检查文档代次、连接状态及完成标记，避免重复增强或修改离场文档。明确跳过的语言也记录终态。
3. 将代码布局和 token 配色统一到全局 `syntax-highlight.css`，移除 Reader 内重复样式和时光机固定深色主题。
4. 运行真实 Reader、解析 Worker、路径预览和跨页面浏览器验收，再执行前端全量测试与构建。

## 配色与阅读规则

| 模式 | 代码背景 | 高亮方向 |
|---|---|---|
| 浅色 | 冷灰白 `#f3f5f9` | 紫色关键字、深绿字符串、蓝色函数、赭色数字 |
| 深色 | 墨蓝 `#161d29` | 柔紫关键字、灰绿字符串、浅蓝函数、暖金数字 |
| 护眼 | 灰绿 `#e5eadc` | 低饱和灰紫关键字、苔绿字符串、灰蓝函数、棕色数字 |

以 `apple-design` 的可读性与克制原则处理阅读内容：代码使用稳定底色，不叠加玻璃模糊；三套 palette 独立定义正文、注释、关键字、字符串、数字、函数、类型、变量、标签、元信息、操作符、标点和差异颜色。单测校验每类文字与代码底色的对比度不低于 4.5:1。

颜色规则仅作用于 `.code-block` 和 `.memo-code`；不修改行内代码、LaTeX、Mermaid 的文字。沿用 13px 等宽字体、1.6 行高、固定行号与局部横向滚动。手机不通过缩小字号或强行换行适配。

保留 Highlight.js 常用语言包的动态加载、700px 可视缓冲区、文档切换清理及过期结果门控。不扩大语言全集或引入额外高亮依赖。已高亮的 DOM 在主题切换时只改变 CSS，不重新生成 token。无语言标记沿用自动识别；纯文本和不支持的显式语言安全保留原文。

## 验证

- `frontend/tests/readerSyntaxHighlight.test.ts`：完成标记、动态加载合同、全局样式、路由样式隔离、三主题 token 完整性及对比度。
- `frontend/scripts/verify-reader-syntax.mjs`：独立 5231 端口的只读模拟服务，所有 API 均拦截为内存数据，服务端另外拒绝未拦截的 `/v1` 请求，绝不代理到真实数据库。
- 浏览器覆盖 390px 手机和 1440px 桌面、三种主题、14 类围栏（含纯文本、不支持语言、自动识别），验证 Worker 解析后确实产生 token、离屏懒高亮、源码保真、长代码横滚、公式/行内代码不受影响、代码预览、主题切换复用 DOM，以及先访问时光机再回阅境轩的颜色一致性。
- 2026-10-31：552 项前端测试、类型检查与生产构建通过；上述 Chromium 桌面/手机模拟验收通过，无页面异常。真机 iOS 和其他浏览器未在本次验证。
