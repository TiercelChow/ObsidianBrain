# 手机端 Wiki 配置卡片信息流

## 范围与问题

仅调整 ≤768px 的 Wiki 配置页面及其 Skill 抽屉；电脑端继续使用原导航和单分区编辑。当前手机通过下拉选择分区，操作缺乏可见性；窄屏选择器和图标受自动网格尺寸挤压。Skill 正文被 MotionSwap 包裹，原来的直接子元素样式未命中，长行和内容滚动因此不可靠。

## 实施顺序

1. 先补失败回归：手机六分区同时呈现、桌面单分区不变、选择器宽度与长名称、图标操作对齐、Skill 正文穿透动画包装。
2. 复用同一份配置表单，以共享手机断点呈现六张纵向卡片，不增加手机分区下拉、折叠列表或双份表单状态。
3. 各卡片操作贴近标题或对象，独立图标保持 44px 触摸区域、无边框与可访问名称。手机标题与选择器分行，长知识库名称在选项内换行，保留系统下拉材质。
4. 手机同时展示配置文档与 Skills，知识库切换同步加载两者，拒绝旧响应覆盖新知识库。Token 用量与备份随手机信息流首次加载；已有分区链接定位对应卡片。
5. Skill 抽屉保持头尾可见，中间单一纵向滚动；正文采用明确类名，不依赖直接子元素关系，换行展示长路径和完整指令。复用系统抽屉与减弱动画行为，不新增动画库。
6. 全量前端测试、类型检查、构建及隔离浏览器验收：320/390px、横屏短视口、1440px 桌面；长知识库名称、多文件长 Skill、切库与底部操作可达性。

## 安全边界

- 不修改后端、Prompt、Skill 正文、供应商凭据或用户数据库。
- 浏览器验证仅使用内存 mock，禁止调用真实模型或写入真实书架。
- 不自动提交。计划、TDD、调试、验证和自审技能未在当前目录提供，执行相同流程；apple-design 用于分端布局、分组映射和触摸目标。

## 实施与验证结果

- 手机六个分区使用同一份表单呈现独立卡片；电脑继续只挂载选中分区，没有另建一套配置状态。
- 知识库长名称在控件与选项中换行。保留系统锚定下拉，在 Popper 布局阶段按实际展开方向与 visualViewport 计算可用高度，仅约束内部滚动区；不以偏移覆盖输入栏，也不让列表下缘超出短屏。回归覆盖向上、向下、键盘偏移、最大值和零空间。
- 手机切库同步刷新文档与 Skills，丢弃迟到响应；保留未保存的 Runtime 全局字段。Skill 绑定响应也校验所属知识库，避免污染当前卡片。
- Skill 抽屉正文穿透 MotionSwap 包装应用明确样式，长行换行，中间区域负责唯一主要滚动，底部操作不随正文滚走。
- 先确认原实现的 4 项回归失败；可用高度计算另确认失败后实现。最终 `npm test` 459 项通过，`npm run build` 的类型检查与生产构建通过（既有大包提示保留）。
- `scripts/verify-mobile-wiki-settings.mjs` 隔离浏览器验证 320×568、390×844、667×375、1440×1000：六卡片／桌面单分区、长名称、整个下拉位于屏幕内、最后一个知识库可滚动选择、成组 44px 操作、快速切库、未保存字段、多文件切换、完整 Skill 最后一行、短视口底部操作通过。额外验证空书架、暗色、减弱动画与分区链接定位。
- 浏览器验收使用内存 API，真实数据库、凭据和模型均未访问；不等同于 iOS／Android 真机验收。脚本结束已关闭隔离服务及浏览器。
