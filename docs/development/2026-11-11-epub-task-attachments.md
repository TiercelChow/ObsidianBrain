# EPUB 阅读与任务附件

## 范围

- 阅境轩识别独立 EPUB 和目录中的 EPUB，按章节阅读，支持目录、三主题、阅读进度和书签。PDF、Markdown 的现有优化保持不变。
- 任务及任意层级子任务可上传、下载、移除附件；每条进展也有独立附件区。附件保存在系统数据目录，不依赖 Obsidian。
- 不执行书内脚本，不支持 DRM；EPUB 不自动加入 Markdown Wiki 编译。附件只供下载，不作为可执行内容或自动提供给 Agent。

## EPUB

1. 后端读取 ZIP 的 container.xml → OPF → spine，解析 EPUB 3 nav 或 EPUB 2 NCX。限制压缩包、条目、XML 与章节大小；清理章节 HTML 时限制节点嵌套深度。不将压缩包解压到磁盘。
2. 前端一次只挂载一个章节，同源 sandbox iframe 禁止脚本；资源响应附加 CSP，屏蔽外部网络、表单和嵌套框架。相对资源 URL 保留目录结构，避免图片、字体和 CSS 丢失。
3. 章节跟随系统亮色、深色与护眼模式。阅读样式优先替换书内的文字和容器颜色，链接、引用、表格、代码和选区使用系统色；保留书籍排版与插图原色。切换主题只同步色值，不重新加载章节。图片、表格与代码不能撑破阅读区。目录与前后章按钮复用现有阅读操作。
4. EPUB 进度为 `(章节序号 + 章内比例) / 章节总数`，仅在当前章节加载完成后保存/恢复。书签另存章节路径及章内比例，跳转先切章再定位。
5. 扩展 reader_books.kind 的数据库约束。迁移事务重建表时临时关闭外键，提交前检查完整性，所有路径恢复外键；迁移测试必须保留已有书签和知识库关系。

## 任务附件

- 元数据独立表以任务 UUID、可选进展 UUID 关联，不对每次重写的 task_nodes/task_progress 建立级联删除。
- 上传、列出和下载均检查目标任务和进展归属。每文件最多 50 MiB，每个附件区最多 20 个，总容量上限 1 GiB。
- 上传先预留一条 `uploading` 记录，再流式写入以附件 ID 命名的独立文件；展示名不参与磁盘路径。文件同步完成后才切为 `active`，允许列表和下载。失败清理未完成的文件，下载使用 attachment + nosniff，不内联执行 HTML。
- 移除附件先标记为 `deleted` 并停止展示，再清理磁盘文件，最后删除元数据；失败保留清理记录以供重试。编辑、关闭、归档不删除附件。
- 新进展在表单内直接选择、移除附件，点击记录后统一提交。文字保存后保留进展 ID，再上传文件；部分失败留在同一表单重试，仅重试未成功的文件，不重复创建进展。已保存文字锁定；明确提示部分保存状态，允许移除失败文件或结束本次上传，既有记录仍可补充附件。
- 每个草稿文件有稳定上传标识；后端将任务、进展与上传标识隔离绑定，已完成上传的重复请求直接复用结果，在途请求拒绝并提示稍后重试，防止响应丢失后重复生成附件。中断上传仍由持久化清理状态保护。
- 桌面根任务顶部的信息/附件与下方拆解/进展使用同一组列宽及内边距，右侧标题和按钮与进展区对齐；顶部不画分隔线。手机任务详情和桌面子任务弹窗中的信息、附件纵向单列，使用同一个详情滚动区。
- 手机进展详情填满公共抽屉的宽度，底部安全区由内容面板填充。较长的记录在抽屉内滚动，附件与下载按钮仍可到达。
- 子任务/进展新增动作统一使用等宽高的共享圆形按钮；不使用改变宽高比例的局部样式。
- UI 使用共享图标操作、玻璃材质和抽屉。添加及选择附件统一用回形针，取消上传保持关闭图标。附件行显示文件名、大小、下载和移除操作，长文件名换行，手机端触控区域至少 44px。

2. 实现后端格式和文件接口；再接入书架、阅读器与任务详情/记录弹窗。
