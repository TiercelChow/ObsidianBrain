# 大上下文与阶段独立输出扩容

## 目标与证据

用户同意放宽研究预算。只读运行记录显示：正文预估 3000 tokens 的章节实际申请
4536，返回 max_tokens；多个已完成主题在约 5000–6000 时截断，提高到约 10922
后完成。未声明模型能力时使用 32768 上下文护栏；阶段失败共享任务三次重试，
导致第七个章节首次截断就耗尽机会。

## 计划

1. 红绿回归：未声明能力可使用 1M 应用默认值、真实小容量与输出硬限仍生效，
   正文/JSON/推理分别预留，输出不再被上下文固定比例压低。
2. 抽取共享上下文/输出护栏至 models，统一问答策略和取证网关；未知默认
   1048576，不写成供应商真实容量。用户现有能力配置不覆盖，ACP 实测容量优先。
3. 研究每阶段最多两次 token 截断扩容，格式修复独立一次。只重做当前阶段；
   保存每次 Run、预算变化、父 Run 与部分输出，重建完整 JSON 而非拼接半成品。
   取消、拒绝、权限、数据库故障不借扩容重复调用。扩容耗尽/真实硬限明确停止，
   不继续消耗任务队列退避预算；用户仍可显式恢复。
4. 增加隔离 Fake Runtime 流程测试：多个主题各自截断仍能在一次任务领取中完成，
   格式修复与输出扩容不相互耗尽，无限截断有界停止、取消不重试、成果/部分输出保留。
5. 更新配置页文字和需求/开发设计，运行后端 fmt/clippy/test/build 和相关前端验证。

不重写 Harness Agent Loop，不放宽工具权限，不更改真实数据库/模型配置，
不调用真实供应商。编译/PPT 另有独立合同；PPT 选材受益于共享的大上下文默认值，
本次不改变编译专用输出策略或演示交付合同。
计划/TDD 等项目要求的技能不在本次提供的目录，按同样的验证流程执行。

## 实施与验证

- 未声明容量时共享默认值已从 32K 改为 1M，声明的小容量和超过 1M 的配置均保留。
  正文估计 3000、三项取证要求、推理未关闭的示例，初始请求从 4536 提高为
  13752 tokens（正文 3000 + 结构 2560 + 推理余量 8192）。
- 已实现阶段独立扩容及格式修复计数、实际容量/完整输入约束、截断正文保存、
  父子 Run 与预算事件追溯；旧的 32K 边界用例调整到新默认容量附近，仍验证
  容量保护，以及 ACP 报告压缩后允许继续的行为。
- `cargo fmt -- --check`、`cargo clippy -- -D warnings`、`cargo build` 通过；
  `cargo test -- --quiet`：444 通过，3 个原有测试忽略，无失败。
- 前端 `npm test`：266 通过；`npm run build` 类型检查和构建通过，仍有既有
  Rollup PURE 注释、静态/动态导入和大 chunk 提示。
- Fake Runtime 验证每个规划/章节/综合阶段连续截断两次仍能独立完成，不消耗
  任务全局重试；格式修复不占扩容机会，取消和无限截断有界停止，部分结果保留。
  未修改真实用户数据，未调用真实模型；上线后仍需以实际供应商进行验收。
